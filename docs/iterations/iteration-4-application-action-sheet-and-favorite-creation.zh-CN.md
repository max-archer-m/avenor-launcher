# 迭代 4：应用操作面板与创建收藏

> 英文语义源：[iteration-4-application-action-sheet-and-favorite-creation.md](iteration-4-application-action-sheet-and-favorite-creation.md)。

> 本迭代适用于 [Avenor Launcher 1.0.0 交付契约](../versions/1.0.0/delivery-contract.zh-CN.md)，定义一个产品增量及其必需证据。本文不授权实现、不批准候选架构，也不声明迭代完成。项目作者必须明确授权实现。

## 目标

使作者能够长按应用、使用纳入的模态应用操作，并将一个 Drawer 条目作为一个持久且不重复的收藏添加到 Home。

## 可观察结果

作者能够长按 Drawer 条目、打开模态应用操作面板、打开系统应用信息、将条目添加为收藏，并在普通进程重建后于 Home 观察到该收藏，且不会创建重复项。

## 纳入工作

- 从 Drawer 长按打开应用操作面板，且不与列表、过渡或索引手势冲突。
- 实现纳入的模态呈现、scrim、拖动把手、输入阻断、Back/scrim/拖动关闭、身份呈现和平台提供的 badge 处理。
- 防御性地打开系统应用信息，并按规定在返回或失败后保留来源 Drawer 位置。
- 为非收藏 Drawer 条目呈现适用的添加收藏操作。
- 建立有序收藏身份持久化、schema 版本、原子变更、备份排除和进程恢复。
- 将新收藏的身份追加到 Home，并防止重复添加同一可启动身份。
- 添加到 Home 后仍将应用保留在 Drawer 中。
- 区分成功的空持久化读取与失败读取，并保留技术评估要求的禁止破坏性写入不变量。
- 本地化纳入的操作标签和失败反馈。

## 排除工作

- 分配给迭代 5 的移除收藏操作和完整收藏生命周期。
- 收藏排序、排序模式、平台应用快捷操作、卸载、禁用、移除分身、Settings 或面向用户的第三方许可证界面。
- 排除在 `1.0.0` 外的完整收藏损坏恢复 UI。
- 完整版本兼容性、实测质量、签名、正式 APK、归档、tag 或分发操作。

## 技术影响面

- 模态面板状态、所选条目身份、pointer/输入阻断、关闭和平台信息操作。
- 收藏领域模型、有序身份 schema、持久化边界、原子添加/去重、读取状态和进程恢复。
- 从持久化身份渲染 Home 收藏，以及 Drawer/Home 共享清单状态。
- 所选持久化实现的备份/数据提取排除和依赖/许可证评估。

Proto DataStore 是候选方向，不是预先批准的结果。本迭代选择能够保留有序类型化身份、明确迁移、读取失败区分、禁止破坏性覆盖和可接受许可证义务的最小已证明持久化方案。需要时通过架构文档或 ADR 记录重大持久化选择。

## 依赖和序列

- 项目作者接受迭代 3 的所选条目身份、Drawer 位置和长按输入基础足以继续扩展；准入不要求其正式关闭或完成每个建议验证场景。
- 合格的依赖/许可证审查足以确定所选持久化技术栈能否保持在 `1.0.0` 范围内。
- 项目作者明确授权本迭代；若必需 notice 界面与已批准排除项冲突，还需授权任何产品变更。
- 当可观察的收藏创建和持久化基础可接受、适合增加移除与调和且已知缺口得到记录时，项目作者可以授权迭代 5。

## 迁移和兼容性影响

- 本迭代创建首个持久化收藏 schema；不存在 1.0 前生产迁移。
- Schema 只包含已批准产品路径所需的稳定可启动身份、顺序和 schema 版本。
- 它必须支持未来迁移，且不进行破坏性替换。
- 云备份和设备间迁移继续排除。

## 安全、隐私、权限和许可证影响

- 收藏是存储在凭据加密的应用私有存储中的本地用户内容数据。
- Release 构建不完整记录收藏身份，收藏身份也不用于分析或使用历史。
- 不引入网络、账号、云、广泛软件包可见性或隐藏资料能力。
- 外部应用信息操作能够处理不存在和 `SecurityException`，且不暴露原始异常文本。
- 关闭前需要对解析后的持久化依赖图和 notice 义务进行文档化审查。

## 风险和未解决决定

- 候选身份对于设备特定分身可能无法保持持久稳定。
- 若不改用替代 serializer 或 DataStore 形式，持久化集成可能无法保留失败不变量。
- 合格许可证审查可能要求目前排除在 `1.0.0` 外的面向产品 notice 界面。
- 面板手势可能与底层过渡或列表输入冲突。
- 显示新添加收藏需要与当前清单正确调和，且不得把标签、图标或可用性持久化为收藏事实。

## 验证计划

建议执行以下场景，以降低交付风险并完善证据。除非项目作者明确将某一场景提升为门禁，否则结果不完整或无法取得不阻塞本迭代的准入、准出或推进。缺失结果仍属于未知，必须记录且不得视为通过。

- 对 schema 编码、身份相等性、追加顺序、重复防止、原子变更、读取失败和进程恢复进行单元测试。
- UI 测试覆盖长按、模态阻断、关闭、应用信息、添加收藏、本地化失败和 Home 呈现。
- 在切实可行时对持久化重建和备份/数据提取配置进行 instrumented 测试。
- 在两台真机上验证主条目和暴露的分身/资料条目的添加到 Home 行为。
- 验证进程重建只保留一次准确收藏，并且失败读取期间不执行写入。
- 检查解析后的依赖图、许可证证据和 merged manifest。

## 验收证据

执行后记录以下建议证据。缺失建议证据本身不阻塞作者验收或推进：

- 操作面板交互和平台信息结果；
- 准确添加、去重、追加顺序、Home 呈现和进程重建结果；
- 适用主条目和分身/资料条目的身份结果；
- 持久化 schema、失败不变量、备份排除、依赖和许可证证据；
- 成功的自动化与手动命令；
- 每个产品或技术不匹配及其处置。

不能仅因本契约存在就视为验收证据存在。

# 迭代 6：兼容性、质量与正式 APK 收尾

> 英文语义源：[iteration-6-compatibility-quality-and-formal-apk-closure.md](iteration-6-compatibility-quality-and-formal-apk-closure.md)。
>
> 本迭代适用于 [Avenor Launcher 1.0.0 交付契约](../versions/1.0.0/delivery-contract.zh-CN.md)，定义版本收尾产品和证据结果。本文不授权签名、产物移动、tag、发布或公开分发。每项变更都需要项目作者适用的明确授权。

## 目标

证明完整 `1.0.0` 产品路径兼容、可靠、可测量且可追踪，并由一个具有正式标识和签名的 APK 表示，且不增加未完成产品范围。

## 可观察结果

同一个使用 release 签名的 `1.0.0` APK，在 API 31 模拟器、Samsung API 36 设备和 Pixel API 37 设备上完成所选离线 Home、Drawer、应用启动、操作面板和收藏路径。其源码、标识、签名证书、摘要、验证、限制和外部位置均可追踪。

## 纳入工作

- 解决使已验收迭代 1 至 5 行为通过完整环境矩阵所必需的缺陷。
- 在每个必需环境中执行完整的确定性自动化与手动验证计划。
- 在真机上重复测量冷启动、完整显示时间、关键交互帧行为、内存、空闲功耗和稳定性。
- 保留测量步骤、迭代次数、构建模式、设备状态、JSON、trace 和观察分布。
- 获得项目作者对基于证据的绝对退出阈值的批准。
- 完成适用于实际实现的 release 依赖、许可证、merged-manifest、权限、备份、安全和隐私审查。
- 根据证据决定 baseline profile 是否实质改善关键路径。
- 通过适用决定权记录和处置 OEM 限制与契约不匹配。
- 在单独授权下，建立 release 签名保管和备份，构建并验证正式 APK，计算并复验 SHA-256，将其放入获批外部位置。
- 只有全部完成证据存在后，才准备事实性版本归档记录并更新链接。

## 排除工作

- 新产品能力、延期的 `1.0.0` 行为、Settings、排序、快捷操作、卸载、更广设备适配、网络能力、后续能力层或商业功能。
- 静默放宽纳入的验收要求。
- 未经单独明确授权创建 tag、声明里程碑、创建 GitHub Release、远程上传、执行应用商店操作或公开分发。
- 在产品仓库中存储 APK 或签名秘密。

## 技术影响面

- 完整已验收路径的跨环境缺陷修复和回归覆盖。
- Release 构建、lint、测试、benchmark、trace、Manifest/依赖证据和可复现命令。
- 签名集成、证书验证、APK 身份/摘要、源码可追踪性和外部产物记录。
- 版本归档准备和链接迁移。

本迭代不引入推测性架构。暴露重大架构选择的缺陷修复遵循 ADR 流程；产品行为变更返回产品经理和项目作者处理。

## 依赖和序列

- 项目作者接受迭代 1 至 5 的可观察基础足以开始兼容性与质量收口。进入本迭代不要求这些迭代正式关闭或完成全部建议场景。
- 权威构建、测试、lint、安装和聚焦验证命令作为正式版本关闭证据建立；缺少这些命令不阻塞进入本迭代。
- 签名身份创建、签名、外部产物移动和归档变更分别就绪时，项目作者分别作出授权。
- 只有满足版本契约中的每个门禁后，才完成版本。

## 迁移和兼容性影响

- 在已批准的竖屏手机边界内验证 Android 12/API 31 至 Android 17/API 37。
- 验证最终产物中的准确 `versionName` `1.0.0` 和 `versionCode` `1`。
- 验证进程/设备恢复，以及迭代 5 产出的最终持久化 schema。
- 不纳入降级、公开分发、应用商店迁移或 1.0 前生产数据迁移。

## 安全、隐私、权限和许可证影响

- 检查最终 merged release manifest 中的每项权限、导出组件、query、备份规则和依赖贡献。
- 确认不存在未经批准的网络、广泛可见性、隐藏资料、分析、数据收集、云备份和设备迁移行为。
- 记录解析后的运行时依赖图和合格许可证结论。
- 项目记录只存储 release 证书 SHA-256 指纹；绝不存储 keystore、密钥、密码、签名属性文件或其他秘密。
- 正式完成前，要求作者控制的安全存储，以及至少两个相互独立的加密签名备份。

## 风险和未解决决定

- 绝对性能、内存、功耗和稳定性阈值在可重复测量存在前仍未决定。
- OEM 限制可能需要作者接受或产品契约决定。
- 合格许可证审查可能暴露与排除面向用户 notice 界面的冲突。
- 准确的外部 APK 目录、保留、同步、备份和 Git 跟踪策略由作者保留决定。
- 在实际环境建立前，不存在签名参数和可执行命令。
- 已验收核心行为失败不属于可静默豁免的质量债。

## 验证计划

迭代 6 可以在以下工作完成前开始。版本契约要求时，这些验证是正式完成 `1.0.0` 的必要条件，而不是进入迭代 6 的门禁。

- 运行所有文档化构建、单元、UI、instrumented、lint、Manifest、依赖、安装和聚焦验证命令。
- 在每个必需环境中完成完整离线用户路径。
- 验证 Home 资格、直接启动、时间/日期、Drawer、分组/索引、过渡、实时更新、准确条目启动、操作面板、收藏创建/生命周期、进程重建和设备重启。
- 记录崩溃、ANR、意外激活、重复、数据丢失、覆盖和不可用行为。
- 运行可重复真机 benchmark 并保留生成证据。
- 构建最终获授权 release 变体，验证标识与签名，计算 SHA-256，仅在授权下复制并复验外部文件。
- 比较文档、实现、测试和验证证据；明确解决每个实质契约不匹配。

## 验收证据

关闭前记录：

- 准确的成功构建、测试、lint、安装、benchmark、签名、摘要和验证命令；
- 完整环境标识、步骤、结果、构建身份、源码 commit 和 APK 摘要；
- 测量分布和作者批准阈值；
- 依赖、许可证、Manifest、权限、备份、安全和隐私结论；
- 已签名 APK 文件名、`versionName`、`versionCode`、源码 commit、SHA-256、签名证书指纹、构建时间/环境和外部逻辑位置；
- 每个已知限制、未解决缺陷、技术债、迁移问题、替代方式和作者处置；
- 已验收迭代 1 至 5 及其证据的链接。

不能仅因本契约存在就视为验收证据存在。

## 相关决定、commit 和 tag

- 架构、ADR、产品决定和发布治理链接：记录每个适用决定。
- 实现和关闭 commit：记录 APK 所表示的准确源码历史。
- Tag：`1.0.0` 不要求 tag；只有在项目作者单独明确授权后才创建。
- GitHub Release 和公开分发：本迭代不要求也不授权。

## 最终结果

只有项目作者接受完整事实证据集，并且同一个已签名 APK 在标识、源码 commit、签名、摘要、必需环境、外部存储、限制和归档记录之间均可追踪时，本迭代和正式版本才关闭。在此之前不声明完成。

## 剩余问题和交接

完成后，将版本契约、支撑版本输入和原始纳入迭代记录移入 `docs/archives/v1.0.0/`，更新链接，将下一个项目级迭代编号保留为 `7`，并记录所有剩余问题以供后续获授权交付处理。Tag、里程碑、GitHub Release 或公开分发仍是独立决定。

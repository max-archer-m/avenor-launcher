# 迭代 2：Drawer 应用发现与启动

> 英文语义源：[iteration-2-drawer-application-discovery-and-launch.md](iteration-2-drawer-application-discovery-and-launch.md)。
>
> 本迭代适用于 [Avenor Launcher 1.0.0 交付契约](../versions/1.0.0/delivery-contract.zh-CN.md)，定义一个产品增量及其必需证据。本文不授权实现、不批准候选架构，也不声明迭代完成。项目作者必须明确授权实现。

## 目标

扩展已验收的 Home 增量，使作者能够进入 Drawer，查看在 Avenor 最小权限边界内成功读取的可启动条目，在非当前资料读取失败时继续使用已有条目，在没有可用清单时进行恢复，并启动预期条目。

## 可观察结果

从已验收的 Home 构建开始，作者能够使用已批准的向上交互进入 Drawer，看到平台暴露可启动条目的单一列表，通过 Retry 从加载失败中恢复，选择一个条目并启动该准确应用。Back 返回 Home。

## 纳入工作

- 建立项目所有的可启动清单边界，以及 UI 状态使用的不可变快照。
- 使用 Android 的 Launcher 感知平台边界获取清单并准确启动条目。
- 将平台暴露的每个可启动 Activity 视为独立条目，避免仅按软件包名去重。
- 在可用时呈现平台标签、图标和 badge，并提供安全的通用图标回退。图标呈现通过 [ADR-0001](../decisions/0001-establish-replaceable-launcher-icon-rendering.md) 定义的可替换边界：保留原生自适应行为，在设备 mask 内规范化旧式图标且不裁掉其可识别内容，并在规范化后添加资料或分身 badge。
- 呈现稳定且足以支持核心发现的单列应用列表，采用产品规定的平台转写与 locale-aware 混合排序，作为迭代 3 完整行为的基础。
- 实现相互区分的 Loading、Content 和 Error 状态。将完整读取为空或没有留下任何可用清单的失败视为 Error，并提供本地化手动 Retry。非当前资料的局部失败可以省略该资料，同时保留已有 Content，且不要求提供提示。
- 实现基础二元状态切换：向上拖动达到与契约一致的 `120dp` 释放门槛后进入 Drawer，并通过 Back 返回，且不会意外激活应用。该临时入口路径不实现也不满足分配给迭代 3 的完整直接操纵过渡。
- 防御性地启动所选条目，并抑制快速重复激活。
- 在已记录真机上验证主条目、分身和正常暴露的资料候选。
- 将 Private Space 和隐藏资料访问保持在清单边界之外。

## 排除工作

- 分配给迭代 3 的连续拖动进度、包含甩动目标判定的完整释放决定、回弹、列表边界移交、指针仲裁、最终字母索引交互、完整章节锚点行为及实时更新位置保留。
- 应用操作面板、应用信息、收藏、持久化、调和和 Home 收藏呈现。
- Settings、排序、快捷操作、卸载、移除分身或其他任何排除在 `1.0.0` 外的操作。
- 完整版本性能、签名、正式 APK、归档、tag 或分发操作。

## 技术影响面

- 项目所有的清单模型、身份候选、仓库边界、回调、不可变 UI 状态和规范化完整名称比较基础。
- `LauncherApps` 或另一种有证据支持的 Launcher 感知平台适配器。
- ADR-0001 已接受的可替换图标渲染边界和当前 `SystemAdaptive` 策略。渲染图标是派生呈现，不是可启动身份或持久化事实；算法常量和图像分析启发式保留在代码与测试中。
- 核心 Drawer 列表渲染、Loading/Content/Error 状态归约、手动 Retry、准确条目启动和重复激活抑制。
- 可观察路径所需、可继续扩展的 Home/Drawer 路由状态和 Back 行为；这不代表完整产品手势契约已经验收。

设备证据必须确定候选资料加 `ComponentName` 身份是否可行。本迭代不通过陈述批准身份或架构；已证明的重大选择单独记录。

## 迁移和兼容性影响

- 本迭代不引入生产持久化 schema。
- 清单和身份模型必须保留迁移至后续收藏持久化的路径。
- API 31 至 API 37 继续作为产品范围；模拟器证据不能替代 Samsung 或 Pixel 的分身/资料行为证据。

## 安全、隐私、权限和许可证影响

- 不声明 `QUERY_ALL_PACKAGES`、`ACCESS_HIDDEN_PROFILES`、`INTERNET`、使用情况访问、通知访问、联系人、位置、文件、照片或无障碍服务能力。
- 软件包可见性和任何 Manifest query 都必须为所选路径所必需并可追踪。
- 外部启动操作能够容忍不存在、撤销、禁用状态和 `SecurityException`，且不暴露原始异常文本。
- 清单元数据保持本地，不在 release 构建中完整记录。
- 解析清单依赖后重新检查 merged manifest 和依赖图。

## 风险和未解决决定

- Samsung 和 Pixel 可能以不同方式暴露分身/资料条目、badge 和启动行为。
- 平台转写和 locale 排序结果可能因支持的 API 级别或 locale 数据修订而不同；实现必须遵循当前产品契约并记录观察到的兼容性差异，不得为此引入独立读音字典。
- ADR-0001 记录了当前设备 mask、规范化旧式图标可识别性和 badge 呈现的 Samsung 已接受证据，Pixel 行为则仍是建议补充的未验证证据。本迭代的 Home 尚无图标消费者；交付首个 Home 图标消费者时，建议把跨界面一致性纳入验证。不要求与 OEM 专有视觉效果完全一致。
- 当前源码在非当前资料发生 `IllegalStateException` 或 `SecurityException` 时，会省略该资料的 Activity，同时保留已有 Content。这符合当前非阻断产品方向。设备证据仍需记录哪些条目可能缺失，并确认局部失败不会导致 Avenor 崩溃、阻断已有条目启动或触发破坏性的收藏调和。
- 当前源码采用 `120dp` 释放门槛，随后直接执行二元界面切换。与最终距离一致不构成对分配给迭代 3 的连续位置、不透明度、fling、回弹、取消或手势移交契约的验收。
- Android 回调可能无法区分暂时不可用和永久消失。
- 适合后续持久化的稳定身份，在真机证据存在前尚未得到证明。
- 完整手势控制器要到迭代 3 才完成；核心过渡不得建立不兼容的状态模型。
- 无法读取任何可用清单时仍进入 Error，并且不构成增加广泛可见性权限的理由。

## 验证计划

建议执行以下场景，以降低交付风险并完善证据。除非项目作者明确将某一场景提升为门禁，否则结果不完整或无法取得不阻塞本迭代的准入、准出或推进。缺失结果仍属于未知，必须记录且不得视为通过。

- 对身份比较、重复防止、规范化完整名称比较、汉字与拉丁名称混合排序、大小写和拉丁字符重音处理、稳定排序、状态归约、空结果分类、Retry 过渡和激活节流进行单元测试。
- 在切实可行时对平台适配器的清单和准确条目启动进行 instrumented 测试。
- 强制产生完整空结果、当前资料读取失败、非当前资料读取失败、Retry 再次失败和 Retry 成功。验证 Loading、Error 和 Content 保持可区分，非当前资料失败时保留可用 Content 且不崩溃或进入全界面 Error，没有任何可用清单的失败则进入 Error。
- 通过 UI 测试验证加载、失败、手动 Retry、Back、临时 `120dp` 入口门槛和核心二元过渡行为，但不据此声明完整导航过渡已验收。
- 在 Drawer 中验证自适应、旧式、回退、主条目、分身和工作资料图标情况。确认设备 mask 跟随平台、旧式图标内容在安全区域内保持可识别、badge 在规范化后添加，并且后续 Home 图标消费者能够复用该渲染器而不改变身份或持久化。
- 在 API 31 模拟器和两台真机上验证列表内容与启动行为。
- 分别记录 Samsung 和 Pixel 的主条目、分身/资料、badge 和启动观察结果。
- 检查软件包可见性、merged manifest、依赖图，以及不存在未经批准的声明。
- 记录实际命令、构建身份、源码 commit、环境、步骤和结果。

## 验收证据

当前有限证据：

- 已接受的 ADR-0001 记录了当前设备 mask 形状、规范化旧式图标可识别性和资料/分身 badge 呈现的 Samsung 真机验收，以及该边界的 debug Kotlin 与 Android-test Kotlin 编译成功结果。
- 当前仓库源码包含 Loading/Content/Error 归约、本地化错误呈现、手动 Retry、准确条目启动、基于平台转写的比较、图标规范化、临时 `120dp` 入口门槛，以及包含汉字与拉丁名称混合排序场景的回归测试源码。这些内容的存在属于源码证据，不证明每项测试或必需环境已经通过。

执行后记录以下建议证据。缺失建议证据本身不阻塞作者验收或推进：

- 准确的成功自动化和手动验证命令；
- 每个必需环境的清单和准确条目启动结果；
- 适用 locale 和支持 API 级别下的规范化混合排序结果，包括观察到的平台转写差异；
- Samsung 和 Pixel 的分身/资料身份观察结果；
- 链接 ADR-0001 的自适应、旧式、回退、资料/分身 badge、Samsung 和 Pixel Drawer 结果，以及 Home 具有图标消费者后执行 Home/Drawer 一致性验证的明确交接；
- merged-manifest 和最小权限证据；
- 每次已观察清单加载失败的准确环境和失败类别、它影响当前资料还是其他资料，以及形成的 Loading/Error/Content 状态；
- 空结果、非阻断部分资料失败、手动 Retry、Retry 再次失败和 Retry 成功结果；
- 转交作者决定的每个未解决 OEM 限制或契约不匹配。

不能仅因本契约存在就视为验收证据存在。

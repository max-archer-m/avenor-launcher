# 迭代 10：双击锁屏授权闭环

> 适用于 [Avenor Launcher 1.1.0](delivery.zh-CN.md)。本记录规划一个产品增量，不授权实现、凭据、发布或 Git/远程操作。

## 状态

- 值：`Completed`
- 更新日期：2026-08-16
- 依据：物理设备验证确认 debug-only 实现路径满足产品边界。[ADR-0004](../../decisions/0004-purpose-limited-accessibility-service-for-double-tap-lock.md) 记录了主线集成所需的无障碍服务约束。

## 目标

让作者可以主动选择启用 Avenor 用途受限的无障碍服务，并通过双击 Home 符合条件的空白位置请求一次 Android 系统锁屏操作，同时不阻断或观察任何独立 Launcher 路径。

## 可观察结果

Settings 展示 Android 的真实服务状态并说明该能力。作者阅读已确认的本地隐私信息和显著披露，明确继续进入系统无障碍设置并在系统中启用服务后，完全发生在 Home 基础信息区合格空白位置内的有效双击请求一次锁屏操作。授权撤销或操作失败只影响本能力。

## 纳入工作

- 名为 `双击锁屏` 的 Settings 条目，展示真实的 `已开启` 或 `已关闭` 状态并在返回时刷新。
- 本地说明界面、系统设置跳转，以及具有 `取消` 和 `同意并继续` 操作的独立显著披露。
- 经确认的本地 Privacy 呈现，说明当前产品数据边界，以及无障碍服务唯一的锁屏用途、数据访问行为、授权方式和关闭路径。
- 用途受限的无障碍服务：除用户明确触发的锁屏请求外不执行其他全局操作，也不请求读取窗口内容。
- 仅在基础信息区符合条件的空白位置识别双击，使用平台时间和移动容差，并遵守契约规定的手势归属和排除目标。
- 对服务未启用、被撤销、断连、不可用或操作失败采用关闭能力式失败，并提供契约规定的本地化反馈。
- 纳入 UI 和披露内容的英文、简体中文及英文回退资源。

## 排除工作

- 设备管理员回退、后台触发锁屏、读取屏幕内容、其他全局操作、行为观察、分析或自动化。
- Avenor 自有权限开关、首次启动权限请求、自动跳转设置或保留披露确认历史。
- 商店发布、商店政策已获批准的声明，或没有适用审核支持的法律或专业结论。
- 当前双击锁屏契约之外的任何无障碍服务用途。

## 技术影响面

无障碍服务声明与配置、服务状态观察、锁屏操作适配器、Settings 导航与披露状态、Privacy 内容呈现、Home 命中测试与手势仲裁、资源和聚焦测试。准确代码组织属于技术选择；任何更广权限、数据、后台或服务边界都需要作者决定和适用的专业复核。

## 依赖和顺序

依赖已完成的迭代 9 Settings 导航与状态刷新基础。作者批准的本地 Privacy 和显著披露正文现已由所链接的产品契约定义。聚焦技术验证可以先于 ADR，并且必须证明最小 AccessibilityService 声明、准确状态检测、锁屏操作、安全失败行为、受支持 API 行为、数据边界，以及实现与该正文一致。

上述边界得到证据支持后、服务集成到 `1.1.0` 主线前，必须建立 ADR，记录服务唯一用途、权限与 manifest 边界、明确禁止的行为、安全失败规则、与 Privacy 和显著披露的关系，以及未来扩展或商店分发必须重新审核的要求。证据存在前不得建立空 ADR。如果验证要求扩大权限、数据处理、后台行为或产品范围，应停止并请求作者决定，不得集成该结论。

## 迁移和兼容性影响

不计划收藏数据迁移。服务在用户通过 Android 设置启用前保持关闭。安装或升级不得自动启用；授权缺失或撤销时，Home、Drawer、应用启动和 Settings 必须保持完整可用。

## 安全、隐私、权限和许可证影响

本迭代引入无障碍服务能力，因此需要明确的最小权限、隐私、安全、披露和未来分发政策审核。服务不得读取窗口内容、为产品行为观察其他应用、为分析收集无障碍事件或使用设备管理员。本迭代不授权监控 SDK 或网络服务。

## 风险和未决决定

- OEM 无障碍设置、服务连接和锁屏操作行为需要在支持基线上取得设备证据。
- 手势识别不得延迟时钟或日历选择，也不得与 Home-to-Drawer 拖动、长按、编辑表面、系统 inset、收藏或其他目标冲突。
- 实现必须准确复现当前经作者批准的 Privacy 与显著披露正文，不得削弱、合并或绕过两者独立展示的边界。
- 即使 GitHub 分发构建已经验收，未来商店分发仍需要重新审核平台政策和披露。
- ADR-0004 现已记录任何主线集成前所需、由证据支持的 AccessibilityService 边界。本次完成结果仍为 debug-only，不声称已经完成主线集成。

## 验证计划

作为版本路径的一部分，本迭代行为必须在作者指定的主要物理设备上得到验收。额外建议场景包括服务从未启用、已启用、被撤销、断连和操作失败；披露的 `取消` 与 `同意并继续` 路径；系统设置处理器失败；返回后的状态刷新；有效和无效双击；时间、日期、收藏、编辑表面、inset、拖动、长按和取消排除；进程重建；离线使用；英文、简体中文和回退资源；API 31；另一台 API 36 或 API 37 物理设备；以及额外 OEM/profile 覆盖。未执行的建议证据保持 `Unknown`、`Not run` 或 `Unavailable`，其本身不阻塞版本。已经执行的纳入路径失败不得因场景属于建议而被忽略。

## 验收证据

项目作者已在指定主要物理设备上验收 debug 实现。完成结果记录了获验收路径和设备环境；聚焦技术验证记录了 ADR 前证据及剩余建议场景。获批准披露版本、manifest/服务边界、源码/构建身份、初始及最终服务状态、手势位置和结果、系统跳转、失败行为、回归和跳过场景仍是适用的证据字段。

## 最终结果

本迭代已完成，物理设备证据支持产品边界。debug 实现成功演示了 Home 双击锁屏、Settings 状态和披露流程、服务状态检测和安全失败行为。ADR-0004 现已建立主线集成所需的架构约束。

## 剩余问题和交接

无障碍服务仍为 debug-only，尚未集成到主线。主线集成需要明确的作者决定、将服务从 `src/debug` 移至主 manifest 且边界约束不变的构建配置变更，以及版本交付协调。即使主线集成后，商店分发仍需重新审核平台政策和披露。

# Avenor Launcher 1.1.0 技术评估

> 语义源：[technical-assessment.md](technical-assessment.md)。
>
> 本评估分析已规划的 [1.1.0 交付](delivery.zh-CN.md)之可行性与交付约束。它不更改产品范围、不授权实施或发布活动，也不建立持久架构决策。项目作者保留决策权。

## 评估结论

选定的 `1.1.0` 范围在当前 API 31 基线上技术可行，并且不需要更改应用身份、提高 `minSdk`、替换现有持久化格式或增加第三方运行时依赖。迭代 7–9 与 11 是对已验收实现的增量扩展。迭代 10 可行，但它是本版本最主要的架构、隐私、平台政策与设备验证风险。

目前没有理由进行大范围重构或模块拆分。实现应围绕现有组合根增加范围收窄的平台适配器和页面级状态持有者，同时保留已建立的精确启动项身份和项目自有 `AtomicFile` 边界。

## 输入与当前基线

本评估使用当前产品页面、导航、Privacy 与数据处理契约和设计基础；开发、验证与发布指南；迭代 7–11；以及 ADR-0002 和 ADR-0003。当前检入实现具有：

- `versionCode` 1 和 `versionName` `1.0.0`；
- `minSdk` 31 的单 Compose 应用模块；
- 通过项目自有原子文件保存的有序 schema-1 收藏；
- 可感知资料范围的启动项身份与清单协调；以及
- 迭代 11 将移除的 Home 与 Drawer 共用应用名称跑马灯行为。

本评估与产品措辞不同时，产品契约仍为权威。Android 文档确定 API 契约而不能证明 OEM 行为；所有设置目的地、快捷方式暴露、无障碍状态和锁屏行为仍需在指定实体设备上取得证据。

## 跨迭代技术边界

`1.1.0` 保持单模块。仅提取选定工作需要的内聚边界：收藏重排操作、快捷方式发现与调用、设置状态和无障碍锁屏执行。顶层应用 composable 可以继续协调导航，但新的平台调用和持久写入不应直接嵌入 UI composable。

目前不需要新增依赖。Compose 指针输入、Android 框架 API、已在使用的协程和现有持久层足以覆盖规划行为。重排或导航框架会增加生命周期与手势风险，却不解决产品要求。

所有新增面向用户的字符串、语义颜色和可复用尺寸继续由资源或主题提供。平台失败必须受控且可本地化，不能让缺少处理器、资料被锁或服务不可用转化为应用崩溃。

## 迭代 7：主收藏重排

Schema 1 已按顺序保存收藏身份。在 `1.1.0` 子集中，处于该列表即隐式表示属于主收藏组，因此 Privacy 正文中保存分组与顺序的描述不要求新增字段或迁移。仅重排选定的全宽主收藏不得提前建模被排除的伴随收藏状态；后续实现伴随收藏组时需要另行评审 schema 演进。

为 `FavoriteStore` 增加一个串行化的完整顺序操作，例如 `replaceOrder`，并保持以下不变量：

- 新列表包含当前已接受列表中相同且唯一的身份；
- 写入仍处于存储 mutex 内并复用现有原子替换路径；
- 读取失败不得解释为空列表，也不得被重排覆盖；以及
- 仅为已完成的有效移动持久化，不按每个指针帧写入。

拖动会话、目标索引、层级、边缘自动滚动和取消状态属于瞬态 UI 状态。必须明确手势所有权：编辑模式拖动消费自己的指针流，普通 Home 导航不得从同一指针流开始，Back 按产品契约取消或退出。Compose 内置指针和滚动 API 足够；边缘自动滚动与触觉行为需要聚焦设备检查。

## 迭代 8：平台应用快捷方式

将 [`LauncherApps`](https://developer.android.com/reference/android/content/pm/LauncherApps) 用作范围收窄的平台适配器。发现快捷方式时必须先验证快捷方式宿主权限，查询所选启动项身份表示的精确 activity/package 与用户资料，并只在操作表生命周期内保留 package、快捷方式 ID、排名/顺序、标签、图标和用户。快捷方式数据不得成为项目自有持久数据。

调用必须通过 `startShortcut` 使用精确 package、快捷方式 ID 和用户。安全异常、资料被锁、快捷方式消失与目标不可用必须安全关闭或恢复，同时保留来源 Home 或 Drawer 状态。共用操作表应接收展示模型和回调，而不是框架快捷方式对象。

初始实现应保留平台查询暴露的稳定顺序，并保持在现有无溢出产品契约内。设备证据至少需要从两个来源页面分别调用一个动态或清单快捷方式，并在设备具备条件时覆盖无快捷方式、撤销/不可用和资料特定场景。

## 迭代 9：基础设置

设置应作为现有应用内导航状态中的不透明页面，License 展示作为本地子目的地或模态层。返回 Drawer 必须保留已建立的 Drawer 状态。

使用 [`RoleManager`](https://developer.android.com/reference/android/app/role/RoleManager) 判断 Avenor 是否持有 Home 角色，并使用系统 Home 设置目的地进行管理。前台恢复时重新查询；不得将系统角色状态作为应用持久数据缓存。OEM 目的地行为仍是实体设备结论。

在本地打包根 `LICENSE` 内容，并增加验证检查来防止展示副本漂移。通过隐式 HTTPS 查看 intent 打开 `https://github.com/max-archer-m/avenor-launcher`；无需 `INTERNET` 权限，且缺少处理器时必须本地处理。读取已安装包的版本名称与 long version code，使展示描述当前运行产物。迭代 9 验收前应应用规划的 `1.1.0` 标识，而最终版本代码仍遵循“下一个未使用值”的规则。

## 迭代 10：双击锁屏

实现一个专用且用途受限的 [`AccessibilityService`](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService.html)，以 `android.permission.BIND_ACCESSIBILITY_SERVICE` 声明并使用最小元数据。它不得请求窗口内容读取、手势执行、广泛事件观察或无关全局动作。其事件回调不应执行产品工作。启用状态应从系统已启用服务列表按精确组件得出并在恢复时刷新；“已启用”和“当前已连接”是不同状态。

应用到服务的边界只应暴露锁屏请求。存活服务实例必须确认锁屏全局动作可用，然后调用 `performGlobalAction(GLOBAL_ACTION_LOCK_SCREEN)`；返回 false 或不可用时不得崩溃。服务缺失、撤销、断连或 OEM 拒绝都必须安全失败。

双击识别仅附着于产品定义的基础信息空白区域。不得在时间、日期、收藏、编辑控件或导航区域上方放置父级检测器，否则会延迟或抢占其手势。编辑模式禁用锁屏手势，跨过阈值的导航拖动优先。使用平台配置的双击时间，不自定义时间常量。

确切的本地 Privacy 正文和显著披露现已在当前 [Privacy 产品契约](../../product/features/privacy.zh-CN.md)中获得作者批准。它们必须作为英文和简体中文资源随应用打包，对其他语言回退英文并保持离线；每种语言应只有一个受维护正文来源，避免 Settings Privacy sheet、说明流程与披露产生相互冲突的副本。查看 Privacy 和继续披露仍是不同状态；两者都不持久化为同意，并且只有“同意并继续”可以发起以启用为目的的系统跳转。

Privacy 联系方式复用与项目仓库入口相同的窄隐式 HTTPS 适配器，但使用独立固定 Issues URL、本地化失败提示和保持 sheet 的行为。这不增加 `INTERNET` 权限，也不得预先检查网络状态。

Android 的无障碍指南将这类服务定位为残障辅助，因此本地技术可行不等于符合公开商店分发资格。后续任何商店发布都需要重新进行平台政策以及适当的专项审查。迭代 10 可以先聚焦验证最小服务声明、准确启用状态检测、锁屏操作、安全失败行为和数据边界。上述边界得到证据支持后、服务集成到版本主线前，必须建立 ADR，记录服务唯一用途、权限与 manifest 边界、明确禁止的行为、安全失败规则、与 Privacy 和显著披露的关系，以及未来任何扩展或商店分发都要重新审核的要求。证据形成前不得建立空 ADR。如果证据要求扩大权限、数据处理、后台行为或产品范围，应停止并取得作者决定，不得创建或集成该扩大设计。

## 迭代 11：展示与升级闭环

将共用跑马灯实现替换为普通单行 `Text`，使用尾部省略且不软换行。应从 Home、Drawer 和应用根移除关联的选择、测量、动画和编排状态，而不是保留休眠的跑马灯路径。

升级验证必须从使用相同作者本地签名身份的已验收 `1.0.0` 安装开始，填充 schema-1 收藏，原位安装可追溯的 `1.1.0` 候选，并在执行重排前验证身份和顺序得到保留。闭环证据必须记录实际版本代码、源提交、设备和跳过检查；不得暴露签名材料。

版本收尾前，开发角色必须检查当前合并 manifest 与备份资源，包括 `android:allowBackup`、`android:dataExtractionRules`，以及适用于受支持 API 范围的任何旧版或等效配置。所得证据必须确认项目自有收藏持久化文件不会进入 Android 云备份或设备迁移备份。本文不把当前状态评估为已经通过，准确配置仍由开发角色依据实际工程决定。

## 验证策略

实现应为收藏排列校验与写入失败、快捷方式映射与调用参数、Home 角色状态映射、无障碍组件状态映射和锁屏命令失败路径增加聚焦自动化检查。Compose UI 检查最适合覆盖编辑模式手势所有权、操作表快捷方式存在性、设置导航、相互独立的 Privacy 与披露流程、取消路径、语言回退和静态省略语义。应通过聚焦内容检查比较随应用打包的 Privacy/披露资源和已批准产品正文，但不要求渲染后的排版或换行完全相同。

一台作者指定的主要物理设备仍是必需验收环境。记录其进程重建、升级保留、边缘自动滚动、触觉、从两个页面调用快捷方式、系统设置返回、服务启用/撤销/重连、允许与排除的双击区域以及锁屏执行失败证据。API 31、另一台 API 36 或 API 37 物理设备以及额外 OEM/profile 覆盖属于建议证据。未执行时记录为 `Unknown`、`Not run` 或 `Unavailable`；缺少这些证据本身不阻塞作者日常使用基线。如果已经执行，纳入路径失败必须解决或返回作者处置，不得因该检查属于建议而忽略。

本评估不声称已取得任何构建或设备结果。

## 风险、门槛与决策

| 项目 | 评估 | 必需处理 |
| --- | --- | --- |
| 收藏重排损坏 | 保留 schema 1 和原子完整列表替换时为低 | 校验排列并保留读取失败门槛 |
| 快捷方式资料错配 | 中 | 在查询与调用全程携带精确 activity/package/user 身份 |
| 设置 OEM 跳转 | 中 | 恢复时重新查询并取得主设备证据 |
| 无障碍能力与政策 | 高 | 最小服务、安全失败适配器、已批准披露、设备证据、后续分发审查 |
| 手势冲突 | 中 | 将检测器限定于合资格空白区并测试编辑/导航优先级 |
| 升级与签名连续性 | 中 | 使用相同私有作者本地签名身份并取得原位升级证据 |
| Android 备份排除 | 检查前未知 | 检查 manifest 和适用备份规则；证明收藏持久化不会进入云备份和设备迁移 |
| 根 composable 架构增长 | 中 | 增加窄状态持有者/适配器；不做大范围重写 |

### 剩余门槛与作者决策边界

作者已经批准产品文档引用的确切本地 Privacy 正文和显著披露文本。目前没有更多产品文案确认阻塞迭代 10。达到启用验收前，仍需完成最小服务声明、资源与展示精确一致性、受支持系统动作与状态检测、安全失败和数据边界行为，以及实体设备行为的技术确认。聚焦验证可以先于 ADR，主线集成不得先于 ADR；上述由证据支持的 ADR 是集成门禁，不是未决产品文案决定。

Android 备份排除仍是开发角色负责、尚未执行的迭代 11 与版本收尾门禁。目前没有其他未决事项阻塞迭代 7–9 或 11 的技术实施。提高 `minSdk`、更改身份或持久化格式、扩大无障碍能力、改变所声明的数据处理或改变所选产品验收边界，都需要作者另行指示，并在适用时重新评审 Privacy。

## 建议交付顺序

文档规定的数字顺序在技术上合理。迭代 7 在其他新增项前证明持久化变更；迭代 8 隔离启动器宿主平台行为；迭代 9 建立设置和系统状态刷新；迭代 10 复用该页面完成授权；迭代 11 移除过时展示机制并闭合升级证据。每个迭代应保持可独立审查，迭代 10 应保留其余技术与实现一致性门禁。

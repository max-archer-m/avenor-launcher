# 迭代 13：Home 信息与可编辑收藏组合

> 适用版本：[Avenor Launcher 1.2.0 交付](delivery.zh-CN.md)。
>
> 本稳定契约定义选定交付范围。迭代状态、实际证据、commit、产物和结果仅归同级版本交付记录所有。本文件不授权生产实现或任何 Git、发布操作。

## 目标

交付契约规定的 Home 基础信息对齐和完整、可直接访问的主收藏/伴随收藏组合，包括独立滚动、顺序持久化以及组内和跨组编辑。

## 可观察结果

日期文本使用契约规定的逻辑 start 内缩，同时保留完整触摸目标。Home 按契约组合显示视觉上可区分的主收藏和伴随收藏；两组都可以启动且独立滚动。主收藏使用 `40dp` 图标和 `56dp` 行高，伴收藏使用 `32dp` 图标和 `48dp` 行高，两组之间使用 `16dp` 间距。编辑模式保持这些条目高度，并支持持久化的组内交换、跨组插入和跨组交换，不丢失、不重复或覆盖收藏。

## 纳入工作

- 对可见日期与星期文本应用契约规定的 `8dp` 逻辑 start 内缩，且不缩小完整的 `48dp` 可聚焦触摸目标。
- 从共享组合宽度中扣除固定的两侧 `8dp` padding 和两组之间的 `16dp` 间距后，以约 55% 呈现主收藏、约 45% 呈现伴随收藏。
- 保持普通模式和编辑模式的条目高度一致。两组使用相同的 `24dp` 拖动柄图形；每个拖动柄热区宽度为 `48dp`，由 `24dp` 图形和左右各 `12dp` padding 组成，热区高度跟随当前条目高度。图形右侧不额外设置 margin，视觉间距来自条目已有的 padding。拖动柄必须包含在现有行内，不得拉伸或压缩任一列表。
- 应用每组契约规定的图标、目标、字体、间距、空余空间和独立滚动行为。
- 从 Drawer 新增的收藏默认进入主收藏，不打开 Home 或编辑模式。
- 通过所选收藏的 Launcher 操作进入编辑模式，并保留契约规定的编辑表面和仅 Back 退出方式。
- 支持带固定抓取偏移的独立全安全区域 `50%` 透明度跟手预览、稳定源位置、源行高度保留、目标反馈、无效放置恢复及目标组边缘自动滚动。预览可以经过全部 Home 安全内容，但只有主收藏和伴收藏区域接受放置。被拖动收藏不参与列表位置动画，任何目标变化或其他条目动画都不得使其自动平移、跳转或回弹。
- 将组内拖动定义为仅交换：已有收藏主体是唯一有效目标，该收藏移动到源位置，其原位置成为被拖动收藏的松手位置。同组间隙从不显示插入线，也不接受插入。触控点位于被拖动收藏、源位置或无效区域时，不产生新的交换。
- 将跨组拖动定义为两种互斥操作。已有收藏主体表示实时可见的跨组交换：触控点进入主体时，目标收藏立即与源收藏交换位置和分组归属，两组数量保持不变。目标间隙表示跨组插入：插入线标记目标边界，松手前不执行列表插入，松手时才移除源收藏，并保持目标组原有收藏的相对顺序。第一项之前、条目之间、最后一项之后和空组边界都是有效插入目标。
- 所有目标均以手指触控点判断，不以预览中心或边缘判断。从已有收藏主体移动到间隙时，在不修改已保存数据的前提下，将交换反馈切换为插入线；反向移动时切换回交换反馈。边缘自动滚动期间根据当前目标组几何位置重新计算反馈，不得产生无法解释的目标跳变。
- 收藏拖动期间不持久化当前操作。组内交换和跨组交换在触控点进入有效主体时实时更新可见目标位置；跨组插入只显示反馈。只有在对应有效目标上松手后，才完成当前交换或插入一次。稳定源位置不产生第二个可交互副本。占用目标可以使用同步确认动画，但独立预览不参与该动画。
- 每次完成组内交换、跨组插入或跨组交换后立即持久化。如果持久化失败，只为身份仍然有效的收藏恢复最近一次成功保存的分组归属和顺序，保留更新的已确认应用清单协调结果，不得复活已移除或失效的身份，不得将该操作表现为已完成，并展示现有的收藏更新失败反馈。
- 保留身份、顺序、禁用/不可用行为、应用清单协调和共享加载/错误/Retry 组合。
- 为所选行为新增或更新适度的测试与验证支持。

## 依赖与顺序

实现位于已接受的迭代 12 加载和返回语义之后。本迭代必须在迭代 14 最终确定覆盖两组收藏的 Home 手势仲裁前完成。日期对齐可以作为本迭代内的聚焦 commit 实现，但仍属于同一迭代验收结果。

## 迁移与兼容性影响

来自 `1.0.0` 和 `1.1.0` 的可读收藏必须保留可启动身份和既有顺序。没有伴随组归属的既有收藏按原顺序进入主收藏，除非实现证据要求其他经作者批准的迁移。迁移在适用时必须版本化且具备原子性。不可读或损坏状态不是空状态，不得迁移、修复、清除或覆盖。

不增加降级行为。已接受的 `1.2.0` 产物必须在发布治理和既有签名身份下支持原地升级。

## 安全、隐私、权限与许可证影响

未选择新增权限、网络访问、外部服务、依赖、用户数据类别或许可证影响。收藏组和顺序继续作为 Avenor 本地自有状态，受当前隐私和备份排除边界约束。

## 风险与未决决定

- 如果没有明确的指针所有权，跨组拖动、独立嵌套滚动和边缘自动滚动可能互相冲突。全安全区域跟手预览也必须与范围更窄的有效放置区域分离。
- 如果迁移不具备原子性且不了解 profile，持久化格式变更可能造成破坏性丢失或错误身份映射。
- 当前产品契约选择可观察的 55/45 组合，但不规定具体 Compose 布局架构。
- 重大的持久化或手势架构变化需要作者决定，并在适用时形成 ADR。

## 验收条件

- 在两种布局方向下，日期与星期可见文本都具有契约规定的 `8dp` 逻辑 start 内缩，完整行仍是 `48dp` 可聚焦触摸目标。
- Home 按契约的扣除间距后相对宽度、共享视口高度、独立滚动位置、保留空余空间以及普通/编辑模式一致的条目高度呈现主收藏与伴随收藏区域。
- 两组都可启动条目并暴露适用的长按操作。
- Drawer 新增项追加到主收藏，绝不静默分配到伴随收藏。
- 编辑模式支持源位置稳定的独立预览、实时可见的组内交换、实时可见的跨组交换、松手提交的跨组插入、互斥的触控点目标反馈、首部/中间/末尾/空组插入边界、无效放置恢复和溢出组边缘自动滚动。预览不改变条目或视口高度，松手时完成并保存当前操作。
- 活动拖动期间发生 Back 时，取消该拖动、恢复最近一次已保存的可见状态、移除全部拖动反馈，并阻止该手势后续的 release 触发保存。
- 每次完成的变更只保存一次，并在适用的重新打开、进程重建或重启场景中保留。
- 收藏保存失败时，只为身份仍然有效的收藏恢复最近一次已保存顺序，并保留时间上更新的已确认应用清单协调结果；失败恢复不得复活已确认移除或失效的应用、分身或可启动身份。
- 从可读既有收藏状态升级时保留身份和顺序且不丢失或重复；不可读状态保持原样且禁用变更。
- 应用清单变化以及禁用或暂时不可用收藏遵循当前 Home 契约。

## 验证要求

拖放聚焦验证包括：

1. 从拖动柄开始拖动，确认预览以初始抓取偏移连续跟手。
2. 确认源收藏保持稳定、保留行高、不产生第二个可交互副本，且不导致列表收缩或视口变化。
3. 在同一组内分别拖到第一项、中间项和最后一项，确认触控点进入主体时目标实时与源交换；经过间隙时不出现插入线或插入操作。
4. 在同一组内触碰被拖动收藏、源位置和无效 Home 区域，确认不产生新的交换。
5. 分别以目标组第一项、中间项和最后一项执行跨组交换，确认触控点进入主体时目标实时与源交换，且两组数量及源/目标位置符合交换示例。
6. 跨组插入到第一项之前、条目之间和最后一项之后，确认插入线及目标组原有顺序保持。
7. 插入空目标组，确认显示空组边界反馈。
8. 从交换主体移动到插入间隙再返回，确认主体上实时显示交换、间隙上仅显示插入反馈，反馈互斥，且持久化只在松手时发生。
9. 完整经过“源组交换 -> 组间区域 -> 目标组插入 -> 目标主体交换 -> 返回源组”的目标变化路径。
10. 触发顶部或底部边缘自动滚动，确认反馈始终对应触控点和当前目标几何位置，不发生无法解释的跳变。
11. 在无效区域松手，确认恢复原始分组和顺序，持久化数据不变。
12. 分别从拖动柄上部、中部和下部开始，确认预览偏移随起点改变，但触控点目标和松手结果保持一致。
13. 分别在活动交换和活动插入目标期间按 Back，确认预览与反馈消失、恢复最近一次已保存状态，且该手势后续 release 不能触发保存。
14. 在收藏持久化失败期间，使更新的应用清单结果确认某个收藏身份已移除或失效；确认回滚保留该清单结果且不会复活该身份。

其他聚焦场景覆盖零收藏、仅主收藏、仅伴随收藏、两组都有、普通/编辑模式等高、每组分别溢出、全安全区域跟手预览、Back 退出、进程重建、设备重启、可读升级、不可读持久化、安装/移除/禁用/重命名/clone/profile 变化、英文、中文、fallback locale、RTL 和相关字体缩放。

建议执行相关自动化检查、生成可安装 debug 构建，并由作者在指定主要设备上观察。实际结果归 `delivery.md` 所有；本契约不记录任何检查已运行。

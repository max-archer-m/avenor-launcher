# Avenor Launcher 1.0.0 交付契约

> 英文语义源：[delivery.md](delivery.md)。
>
> 本版本级契约依据项目的[版本、产物与发布治理](../../release.zh-CN.md)，整合已批准的 [1.0.0 产品范围](product-scope.zh-CN.md)和受证据限制的[技术评估](technical-assessment.zh-CN.md)。本文通过链接引用纳入的迭代契约，而不复制其交付细节。
>
> 本文档不授权实现、架构决定、签名、产物移动、Git tag、GitHub Release 或公开分发。每个迭代都需要自己的契约和项目作者明确授权。

## 版本结果

`1.0.0` 交付首个可安装、经验证、满足项目作者日常使用最低可用要求的 Avenor Launcher APK。

完整版本结果是完成[产品范围](product-scope.zh-CN.md)选择的离线路径：将 Avenor 用作 Android Home 应用，在 Home 与 Drawer 之间移动，找到并启动平台暴露的应用，将其添加为持久化收藏，从 Home 启动，并移除该收藏。

- Android `versionName`：`1.0.0`
- Android `versionCode`：`1`
- Android `applicationId`：`com.avenor.launcher`

仅有文档、中间迭代或本地构建都不会形成正式版本。只有全部纳入的产品增量和版本级证据要求完成后，正式版本才存在。

## 交付级别

`1.0.0` 采用[发布治理](../../release.zh-CN.md)定义的 `Author daily-use baseline` 级别，不属于 `Formal release artifact`。

因此，本版本以作者指定主要物理设备上的已接受日常使用证据，以及准确的源码/APK 可追踪性作为完成条件。API 31 与 Pixel 验证、完整自动化矩阵、性能分布与绝对阈值、正式发布签名与 keystore 备份、发布级专业许可证结论、发布级摘要证据、tag、发布和公开分发保留为建议或延期工作，不构成 `1.0.0` 完成门禁。

## 纳入和排除范围

[1.0.0 产品范围](product-scope.zh-CN.md)是纳入行为、排除项、产品验收意图和详细当前产品引用的权威来源。本契约选择该范围而不重新定义它。

产品范围中的排除项继续排除在 `1.0.0` 之外，包括延期的设置行为、收藏排序、平台应用快捷操作、卸载与分身移除操作、手动语言选择、完整收藏损坏恢复行为、更广设备适配、网络或账号能力、分析、后续能力层和公开分发。

如果实现或验证证据与纳入行为冲突，受影响工作在契约不匹配处停止。技术角色记录证据和影响；产品经理与项目作者决定任何产品范围或验收变更。迭代不得静默地把失败要求转化为实现限制。

## 技术可行性边界

[技术评估](technical-assessment.zh-CN.md)认为所选范围可行，但仍需要仓库和设备证据。其中的候选方向不会因为出现在评估或本契约中就成为获批架构。

已确认版本约束包括：

- `minSdk` 31 和 `targetSdk` 36，除非获授权的产品契约更新改变它们。
- 当前获批的 Android 应用身份是 `com.avenor.launcher`。后续只有经项目作者明确决定，并记录其对安装、升级、签名、数据连续性、分发和迁移的影响后，才允许修改。
- 实现获授权后，在产品仓库根目录创建 Android 项目。
- 核心行为保持本地和离线，不使用账号、服务器、云同步、分析或网络依赖。
- 已批准基线排除 `QUERY_ALL_PACKAGES`、`ACCESS_HIDDEN_PROFILES`、`INTERNET`、云备份和设备间迁移。
- 面向用户的字符串、颜色和可复用尺寸使用资源定义，并提供默认英文与简体中文资源。

稳定 API 37 `compileSdk`、准确 JDK/Gradle/AGP/Kotlin/Compose 组合、单 Activity Compose、项目自有 `LauncherApps` 边界、资料加组件身份、Proto DataStore、coroutines 和依赖注入等候选技术方向，由首个依赖它们的产品迭代及时验证。已证明的重大选择进入架构文档或 ADR；普通实现细节留在代码和测试中。

## 版本级依赖和决定

迭代开始变更工作前：

1. 项目作者接受前序实现基础足以继续，或明确改变依赖顺序；进入下一迭代不要求完成前序全部建议验证场景；
2. 迭代契约已经对照当前产品范围和实现证据审核；
3. 未解决产品不匹配已经转交产品经理和项目作者；
4. 重大技术决定已经判断是否需要 ADR；
5. 项目作者已经明确授权该迭代实现。

由于本项目当前由作者个人维护，迭代验证场景属于建议证据，而不是默认的迭代准入或完成门禁。当迭代满足状态规则并记录全部已知缺口时，即使建议验证尚不完整，也可以变为 `Completed`。缺失检查仍属于未知，不表示通过。该灵活性不放宽下文 `1.0.0` 作者日常使用基线门禁。

整个版本中由项目作者保留的决定包括：

- 批准此前瞻性交付边界和序列；
- 授权和验收每个迭代；
- 任何 `minSdk`、产品范围或验收意图变更；
- 有证据证明稳定 API 37 候选无法复现后的 API 36 `compileSdk` 回退；
- 接受 OEM 限制；
- 作者指定的主要物理设备和已接受日常使用结果；
- 另行开展时可选的 release keystore 创建、保管、备份与签名；
- 作者选择保留基线 APK 时的外部保留；
- 任何 tag、里程碑声明、GitHub Release、产物上传或公开分发。

批准此前瞻性交付计划不表示批准候选架构，也不表示依赖证据的门禁已经满足。

## 验证和退出门禁

### 必需环境

| 环境 | 必需用途 |
| --- | --- |
| 作者指定的主要物理设备；当前为 Android 16/API 36 的 Samsung Galaxy S23 Ultra | 安装，以及用于日常使用的完整所选离线 Home、Drawer、启动、操作面板和收藏路径 |

记录设备、OS/API、应用标识、源码 commit、可用的 APK 或构建身份、步骤、结果和已知限制。Android 12/API 31 模拟器与 Google Pixel 8/API 37 证据继续作为建议兼容性工作，不阻塞本交付级别。

### 确定性门禁

- 一个可安装 APK 使用 `applicationId` `com.avenor.launcher`、`versionName` `1.0.0` 和 `versionCode` `1`，并可追踪到记录的源码 commit。
- 完整所选路径在作者指定的主要物理设备上离线通过。
- 已接受的主要设备运行在纳入路径中没有 Avenor 导致的崩溃、ANR、意外启动、重复收藏、静默删除收藏或数据覆盖。
- 所选日常使用路径所需的清单、身份、启动、持久化、恢复、本地化、导航、手势和失败行为在该设备上符合链接的产品契约。
- 每项已知未执行检查、限制、未解决缺陷、权限或依赖关注点和兼容性缺口均已记录，且不表述为通过。
- 实现和交付文档已经 commit 并同步到作者指定的共享 Git 历史。

### 不阻塞 `1.0.0` 的建议证据

API 31 和 Pixel 兼容性、完整自动化测试和 release lint、merged manifest 与已解析依赖审查、可重复性能/内存/功耗分布、绝对质量阈值、baseline profile 评估和合格许可证结论继续作为有价值的后续证据。缺失结果保持未知。在指定主要设备上发现的纳入路径失败仍须解决，或在完成前明确修改产品契约。

## 产物、签名和已完成记录要求

- 日常使用基线是一个可安装、`applicationId` 为 `com.avenor.launcher`、`versionName` 为 `1.0.0` 且 `versionCode` 为 `1` 的 APK。
- 日常使用基线获验收前修改 `applicationId`，只在作者批准后替换计划身份；基线存在后修改它会形成不同的 Android 应用身份，不得表述为普通的原位升级。
- 记录已接受安装可获得的准确 APK 或构建身份以及对应源码 commit，不编造不可用证据。
- 本级别可以使用开发签名或其他作者控制的签名身份，并记录由此产生的更新或重新安装限制。稳定发布签名、证书指纹、安全保管和两份加密备份延期到开展正式发布制品时处理。
- 如果作者保留 APK，应将其放在产品仓库之外并记录逻辑位置。外部保留、SHA-256 计算和复制仍属于需要单独授权的操作，不是完成要求。
- 本契约不授权复制、提交、上传或分发 APK。

整合交付记录、支撑版本输入和原始迭代记录继续统一保留在稳定的 `docs/delivery/1.0.0/` 目录中。该已完成记录包含交付级别、标识、源码 commit、纳入迭代、重要变更、主要设备证据、限制和可用 APK/构建身份。本级别未报告也不要求保留产物位置、发布摘要或证书指纹。

`1.0.0` 不要求 tag、里程碑声明、GitHub Release、远程上传、应用商店操作或公开分发。

## 已知限制和遗留问题

完成记录区分产品范围排除项与已观察限制、未解决缺陷、工具链或测量约束、依赖义务、技术债、迁移工作和后续版本事项。

不能为了关闭版本而把纳入的验收失败重新标记为已知限制。改变产品行为或验收意图的限制，需要产品经理审核、项目作者批准并更新适用产品契约。

每个剩余事项记录受影响环境和行为、用户影响、证据、处置、后续目标和受支持替代方式。如果没有剩余事项，完成记录应陈述有证据支持的结论。

## 完成结果

`1.0.0` 已达到 `Author daily-use baseline` 级别并完成。

- 六个纳入迭代均为 `Completed`，其证据保留在该稳定版本目录中。
- 已验收 APK 使用 `applicationId` `com.avenor.launcher`、`versionName` `1.0.0` 和 `versionCode` `1`，对应源码 commit `053b6b7da58a27a9c237d98c2e49f7a94e5b1d3e`。
- 项目作者在 Android 16/API 36 的 Samsung Galaxy S23 Ultra 上验收完整所选离线路径，并报告不存在已知核心路径阻塞。
- APK 使用作者本地私有签名身份。后续原位更新必须使用同一身份；如果该身份不可用，则不能假定更新连续性。
- 准确 Gradle 与安装命令、APK 文件名、摘要、保留位置和命令输出未报告。
- API 31 与 Pixel 兼容性、完整自动化矩阵、性能分布、merged manifest 与解析依赖审查、合格许可证结论、正式安全和隐私审查、release 签名保管与备份，以及正式发布制品证据继续属于未知或未执行的后续事项，而不是已通过结果。
- 宣告该版本边界的原因是：完整最低离线 Home、Drawer、应用启动、操作面板和持久化收藏路径已获验收，可供作者持续日常使用。
- 未创建也不要求 tag、里程碑、GitHub Release、上传、发布或公开分发。

# 迭代 21：升级、回归与版本闭环

> 适用版本：[Avenor Launcher 1.3.0 交付](delivery.zh-CN.md)。状态与实际证据只属于 `delivery.zh-CN.md`；本契约不授权实现、版本修改、Git、制品、tag、发布或 Release 操作。

## 目标

形成真实端到端证据，证明所选 `1.3.0` 旅程可从已接受 `1.2.0` 基线安全升级、兼容既有 Launcher 行为，并可交由作者单独决定版本完成。

## 可观察结果

一个可追踪候选制品能在作者指定主要设备上升级已接受 `1.2.0`，按所选迁移保留可读收藏，完成迭代 15–20 旅程，并记录全部结果与缺口，而不暗示 tag 或公开发布获批。

## 纳入工作

- 对齐迭代 15–20 的产品契约、实现、测试、标识和证据，解决或记录重大不一致。
- 验证代表性 `1.2.0` 主／伴收藏经原位升级进入统一模型；全新安装可以提供补充证据，但不能替代该旅程。
- 验证 Home、编辑、多选、收藏栏、本地／跨容器移动、自动滚动、导航、启动、清单变化、持久化失败、同进程返回和进程重建。
- 检查 Manifest、`allowBackup`、`dataExtractionRules` 及适用等效配置，确认收藏文件不进入云备份或设备迁移备份，不预设当前已满足。
- 形成或识别带已接受标识、源提交、签名类别、摘要和升级限制的可安装制品。
- 将强制和建议检查真实记录为 Passed、Failed、Not run、Unknown 或 Unavailable；获授权且证据充分时更新交付记录。

## 排除工作

不在收尾中新增功能或隐藏未完成工作；不包含修复工具、恢复、云备份、私密空间、双击锁屏新范围、正式发布制品、GitHub Release、商店／公开发布、自动 tag，且不追溯修改 `1.2.0`。

## 技术改动区域

升级夹具与旅程、回归测试、备份配置检查、构建／制品追踪、物理设备验收、证据记录及仅在另行纳入范围时的聚焦缺陷修正。

## 依赖与顺序

依赖已接受的迭代 15–20。发现的实现缺口返回所属迭代或新作者批准范围；收尾不得静默吸收。

## 迁移与兼容影响

本迭代验证而不重新定义迁移。原位升级保留可读身份、目标映射、顺序和适用设置；不可读状态保持原样且禁用修改；不支持降级。

## 安全、隐私、权限与许可影响

不选择新权限、网络、数据类别、外部服务、依赖或许可影响。备份排除是强制兼容／隐私检查；不一致或扩大边界必须在完成前修正或交作者审查。

## 风险与未决事项

具体 `versionCode`、源提交、签名、制品、设备环境和 tag 处置在规划时不存在；构建通过不能证明迁移或日用验收；建议检查一旦执行并发现纳入路径失败，不能因其原本可选而忽略。

## 验收条件

- 迭代 15–20 已接受，且无未解决重大契约不一致。
- 候选保留 `com.avenor.launcher`，使用批准的 `1.3.0` 标识，并可追踪到源和签名类别。
- 强制主要物理设备从已接受 `1.2.0` 基线原位升级候选制品并完成旅程，无非预期丢失、重复、错误目标／顺序、破坏性覆盖、崩溃、ANR、错误启动或导航死路。
- 进程重建、清单变化、持久化失败、Undo、导航恢复和跨容器行为符合契约。
- 已检查备份配置且收藏数据不进入 Android 云备份或设备迁移；全部跳过、未知、失败或不可用检查准确记录。
- 作者单独决定版本完成及是否值得 tag；GitHub Release 仍可选且需独立授权。

## 验证要求

主要设备从已接受 `1.2.0` 基线原位升级及完整作者旅程是强制版本证据。全新安装是建议补充证据，不能替代升级。聚焦自动化及额外 API 31、API 36/37、OEM、profile、clone、语言、字体、导航模式、无障碍和性能覆盖为建议项，除非被提升。实际命令、环境、设备、制品和结果属于 `delivery.zh-CN.md`。

使用当前发布、验证、隐私、持久化和身份决定；不创建“收尾 ADR”，仅在实现证据形成重大边界时创建或修订持久决定。

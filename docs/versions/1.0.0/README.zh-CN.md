# Avenor Launcher 1.0.0 交付契约

> 英文语义源：[README.md](README.md)。
>
> 本版本级契约依据项目的[版本、产物与发布治理](../../release.zh-CN.md)，整合已批准的 [1.0.0 产品范围](product-scope.zh-CN.md)和受证据限制的[技术评估](technical-assessment.zh-CN.md)。本文通过链接引用纳入的迭代契约，而不复制其交付细节。
>
> 本文档不授权实现、架构决定、签名、产物移动、Git tag、GitHub Release 或公开分发。每个迭代都需要自己的契约和项目作者明确授权。

## 版本结果

`1.0.0` 交付首个可安装、经验证、满足项目作者日常使用最低可用要求的 Avenor Launcher APK。

完整版本结果是完成[产品范围](product-scope.zh-CN.md)选择的离线路径：将 Avenor 用作 Android Home 应用，在 Home 与 Drawer 之间移动，找到并启动平台暴露的应用，将其添加为持久化收藏，从 Home 启动，并移除该收藏。

- Android `versionName`：`1.0.0`
- Android `versionCode`：`1`

仅有文档、中间迭代或本地构建都不会形成正式版本。只有全部纳入的产品增量和版本级证据要求完成后，正式版本才存在。

## 纳入和排除范围

[1.0.0 产品范围](product-scope.zh-CN.md)是纳入行为、排除项、产品验收意图和详细当前产品引用的权威来源。本契约选择该范围而不重新定义它。

产品范围中的排除项继续排除在 `1.0.0` 之外，包括延期的设置行为、收藏排序、平台应用快捷操作、卸载与分身移除操作、手动语言选择、完整收藏损坏恢复行为、更广设备适配、网络或账号能力、分析、后续能力层和公开分发。

如果实现或验证证据与纳入行为冲突，受影响工作在契约不匹配处停止。技术角色记录证据和影响；产品经理与项目作者决定任何产品范围或验收变更。迭代不得静默地把失败要求转化为实现限制。

## 技术可行性边界

[技术评估](technical-assessment.zh-CN.md)认为所选范围可行，但仍需要仓库和设备证据。其中的候选方向不会因为出现在评估或本契约中就成为获批架构。

已确认版本约束包括：

- `minSdk` 31 和 `targetSdk` 36，除非获授权的产品契约更新改变它们。
- 实现获授权后，在产品仓库根目录创建 Android 项目。
- 核心行为保持本地和离线，不使用账号、服务器、云同步、分析或网络依赖。
- 已批准基线排除 `QUERY_ALL_PACKAGES`、`ACCESS_HIDDEN_PROFILES`、`INTERNET`、云备份和设备间迁移。
- 面向用户的字符串、颜色和可复用尺寸使用资源定义，并提供默认英文与简体中文资源。

稳定 API 37 `compileSdk`、准确 JDK/Gradle/AGP/Kotlin/Compose 组合、单 Activity Compose、项目自有 `LauncherApps` 边界、资料加组件身份、Proto DataStore、coroutines 和依赖注入等候选技术方向，由首个依赖它们的产品迭代及时验证。已证明的重大选择进入架构文档或 ADR；普通实现细节留在代码和测试中。

## 纳入的产品交付迭代

初步交付序列包含六个累积产品增量：

| 迭代 | 产品增量 | 主要完成证据 |
| --- | --- | --- |
| [迭代 1](../../iterations/iteration-1-home-minimum-usable-surface.zh-CN.md) | Home 最低可用界面 | 可安装的 Home 候选，以及必需基础环境中的本地化时间/日期行为 |
| [迭代 2](../../iterations/iteration-2-drawer-application-discovery-and-launch.zh-CN.md) | Drawer 应用发现与启动 | Home-to-Drawer 入口、平台暴露应用列表、恢复与准确条目启动 |
| [迭代 3](../../iterations/iteration-3-drawer-navigation-and-live-state-completeness.zh-CN.md) | Drawer 导航与实时状态完整性 | 产品完整的分组、索引、过渡手势、更新与稳定状态 |
| [迭代 4](../../iterations/iteration-4-application-action-sheet-and-favorite-creation.zh-CN.md) | 应用操作面板与创建收藏 | 模态应用信息和持久化添加到 Home 行为 |
| [迭代 5](../../iterations/iteration-5-favorite-lifecycle-and-resilience.zh-CN.md) | 收藏生命周期与韧性 | 完整添加、启动、重启、移除、调和与离线收藏闭环 |
| [迭代 6](../../iterations/iteration-6-compatibility-quality-and-formal-apk-closure.zh-CN.md) | 兼容性、质量与正式 APK 收尾 | 完整环境矩阵、实测质量、签名 APK、可追踪性与归档证据 |

每个链接记录定义一个可观察产品增量、排除项、技术影响面、依赖和验证计划。序列是累积的：后续迭代保留前序迭代已验收行为，除非获授权契约变更另有规定。

## 版本级依赖和决定

迭代开始变更工作前：

1. 前序迭代门禁已经满足，或者明确作者决定记录依赖为何改变；
2. 迭代契约已经对照当前产品范围和实现证据审核；
3. 未解决产品不匹配已经转交产品经理和项目作者；
4. 重大技术决定已经判断是否需要 ADR；
5. 项目作者已经明确授权该迭代实现。

整个版本中由项目作者保留的决定包括：

- 批准此前瞻性交付边界和序列；
- 授权和验收每个迭代；
- 任何 `minSdk`、产品范围或验收意图变更；
- 有证据证明稳定 API 37 候选无法复现后的 API 36 `compileSdk` 回退；
- 合格审查要求的任何面向用户许可证界面；
- 接受 OEM 限制；
- 绝对实测性能、内存、功耗与稳定性阈值；
- release keystore 创建、保管、备份与签名；
- 外部 APK 存储和保留策略；
- 任何 tag、里程碑声明、GitHub Release、产物上传或公开分发。

批准此前瞻性交付计划不表示批准候选架构，也不表示依赖证据的门禁已经满足。

## 验证和退出门禁

### 必需环境

| 环境 | 必需用途 |
| --- | --- |
| Android 12/API 31 模拟器 | 最低 SDK 功能兼容；不作为 OEM 或权威性能证据 |
| Android 16/API 36 的 Samsung Galaxy S23 Ultra | 三星 Home、分身/资料、badge、启动、手势、持久化和完整路径证据 |
| Android 17/API 37 的 Google Pixel 8 | 当前平台 Home、资料、启动、手势、持久化、性能和完整路径证据 |

模拟器不能替代任一真机。验证记录标识环境、OS/API、构建身份、源码 commit、APK SHA-256、步骤、结果和保留证据位置。

### 确定性门禁

- 项目通过仓库中实际成功的文档化命令可复现构建。
- Release lint 和所有选定自动化测试通过。
- Merged release manifest 不包含未批准权限、组件、备份行为或依赖贡献声明。
- 完整所选路径在每个必需环境中离线通过。
- 验收运行中没有 Avenor 导致的崩溃、ANR、意外启动、重复收藏、静默删除收藏或数据覆盖。
- 清单、身份、启动、持久化、恢复、本地化、无障碍、导航、手势和失败行为符合链接的产品契约。
- 已解析的 release 依赖图和许可证义务得到记录并解决，且没有未经批准的产品范围变更。

### 依赖证据的门禁

Iteration 6 记录可重复真机的冷启动、完整显示时间、关键交互帧行为、内存、空闲功耗和稳定性分布，并保留测量步骤与生成证据。项目作者只在这些测量存在后批准绝对退出阈值。

只有可复现 release 构建证据证明有实质收益时才纳入 baseline profile；它不是自动版本要求。

## 产物、签名和归档要求

- 正式产物是一个可安装、经验证、`versionName` 为 `1.0.0` 且 `versionCode` 为 `1` 的 release APK。
- 准确 APK 文件名从最终构建记录，不在构建配置存在前编造。
- APK 准确对应记录的源码 commit 和最终验证构建身份。
- 外部归档 APK 具有经过计算和复验的 SHA-256 摘要。
- 正式 APK 使用为 `1.0.0` 建立的稳定 release 签名身份；签名操作需要作者独立授权。
- 归档只记录 release 证书 SHA-256 指纹，绝不记录 keystore、私钥、密码、签名属性文件或其他秘密。
- 正式完成前，作者控制安全签名存储，以及 keystore 和恢复信息的至少两个相互独立加密备份。
- APK 保持在产品仓库外的 `../max-dev-context` 下，使用作者批准的逻辑目录与保留策略。
- 本契约不授权复制、提交、上传或分发 APK。

完成后，将整合契约、支撑版本输入和原始迭代记录移入 `docs/archives/v1.0.0/`，更新受影响链接，并记录标识、源码 commit、纳入迭代、重要变更、迁移、环境证据、限制、APK 文件名和逻辑位置、APK SHA-256、release 证书指纹，以及任何另行获批 tag 或 GitHub Release。

`1.0.0` 不要求 tag、里程碑声明、GitHub Release、远程上传、应用商店操作或公开分发。

## 已知限制和遗留问题

完成记录区分产品范围排除项与已观察限制、未解决缺陷、工具链或测量约束、依赖义务、技术债、迁移工作和后续版本事项。

不能为了关闭版本而把纳入的验收失败重新标记为已知限制。改变产品行为或验收意图的限制，需要产品经理审核、项目作者批准并更新适用产品契约。

每个剩余事项记录受影响环境和行为、用户影响、证据、处置、后续目标和受支持替代方式。如果没有剩余事项，完成记录应陈述有证据支持的结论。

## 完成结果

只有满足以下条件时，才能宣告 `1.0.0` 完成：

1. 六个纳入迭代契约都有可追踪验收证据并已关闭；
2. 完整所选产品路径和确定性门禁在每个必需环境中通过；
3. 实测质量分布满足作者批准的阈值；
4. 依赖、许可证、Manifest、安全、隐私、兼容性和 OEM 结论已经解决或明确处置，且没有未经批准的产品变更；
5. 已签名 release APK、版本标识、源码 commit、APK SHA-256、签名证书指纹、构建身份、外部位置和验证证据指向同一产物；
6. 限制和遗留问题不掩盖纳入要求失败；
7. 项目作者接受事实性完成证据；
8. 已完成版本与迭代记录移入 `docs/archives/v1.0.0/`，且链接已更新。

在这些事实存在前，本节定义关闭证据，不声明 `1.0.0` 已构建、验证、签名、归档或完成。

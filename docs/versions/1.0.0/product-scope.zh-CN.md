## 版本意图

`1.0.0` 为项目作者的日常使用建立首个可安装、经过验证且最小可用的 Avenor Launcher。

本版本验证一个主要产品结果：

> 作者可以将 Avenor 作为 Android 主屏幕应用使用，从 Home 进入 Drawer，查找并启动平台暴露的应用，将其作为持久化收藏添加至 Home，再次从 Home 启动该应用，并移除该收藏；完整核心路径可以离线使用。

本交付范围面向[版本、产物与发布治理](../../release.zh-CN.md)所定义的正式应用版本 `1.0.0`；只有满足所需完成证据后，正式版本才成立。它不要求 Git tag、GitHub Release、应用商店发布、公开分发 APK，也不要求实现完整的当前产品契约。

## 纳入的用户旅程

1. 作者在受支持的 Android 手机上安装并打开 Avenor。
2. Android 将 Avenor 识别为可用的主屏幕应用，作者可以通过系统负责的主屏幕选择路径选中它。
3. Home 展示当前系统时间、日期、星期和作者已保存的收藏。
4. 作者执行已定义的上滑手势进入 Drawer。
5. Drawer 按已定义的分组和区域感知顺序展示 Android 向 Avenor 暴露的可启动条目。
6. 作者通过滚动列表或字母索引定位条目并启动目标应用。
7. 作者长按条目，打开应用操作面板，并将该条目添加到收藏。
8. 该收藏出现在 Home 收藏列表末尾；只要其可启动身份仍然有效，进程重建和设备重启后仍然可用。
9. 作者从 Home 启动目标应用。
10. 作者从应用操作面板移除收藏，同时不从 Drawer 移除该应用。

## 纳入的产品范围

### Android 主屏幕能力

- Avenor 是可安装的 Android 应用，平台可以将其识别并选择为主屏幕应用。
- 当 Avenor 不是当前默认主屏幕应用时，仍可直接启动。
- 当 Avenor 被选为默认主屏幕应用时，系统 Home 操作打开 Avenor Home。
- 用户通过 Android 系统负责的路径完成默认主屏幕选择。`1.0.0` 不为该路径提供 Avenor Settings 入口。
- 进程重建后从 Home 开始。Drawer 的临时位置、已打开的应用操作面板和进行中的手势均不在进程重建后恢复。

### Home

- Home 展示不含秒数的系统时间，并遵循系统 12 小时制或 24 小时制偏好。
- Home 展示按当前区域格式化的系统日期和星期。
- 选择时间时隐式调用系统时钟目标；选择日期和星期时隐式调用系统日历目标。
- Home 按持久化的用户定义顺序展示已保存收藏。
- 全新安装时没有收藏，并展示已定义的从 Drawer 添加应用的引导。
- 选择可用收藏时启动目标应用并抑制短时间重复激活。
- 长按收藏时打开本版本纳入的应用操作面板行为。
- 被停用或暂时不可用的收藏继续保留，并遵循 Home 规格定义的不可用与刷新行为。
- 只有成功的应用清单刷新确认其可启动身份永久消失后，收藏才会被自动移除。
- 应用清单或启动失败不得静默删除已保存收藏。

### Home 与 Drawer 过渡

- 在 Home 上向上拖动是 `1.0.0` 进入 Drawer 的方式。
- Drawer 列表到达顶部边界后向下拖动返回 Home。
- 在 Drawer 按系统 Back 返回 Home。
- 在 Home 按系统 Back 时，遵循导航规格定义的默认 Launcher 与非默认 Launcher 行为。
- 手势进度、完成阈值、fling 完成、回弹、位置、透明度、列表边界转移、取消和指针安全行为均遵循当前导航规格。
- 过渡手势不得意外启动、长按或滚动应用条目。

### Drawer 应用清单与应用启动

- Drawer 展示 Android 向 Avenor 暴露的所有可启动条目，不把系统安装和用户安装应用作为不同产品类别处理。
- 当 Android 暴露主应用、应用分身或资料身份下的可启动条目时，Avenor 将每个暴露的身份视为独立条目，不得仅按包名去重。
- 条目使用平台提供的应用名称、图标，以及可用时的平台 badge。
- Drawer 使用 Drawer 规格定义的区域感知分组、稳定排序、分组锚点和同序值决胜规则。
- Drawer 包含 `#` 锚点以及所有非空的 A–Z 锚点。
- 右侧字母索引支持直接选择、连续索引滑动、当前字符展示和已定义的触觉反馈。
- 选择条目时启动目标应用并抑制短时间重复激活。
- 长按条目时打开本版本纳入的应用操作面板行为。
- Drawer 实现已定义的初始加载、空或失败结果、Retry 和成功恢复状态。
- 应用清单更新后，不得继续从过期 UI 启动已确认移除的条目；适用锚点仍存在时，应保持稳定排序和位置。
- 同一进程内返回 Drawer 时，在当前规格要求的范围内保留有意义的列表位置。

### 收藏

- `1.0.0` 包含收藏的添加、移除、存储、恢复和启动。
- 从 Drawer 添加收藏时，将其追加到 Home，并且不从 Drawer 移除。
- 移除收藏时只移除其 Home 引用，Drawer 中的可启动条目继续存在。
- 同一可启动身份不能被重复收藏。
- Android 将主应用和应用分身或资料条目暴露为不同可启动身份时，可以分别收藏。
- 除确认该特定可启动身份永久消失后的移除外，每次收藏变化都必须由用户明确操作触发。
- 收藏身份和顺序在正常进程重建和设备重启后继续保留。
- `1.0.0` 不提供用户控制的收藏排序。因此，除非条目被移除，收藏保持追加顺序。

### 应用操作面板

- 在 Home 或 Drawer 长按应用时打开模态应用操作面板。
- 面板包含应用身份展示、应用信息操作，以及适用的添加收藏或取消收藏 Launcher 操作。
- 应用信息打开系统负责的应用信息界面，并遵循已定义的失败与返回行为。
- 面板遵循当前深色表现、遮罩、拖动柄、模态输入阻止、关闭、操作完成、位置保留和失败反馈行为。
- 可用时，应用分身或资料 badge 遵循当前平台提供的身份表现。
- `1.0.0` 的面板不展示平台应用快捷操作、收藏排序、卸载、停用或应用分身移除操作。
- 被排除的操作不保留空白交互控件或占位。

### 语言与表现基线

- `1.0.0` 的每个用户可见字符串都具有 English 和简体中文资源。
- Avenor 自动跟随当前系统语言区域，对不支持的语言回退至 English。
- Home、Drawer 和应用操作面板使用当前深色主题前景表现，以及透明的 Home/Drawer 表面与系统栏请求。
- 纳入的界面遵循当前条目、图标、排版、触控目标、间距、系统栏和资源化数值规则。
- 纳入行为使用的加载、错误、重试、不可用和失败反馈均需本地化。
- `1.0.0` 字母索引最多包含 27 个槽位：`#` 加 A–Z。由于 Settings 被排除，索引不包含 Settings 齿轮，也不保留不可用的 Settings 占位。
- 纳入的索引需要 `540dp` 完整可用高度，即排除 Drawer 规格定义的 inset 后按 `27 × 20dp` 计算。低于该高度时，索引成为可独立滚动的区域。

### 本地与离线边界

- Home、Drawer、应用启动、收藏管理和纳入的应用操作面板行为不依赖网络连接、账户、云同步或自建服务器。
- 核心持久化用户内容仅限收藏所需的可启动条目身份和顺序。
- `1.0.0` 不收集或存储分析数据、应用使用历史、通知、联系人、位置、剪贴板内容、文件、照片或历史时间日期值。
- 任何必要的 Android 能力、Manifest 声明、权限或 package visibility 规则都必须为纳入的能力所必需且可追踪。
- 依赖的平台能力被拒绝或不存在时，不得阻断其他无关的已纳入核心行为。

## 明确排除于 1.0.0

以下当前产品契约行为从本版本延后：

- 完整 Settings 界面及其 Drawer 齿轮目标
- 默认 Launcher 状态展示和应用内系统默认主屏幕设置链接
- 隐私、Avenor License、Third-party License、项目仓库和可见版本信息入口
- 收藏排序模式、拖动柄、位置交换、排序触觉反馈和排序自动滚动
- 应用操作面板中的平台应用快捷操作
- 卸载、停用和应用分身移除操作
- 手动选择应用语言

以下能力仍在当前产品契约之外，因此同样排除：

- Widget、文件夹、主题、不受限的视觉自定义、Drawer 网格、模糊和玻璃效果
- 横屏、折叠屏、平板、桌面模式和外接显示器适配
- 网络信息、账户、云同步、服务器开发和跨设备备份
- 行为分析、自动排序、推荐、AI 辅助和 Agent 集成
- 日志、诊断导出、更新检查、支付、广告、订阅和商业能力
- 公开分发、应用商店提交、网站 APK 分发、GitHub Release 和大众市场验证

## 产品验收意图

只有按照适用的验证计划，在 Android 12/API 31 最低版本模拟器以及已记录的 Android 16/API 36 和 Android 17/API 37 两台真实设备上观察到以下全部结果时，产品范围才算满足：

- Android 可以将 Avenor 识别为主屏幕应用，作者可以完成系统负责的选择路径。
- Avenor 为默认主屏幕时，返回 Home 可以打开 Avenor Home，且不会阻塞或崩溃。
- Home 按适用语言区域展示正确的系统时间、日期、星期、空状态和已保存收藏。
- 已定义的手势能够可靠打开 Drawer，已定义的反向路径能够返回 Home，且不会意外激活应用。
- Drawer 展示 Android 向 Avenor 暴露的可启动条目，包括平台暴露时不同的应用分身或资料条目，不得因 Avenor 导致遗漏、重复或不稳定排序。
- 滚动列表和字母索引可以让作者定位目标条目，选择后启动该确切条目。
- 加载失败与加载中可以区分，Retry 可以发起新的读取，读取失败不会破坏收藏。
- 作者可以将 Drawer 条目添加到 Home、从 Home 启动、移除，并在每次操作后看到符合预期的 Drawer 和 Home 状态。
- 收藏状态在进程重建和设备重启后继续保留，且不会因暂时的应用清单失败而被删除。
- 纳入的核心行为在没有网络连接时仍可完成。
- English、简体中文和 English 回退行为一致应用于每个已纳入的用户可见字符串。

本文档不虚构可测量的性能、功耗、内存、启动响应和稳定性门槛。技术评估和后续验证契约必须提出基于证据的阈值，确保已纳入旅程足以支持作者日常使用。

## 技术评估输入

版本技术评估必须确定所选范围是否以及如何能够交付，至少包括：

- Android 主屏幕角色声明和系统负责的默认主屏幕选择路径
- `minSdk` 31、`targetSdk` 36，以及最新且兼容的稳定版 `compileSdk`；优先评估 API 37，如果 API 37 仍要求预览版或候选发布版工具链，则保留 API 36
- 最小应用查询、启动、package visibility 和权限范围
- 两台目标设备上主应用、应用分身和资料可启动条目的平台行为
- 适合收藏持久化与协调的稳定可启动条目身份
- 应用清单加载、刷新、软件包变化、停用条目和过期条目行为
- 能够满足可观察导航契约的手势与滚动仲裁
- 本地持久化以及进程和设备恢复行为
- 资源、语言区域、主题、系统栏、图标、badge 和触觉反馈实现约束
- 时钟、日历、应用信息和应用启动目标不可用时的安全处理
- 必需的第三方依赖，以及可能要求重新考虑产品范围的许可证告知义务
- API 31 最低版本模拟器以及两台已记录真实设备的验证方法和可测量质量门槛
- 后续 Settings、排序、快捷操作、卸载和更广泛当前产品契约交付的可能迁移成本

技术约束可以形成有记录的产品范围建议，但不能静默更改本版本或当前产品契约。实质变化需要项目作者作出指示，并更新适用的权威文档。

- `1.0.0` 不要求也不授权 GitHub Release、远程产物上传、应用商店提交或其他公开分发。
- 本产品范围文档不授权实现、创建签名密钥、移动产物、提交、创建 tag、推送或发布操作。每项操作仍须遵循项目的明确授权规则。

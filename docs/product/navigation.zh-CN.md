# 导航与界面层级模型

> 英文语义源：[navigation.md](navigation.md)。

## 职责

本文定义 Home、Drawer、Settings 与应用操作面板之间当前的层级、入口、退出、恢复和公共过渡行为。本文不规定 Home 与 Drawer 必须实现为两个独立 Compose 页面，或实现为同一个可拖动容器中的两个功能区域。

## 初始界面

- Launcher 启动或进程重建后，以 Home 作为初始界面。
- 即使后续实现使用同一个 draggable 容器，Home 与 Drawer 仍是两个不同的产品功能界面。
- Settings 只能通过点击 Drawer 末尾固定设置分组中的设置条目进入。AlphabetIndex 底部的设置齿轮只导航到该分组，不直接打开 Settings。
- Home 不提供 Settings 入口。

## 过渡模型

Home 与 Drawer 使用同一套可逆、跟手的直接操作过渡。以下术语定义其可观察行为：

- **手势偏移量：** 沿目标界面方向累计的拖动距离；反向移动会将累计距离逐步减小到零。
- **手势进度：** 手势偏移量除以 200dp，并限制在 0 到 1。200dp 是当前完整手势距离，未来可以通过产品变更重新调整。
- **Drawer 跟手位移：** 手指保持按下期间，手势每移动 1dp，Drawer 移动 1.5dp；进入和退出均使用 1:1.5 映射。
- **界面完整行程：** Drawer 在屏幕下方的屏外位置与屏幕顶部的最终位置之间移动。200dp 手势距离不表示屏幕高度只有 300dp。
- **停靠动画：** 松手结果确定后，系统从当前跟手位置自动补完到选定端点的剩余屏幕距离。用户不需要把 Drawer 手动拖过完整屏幕高度。

### 透明度

透明度依据手势进度计算，不依据 Drawer 已移动屏幕距离的百分比。设手势进度为 `p`：

- Home 内容透明度为 `max(0, 1 - 2p)`。
- Drawer 内容透明度为 `min(1, 2p)`。
- 进度 0% 时，Home 完全可见，Drawer 完全透明。
- 进度 25% 时，两个界面的内容透明度均为 50%。
- 进度 50% 时，Home 完全透明，Drawer 完全可见。
- 进度 50%–100% 时，Home 保持完全透明，Drawer 保持完全可见，同时位置继续变化。

反向过渡按相同数值倒序执行。回弹和补完动画必须从当前位置与透明度连续执行，不得跳变。

### 松手判定

- 手势进度达到或超过 60%，即 120dp 时，完成到目标界面的过渡。
- 低于 60% 松手时返回来源界面，除非该次松手构成指向目标方向的 fling。
- 指向目标方向的有效 fling 即使低于 60% 也完成切换。速度阈值和检测方式属于实现细节，但必须保持该可观察结果。
- 反向 fling 不得继续进入目标界面，应返回来源界面。
- 手势取消或被系统中断时，沿相同的位置与透明度路径返回来源界面。
- 额外触点不产生产品行为，不得导致位置跳变、反向切换、误触应用或同时出现第二个过渡。

## Home 进入 Drawer

- 普通 Home 模式下，上滑是用户通过手势进入普通 Drawer 的唯一入口。Home 编辑模式中的新增控件可以通过程序触发完成同一向上过渡并进入 Drawer 收藏多选模式；这不会在编辑模式中启用 Home→Drawer 拖动。
- 在 Home 正常模式下，上滑可从 Avenor 的 Home 交互区域内任意位置起始，包括时间、日期、收藏条目、空状态、加载状态、错误状态和 Retry 控件；系统保留区域中的系统手势仍由 Android 管理。
- 纵向上滑首先使收藏主列表滚向末端。主列表无法继续消费偏移量时，同一次连续手势的剩余偏移立即转交给 Home→Drawer 过渡，不要求用户抬手。过渡进度从转交后的偏移开始计算，不包含已被列表滚动消费的距离。
- 下滑使收藏主列表滚向起始位置，不触发 Home 界面过渡。只有建立横向意图后，横向收藏织带才消费手势。
- Home 编辑模式生效期间禁用 Home→Drawer 拖动。模块或应用拖动柄在识别后负责对应移动，其他纵向拖动负责滚动收藏主列表。
- 一次触控序列只能产生一种 Home 操作。在可交互元素的点击或长按操作提交之前，一旦识别为向上拖动，手势所有权即转交给 Home→Drawer 过渡，并取消该元素的点击、长按和对应触觉反馈。
- 基础信息区符合条件的空白位置中，两次点击可以解析为 [double-tap-lock.zh-CN.md](features/double-tap-lock.zh-CN.md) 定义的锁屏手势。任何已经取得过渡所有权的拖动都会取消该识别。时间、日期星期、收藏及其他交互目标永不参与双击锁屏。
- 只有在抬手前该触控序列未成为向上拖动或长按时，才提交点击操作。长按一旦被识别并打开对应操作，同一次触控序列不得再启动 Drawer 过渡。
- 触控序列被取消时不执行点击或长按；如果 Home→Drawer 拖动已经取得手势所有权，则按照界面过渡的取消规则处理。

## Drawer 返回 Home

- 系统 Back 通过反向过渡的补完路径从 Drawer 返回 Home。
- Drawer 普通模式顶部应用栏中的返回箭头也通过相同补完路径返回 Home。
- 下滑时先将应用列表滚向顶部边界。
- 列表滚动偏移量大于零时，下滑偏移量只由列表消费，Drawer 不开始退出。
- 同一次连续下滑中，列表偏移量到达零后，剩余偏移量立即转交给 Drawer→Home 过渡，不要求用户抬手后再次下滑。
- 界面过渡接管剩余手势后，列表保持在顶部边界，直到过渡停靠完成。

## Back 与恢复

- Avenor 已是系统默认 Launcher 时，Home 上的 Back 不产生可见行为；未设置为默认 Launcher 时，Avenor 执行普通系统 Back 行为，不规定最终返回的外部目标。
- Drawer 上的 Back 返回 Home。
- Settings 上的 Back 返回进入前的 Avenor 界面，当前即 Drawer。
- 应用操作面板上的 Back 关闭面板，并返回保持不变的底层界面。
- Home 编辑模式中，Back 先收起已展开的样式面板，否则退出到普通 Home。Drawer 收藏多选模式中，Back 先取消全部未确认选择并通过反向过渡返回 Home 编辑模式，不会同时退出编辑模式。
- 进程重建后从 Home 开始，不恢复 Drawer、Settings、应用操作面板、编辑模式及瞬时面板或选择状态。同一进程内普通 Avenor 往返保留收藏主列表有意义的纵向位置和每条织带有意义的横向位置；进程重建后均回到内容起点。

## Android 系统 Home 操作与外部应用返回

- 当 Avenor 被选为默认 Launcher 时，从任意 Avenor 界面（包括 Home 编辑模式、Drawer、Drawer 收藏多选模式和 Settings）执行 Android 系统 Home 操作都会显示普通 Avenor Home。活动中的收藏多选会被取消，编辑模式也会退出。同一进程内，普通 Home 保留最近一次成功完成的滚动或编辑所形成的主列表与织带有意义位置；取消尚未完成的手势不会产生新位置。这属于系统导航结果，不是 Avenor 的 Back 或 Drawer→Home 过渡；Avenor 不得将 Android 系统 Home 操作重新解释为 Back。本契约中未加限定的 `Home` 只表示 Avenor 产品界面，永远不表示该平台操作。
- 从 Home 或 Drawer 启动普通应用会形成一次外部应用暂离。当 Avenor 在同一进程中返回时，显示 Home 而不是恢复 Drawer；在展示已有 Home 内容前，不显示 Loading，也不要求执行一次阻塞式新的初始读取。
- 同一进程返回时，保留 Home 收藏状态、收藏主列表有意义的纵向位置和每条织带有意义的横向位置。不恢复 Drawer、Settings、应用操作面板、编辑模式或进行中的 Drawer 位置。
- 外部应用运行期间观察到的变化应在不将返回的 Home 替换为 Loading 的前提下协调。更新后的应用清单和收藏状态在下次展示 Drawer 或相关 Home 内容时可用，并遵循各界面的实时更新规则。
- 如果外部应用运行期间 Launcher 进程被重建，则适用进程重建规则，不适用同一进程返回规则。

## 系统界面

- Home 与 Drawer 显示系统状态栏。
- Home 保持透明应用表面；Drawer 的应用背景遵循其当前选定的背景模式，不由本导航契约定义。
- Home 与 Drawer 请求透明状态栏和导航栏区域，并在其下方进行 edge-to-edge 绘制。Avenor 不增加独立的不透明系统栏背景；适用的 Home 或 Drawer 界面处理继续由对应表现规范负责。
- Avenor 保留平台和设备默认的对比度保护行为。适用 Android 版本在三键导航等情况下提供的系统半透明保护层，不由 Avenor 替换或强制关闭。
- 系统导航栏和导航控件跟随用户当前的系统导航模式；Avenor 不隐藏它们，也不进入沉浸模式。
- Home、Drawer、Settings 和所有应用操作面板使用 dark theme 与浅色前景元素。打开面板时不得把状态栏图标切换为深色样式。
- 即使 Home 与 Drawer 在透明系统栏后方进行 edge-to-edge 绘制，内容和交互目标仍必须避让系统栏、屏幕开孔和系统手势 inset。

## 验收意图

- 上滑 100dp 时，手势进度为 50%，Drawer 在停靠前的跟手位移为 150dp。
- 未构成有效 fling 时，在 119dp 松手返回来源界面；在 120dp 或更大距离松手完成到目标界面。
- 低于 120dp 的有效目标方向 fling 仍完成到目标界面。
- 用户反向移动、松手、补完或回弹时，位置和透明度都保持连续；Drawer→Home 从 Drawer 列表滚动转交手势时也保持连续。
- 在 Home 正常模式下，上滑能够从每个由 Avenor 管理的 Home 元素上起始，且不得同时触发该元素的点击或长按。
- Drawer 列表到达顶部前，下滑只滚动列表；到达顶部后，剩余偏移量在同一次手势中转交给退出过渡。
- 打开或关闭 Drawer 时不得误触发应用点击、长按或列表滚动。
- Avenor 作为默认 Launcher 时，从 Drawer 和 Settings 执行 Android 系统 Home 操作都显示 Home，不依赖 Avenor 的 Back 操作。
- 同一进程从普通应用返回时显示 Home，不显示 Loading，也不恢复 Drawer。
- 实现可以选择任何满足上述可观察行为的架构。

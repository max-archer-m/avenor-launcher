# 产品设计基础约束

> 英文语义源：[design-foundations.md](design-foundations.md)。

## 当前主题

- Avenor 所有界面均采用 dark theme，无论该界面本身是否绘制不透明背景。文字、图标、控件和语义颜色角色均使用深色主题呈现。
- Home 与 Drawer 不绘制可见的应用背景。它们的内容表面、状态栏区域和导航栏区域均请求完全透明，使 Avenor 下方的系统背景保持可见。
- 当前产品契约中，Avenor 不为 Home 或 Drawer 添加持久的背景渐变、固定 Scrim、模糊、玻璃效果或其他对比度保护层；这不禁止下文定义的应用拖动边缘提示等短暂、局部交互反馈。未来 Drawer 的玻璃或模糊效果属于可叠加能力，本次不定义。
- Settings 使用不透明的标准 Material 3 dark color scheme。使用 `surface`、`onSurface` 及相关 container 等 Material 语义角色，不自行发明页面专属的深色十六进制颜色；最终资源值留待设计 token 工作确定。
- 模态面板保持深色，弹出时必须维持状态栏图标为浅色。
- Home 与 Drawer 请求透明系统栏，并保留平台或设备默认的对比度保护行为。Avenor 不关闭、不替换，也不重复绘制系统对比度保护。
- 系统导航模式和导航控件根据用户的系统配置正常显示；Avenor 不进入沉浸模式，也不隐藏系统导航。
- 主题自定义属于未来可叠加能力，不在当前契约中定义。

## 布局

- 产品间距使用语义化设计 token，不在各页面任意散布字面数值。
- 布局与可达性决策主要针对右手持机并以右手拇指操作，以及左手持机并以右手点控两种方式优化；其他操作姿势属于次要考虑，而非同等优化目标。
- Home 不设置统一内容 padding。基础信息模块同样不增加 padding；时间行与日期行分别定义自身几何：两者相对适用的屏幕安全边缘使用 `16dp` start 和 end margin，时间行另使用 `16dp` top margin，日期文字继续相对时间文字增加独立的 `8dp` start 内缩；纵向收藏列表容器、收藏栏容器和单个收藏条目均不增加 padding；相邻且可见的 Home 模块以及相邻纵向收藏列表之间使用 `8dp` 间距。普通模式与编辑模式保持这些边界，编辑表面、边界和控件不再增加外侧缩进。
- 应用操作面板分割线采用 `16dp` 横向缩进。
- Home 是固定且不可分页的界面。收藏列表区当前最多包含两个地位相同的纵向列表，不使用文件夹或另一个展示界面；每个列表仅在内容超出共享视口时独立滚动。
- Home 采用内容驱动的纵向尺寸，整体不纵向滚动。基础信息模块包裹必要内容和交互目标。收藏列表区与已有内容的次级收藏区在包含 `8dp` 间距后的自然高度能够放入剩余安全高度时，两者保持自然高度，收藏列表不滚动；超出时，次级收藏区保留收藏栏容器形成的自然高度，收藏列表区获得其上方剩余视口，只有溢出的列表在内部纵向滚动。全宽次级收藏区没有内容时高度为零，最多包含五条高 `56dp` 的横向收藏栏容器；每个容器不增加 padding，只有按内容测量的条目溢出时该视口才独立横向滚动。
- Home 的收藏列表区和每个纵向列表均不增加 padding。一个列表占用收藏列表区完整宽度；两个可见列表在扣除 `8dp` 列表间距后平均分配剩余宽度。收藏内容位置由条目内部元素的明确 margin 决定。宽度根据可见列表数量计算，不采用固定百分比。列表共享一个视口高度，各自保留内容和滚动状态；持久化空列表不得存在。
- 收藏尺寸是列表级 token。“大”使用 `48dp` 图标、`64dp` 条目高度和正常字重的 `18sp/28sp` 名称；“中”使用 `40dp`、`56dp` 和 `16sp/24sp`；“小”使用 `32dp`、`48dp` 和 `14sp/20sp`。所有新建或迁移列表初始使用“中”；编辑模式列表尺寸控件可以分别为每个持久化列表选择并保存“大／中／小”。收藏条目不增加 padding；图标使用 `16dp` start margin 并纵向居中，随后保持 `16dp` 图标名称间距。三种尺寸均使用系统字体缩放和一行静止末尾省略名称。普通模式与编辑模式保持已保存的列表尺寸；每个应用条目使用 `24dp` 拖动柄图形，并将其居中放入贴合物理右侧边缘、宽 `40dp` 且占满条目高度的热区。热区不增加 end margin，并作为作者批准的紧凑热区例外。
- Home 编辑模式中，每个当前已定义且可编辑的模块使用同一种淡灰色、轻微透明且带小圆角的编辑表面。基础信息模块、收藏列表区和已有内容的次级收藏区都显示该模块级表面。每条收藏栏另外使用浅色前景语义色 `12%` alpha 的 `1dp` 独立边界和 `12dp` 圆角，内部保持透明。模块表面位于内容背后而不降低内容亮度，也不表示基础信息模块可以编辑。共享表面颜色、透明度与圆角 token 的精确值仍需视觉校准。

- 次级收藏条目使用固定且不可选择的“中”高度：`40dp` 图标、`56dp` 条目高度、`8dp` start 间距、`8dp` 图标名称间距、一行静止且必要时末尾省略的正常字重 `16sp/24sp` 名称，以及 `8dp` trailing 间距。文字实测宽度最多为 `64dp`，条目按内容测量且最大宽度为 `128dp`；文字上限约等于当前字体缩放下四个全角中文字符的字宽，所有语言均按渲染宽度测量而不直接按字符数量判断。每个收藏栏容器高 `56dp` 且不增加 padding，其条目同样不增加 padding。纵向列表尺寸菜单不适用于收藏栏。条目左对齐，相邻间距 `8dp`，不重新分配收藏栏中的未使用宽度。普通模式与编辑模式保持已经计算的宽度，编辑控件可以使名称更早省略。相邻收藏栏容器使用 `8dp` 纵向间距。每个条目以浅色前景语义色 `6%` alpha（不透明度）作为背景，以同一语义色 `12%` alpha（不透明度）绘制 `1dp` 边界，并使用 `12dp` 圆角；按压反馈沿用当前浅色 ripple。当前收藏栏不预留标题高度。
- 应用级拖动自动滚动使用不可交互的边缘提示，不使用覆盖完整容器的蒙层。该提示是从浅色前景语义色派生、向内覆盖 `48dp` 的渐变：内容侧为透明，活动边缘最高不超过 `8%` 不透明度。只有对应方向仍可继续滚动时才显示，不拦截输入、不改变几何，并始终位于插入与交换反馈之下。
- Home 编辑模式的新增控件使用带前置文本`＋`的本地化纯文本操作，不使用独立图标资源或装饰容器；交互目标高度至少为 `48dp`，宽度足以容纳本地化文案。持久化目标显示`＋ 添加应用`，临时目标的文案明确其将创建的容器。Drawer 在状态栏安全 inset 下方使用固定 `56dp` 高的透明顶部应用栏；普通模式返回箭头沿用 `24dp` 功能图标 token 和 `48dp` 交互目标。
- Home 编辑模式的应用条目取消收藏控件复用 X 图形资源，在条目左上角的 `20dp × 20dp` 实色 error 红色背景上显示白色 X。可见控件和交互热区共用 `20dp × 20dp` 边界，由 `8dp` 边缘间距与 `24dp` X 资源尺寸的一半组成，不增加独立横向操作列。作者明确批准该紧凑取消收藏热区作为常规 `48dp` 最小值的例外。控件不得遮挡应用主要识别图形或平台 clone/profile badge，并与尾部 `24dp` 拖动柄及其贴合物理右侧边缘、宽 `40dp`、占满条目高度的热区保持分离。
- 持久化纵向收藏列表在编辑模式中使用固定的 `40dp` 高控制栏，之后保留 `4dp` 内容间距。一个高 `36dp` 的浅色前景整体表面横跨列表宽度，在控制栏内垂直居中且上下各留 `2dp`，使用 `8%` 填充、`12%` 的 `1dp` 边界和 `8dp` 圆角。删除列表、尺寸和调整列表顺序控件保持在物理左侧、中间和右侧，不为未定义的未来操作预留槽位，也不在 RTL 环境下镜像。每个控件使用作者批准的紧凑 `36dp × 40dp` 热区。删除控件在持续可见的 `32dp`、`8dp` 圆角实色 error 红底上使用 `20dp` 白色 X；尺寸沿用本地化单字符和固定视觉字号；排序使用 `20dp` 拖动柄。尺寸与排序没有常驻独立背景，只在按压时显示有边界的 `32dp` 圆角状态层；删除则调整红色状态。三者均不使用 Ripple，排序在活动拖动期间保持按压态。
- 列表尺寸菜单使用三个 `64dp` 高 Material 菜单条目，每项只提供一个选择目标。物理内容顺序为单选标记、项目内打包的 Android 默认通用应用图标预览、再到本地化标签，并且不在 RTL 环境下镜像。同一份本地图标资源分别以 `48dp`、`40dp` 和 `32dp` 展示，仅作装饰、不含 badge，也不在运行时读取。完整条目使用有边界 Ripple 和平台深色表面 elevation。
- Drawer 收藏多选在每个应用图标前固定预留 `40dp` 选择区域。可选且未选中时，区域内居中的 `24dp` 圆形指示器使用 `1dp` Material `outline` 边框和透明内部；选中后以浅色前景语义角色填充圆形，并用深色 `surface` 语义角色、`14sp/20sp` 中等字重显示从一开始的选择序号，同时整行使用浅色前景角色 `8%` 不透明度背景。指示器属于完整条目目标，不是独立控件或无障碍节点。完整条目以应用名称建立一个切换选择语义节点：未选中报告`未选择`，选中报告`已选择，第 N 项`，已经收藏且不可选择时以 disabled 状态报告`已收藏，不可选择`。已经收藏的条目保留空心指示器，指示器、图标和名称统一使用 disabled 语义透明度。
- 可编辑收藏栏在中部应用视口之外使用固定的 `48dp × 56dp` 控制轨：逻辑 start 为删除收藏栏，逻辑 end 为收藏栏排序。其可见 `24dp` X 和拖动柄图形与应用级控件保持区分，固定控制轨通过轻微 `1dp` 分割线与滚动内容分隔。控制轨只缩小编辑模式视口，不调整按内容测量且最大宽度为 `128dp` 的应用条目。只有一条持久化收藏栏时隐藏排序呈现和交互，但保留 end 控制轨；至少存在两条时显示。临时收藏栏不提供任一控制轨操作。

## 字体

- 字体跟随系统字体缩放。
- 时间采用 `57sp/64sp` 的粗体展示角色，字体支持时使用等宽数字。
- 日期、星期、应用名称和普通信息采用 Material 3 `bodyLarge` 的 `16sp/24sp` 参考值，除非具体组件规格定义其他语义角色。
- 应用名称保持一行和静止。名称无法完整显示时使用末尾省略号；Avenor 不为应用名称使用跑马灯。
- 当前个人使用布局不单独适配极端字体缩放；系统字体缩放超过单行组件边界时，文字仍限制在该单行边界内裁切。
- Settings 主要标题使用 `titleMedium`（`16sp/24sp`）和 `onSurface`；副标题使用 `bodySmall`（`12sp/16sp`）和 `onSurfaceVariant`；居中的次要信息项使用 `titleSmall`（`14sp/20sp`）和 `onSurfaceVariant`。

## 图标与应用身份

- 功能图标尺寸描述可见图形本身，不代表其容器或交互边界。标准功能图标为 `24dp × 24dp`；除非具体组件规格明确规定其他尺寸，该 token 适用于普通图标按钮、操作图标、应用快捷操作图标、Drawer 返回箭头、Settings 右侧箭头及当前其他图标控件。如果适用页面契约后续加入 Settings 的可见返回箭头，或加入 Pixel 设置风格的 Settings 条目前置图标，这些图标同样使用该标准 token。
- 标准功能图标独立可交互时，仍应位于至少 `48dp × 48dp` 的可聚焦触控目标内。图标和标签共同组成一个操作时，完整组合项是单一交互与无障碍目标；图标不产生第二个目标。
- 非交互状态图标为 `40dp × 40dp`。当适用组件定义了独立的加载结果、空状态或错误说明图标时，使用该 token。状态图标本身不接收触控目标或 ripple；相邻操作仍是独立控件。
- 功能图标和状态图标使用适用的语义内容色，并保持一致的视觉重量。不得只为满足名义 token，而在 `24dp` 或 `40dp` 视口内放置比例失衡的过小图形。
- 仅图标控件必须具有本地化无障碍名称。装饰图标，或已有相邻标签为同一个组合操作命名的图标，不得暴露重复的无障碍描述。
- 定义图标尺寸 token 本身不代表向页面新增对应控件。Drawer 契约当前已经纳入返回箭头；Settings 返回箭头和 Settings 条目前置图标只有在适用页面或导航契约明确纳入后才会显示，此处仅确定其视觉尺寸。
- 原生自适应应用图标遵循当前设备 mask，例如设备特定的圆形或 squircle 呈现。
- 不包含自适应图层的旧式图标在当前设备 mask 内规范化呈现，并在安全区域内保持其完整可识别主体。
- 应用分身或资料 badge 使用平台返回数据，在形状规范化后添加以避免被 mask 裁切，并在 Home、Drawer 和相关应用界面中保持一致。
- Drawer 使用 `40dp × 40dp` 的可见应用图标，应用条目高度至少为 `56dp`。Home 使用上文定义的“大／中／小”列表级尺寸。
- 在 Drawer 中，图标和应用名称在条目中纵向居中；可见图标边界与应用名称区域之间的横向间距为 `16dp`。
- 完整 Drawer 条目仍是点击和长按目标；其 `40dp` 图标只是视觉尺寸，不限制条目触控目标。Home 交互目标几何遵循上文定义的“大／中／小”收藏尺寸 token 及适用的 Home 组件规格。
- 应用图标无法加载时，在 Home 或 Drawer 的相应视觉区域使用 Android 平台默认的通用 app icon，并遵循相同的形状规范化和 badge 规则；不留空，也不替换为无关的 Avenor 图标。
- 当前目标设备预计会提供应用分身或资料 badge。平台没有提供时，Avenor 当前不增加自己的备用 badge 或第二身份标签；此类备用身份呈现属于未来可叠加能力。
- 当前产品契约不要求精确复刻 OEM 专有阴影、图标包、主题服务或其他 Launcher 专属效果。

## 交互与无障碍

- 即使可见内容较小，交互控件也应遵循 Android 无障碍建议，提供至少 `48dp × 48dp` 的可聚焦触控目标。这是默认底线；没有经作者接受、并由聚焦设备证据支持的组件级理由时不得缩小。高密度布局应优先分离视觉尺寸与热区几何，或采用不存在语义冲突的覆盖方式。
- Home 时间行高度至少为 64dp；日期行高度为 48dp，并直接提供其可聚焦触控目标。
- 按压、聚焦、选中和禁用状态不能只依赖颜色表达。
- 每个已启用且会执行点击或长按操作的目标，从按下开始提供有界 Material ripple，除非组件契约定义了其他可见按压状态。Ripple 裁切在目标的实际交互边界内，并遵循适用的目标形状；不得扩散到相邻条目，也不得暗示更大的区域可以交互。纵向列表级圆形编辑控件改用其明确规定的仅不透明度按压状态。
- 在当前深色主题契约下，ripple 使用从浅色前景内容角色派生的、低透明度的浅白色。其准确颜色和透明度属于全局共享的语义设计 token，不得由各页面分别定义。
- Ripple 只表示输入正在被按压，不表示操作已经成功。长按目标在达到长按阈值前显示相同的按压 ripple；只有长按被识别后，才提供另行定义的触觉反馈。
- 如果输入转化为滚动、拖动、界面过渡手势、取消或其他非点击交互，应取消按压指示且不得触发点击操作。禁用目标不显示暗示可操作的 ripple。
- 未来浅色主题必须使用从其前景内容角色派生、并能与所在表面保持可见对比度的 ripple，不要求继续使用当前浅白色 ripple。此跨主题原则不会把浅色主题支持加入当前产品契约。
- 触觉反馈遵守系统能力与用户设置。当前语义类型为长按确认，以及短促的索引或编辑移动步进；具体平台常量仍需实现验证。
- 拖动语义以容器为基础。在同一纵向列表、同一收藏栏或收藏栏排序列表内进入另一主体时立即交换并持久化；同容器间隙不插入。进入另一应用容器时，只显示已有主体交换高亮或间隙插入线，并只在有效松手后持久化一次操作。跨容器预览在松手前保持源尺寸，落位后采用目标容器的呈现。
- 小屏专用布局和 TalkBack 专用字母索引行为不在当前个人使用范围内。字母索引使用固定 20dp 槽位；最大 28 槽模型无法在 560dp 可用高度内展示时，索引改为滚动。

## 资源化数值

面向用户的字符串、颜色、尺寸和其他可复用呈现数值必须按适用情况使用可本地化、可主题化的资源，不得作为硬编码字面量散布在产品 UI 代码中。具体 Android 资源组织方式和 Compose 访问结构属于未来技术架构。

# Drawer 交互规格

> 英文语义源：[drawer.md](drawer.md)。公共导航见 [navigation.zh-CN.md](../navigation.zh-CN.md)，空间草图见共享的 [Drawer 线框](../wireframes/drawer.txt)，阅读规则见[线框索引](../low-fidelity-wireframes.zh-CN.md)。

## 目的与布局

Drawer 展示从平台暴露给 Launcher 的来源中成功读取的全部可启动应用条目，包括应用分身。系统应用与用户安装应用一视同仁。

“全部可启动应用条目”受 Avenor 当前 Android 角色与最小权限约束，不表示全部已安装包、隐藏资料，或只有新增其他敏感权限后才会变得可见的条目。

- 应用清单使用单列列表；未来网格属于可叠加能力，不在当前契约中定义。
- 每个分组锚点标题独占一条 `32dp` 高的行，并随应用列表正常滚动；分组锚点不会吸顶覆盖后续内容。标题采用 `14sp/20sp` 中等字重，并相对应用条目内容边界使用 `56dp` start 内缩，使其在 `40dp` 图标和 `16dp` 图标名称间距之后与应用名称列对齐。该内缩只作用于锚点标题，不为应用条目增加永久 margin。
- 每个应用条目至少高 `56dp`，展示 `40dp` 的平台图标、存在时的平台 badge 和应用名称；图标与名称之间为 `16dp`。
- 应用名称只占一行并保持静止；无法完整显示时，使用 [design-foundations.zh-CN.md](../design-foundations.zh-CN.md) 定义的末尾省略号。
- 点击应用后立即启动，并抑制短时间内的重复启动。
- 长按应用产生长按触觉反馈并打开应用操作面板。

## 顶部应用栏

- Drawer 始终在状态栏安全 inset 下方保留一个固定的 `56dp` 高顶部应用栏。应用列表滚动时该栏保持固定，沿用透明 Drawer 表面，不增加可见栏背景。
- 普通模式左侧包含标准 `24dp` 返回箭头，位于 `48dp` 交互目标内。点击后完成与系统 Back 相同的 Drawer-to-Home 向下过渡。中部是为未来搜索框保留的空白、不可交互槽位；当前不显示标题、搜索提示、占位文字或不可用控件。右侧在视觉上为空，也不存在交互目标。
- 应用列表和 AlphabetIndex 从顶部应用栏下方开始，不得与其控件重叠。索引可用高度的计算需要扣除该固定栏高度。

## 收藏多选模式

- 点击 Home 编辑模式中的新增控件后，复用现有 Drawer 界面进入收藏多选模式，并记录该控件对应的持久化列表、临时列表、已有织带或临时织带目标。Drawer 由程序触发完成向上过渡，不要求用户再次拖动。
- 该模式复用相同应用清单、区域排序、应用条目、分组锚点和 AlphabetIndex。固定 Settings 分组及 Settings 索引 token 隐藏，因为 Settings 不是可选择的应用目标。
- 顶部应用栏将普通内容替换为左侧`取消`、中间本地化目标说明和右侧`确认`。没有选择任何应用时，确认按钮禁用。
- 点击可选应用时切换选中状态，不启动应用；该模式禁用长按操作和应用操作面板。所有应用条目都在应用图标左侧预留相同的选择顺序区域，避免条目内容横向跳动；已选条目在此显示从一开始的选择序号。
- 选择顺序就是用户依次选中条目的顺序。取消某个条目后，后续序号立即连续重排；确认时按照当前显示的序号顺序将剩余条目追加到已记录目标。
- 已经归入任一纵向收藏列表或次级收藏织带的身份继续显示，但不可选择。判断该状态时，主应用、应用分身和工作资料条目继续使用彼此独立的稳定身份。
- 点击确认时一次性保存当前完整选择，然后完成向下过渡并返回同一个 Home 编辑模式。点击取消、系统 Back 或有效的 Drawer 下滑退出时，丢弃全部未确认选择、完成向下过渡并返回 Home 编辑模式。
- Android 系统 Home 操作也会丢弃全部未确认选择，但同时退出 Home 编辑模式并直接落到普通 Home。任何取消路径都不持久化部分选择，向下动画本身也永远不代表确认。
- 应用清单变化按稳定条目身份协调，不打断多选。新安装条目以未选状态出现；已选条目的名称或图标变化时原位更新并保留选择序号；资料临时不可用或清单局部读取失败时保留受影响条目与选择，不将其视为永久消失。这些非破坏性变化不显示额外反馈。
- 刷新确认已选应用卸载、应用分身删除或其他可启动身份永久消失时，Drawer 从当前选择中静默移除该行，并连续重排后续序号。未选身份确认消失时只移除该行。两种情况都不显示 Toast、Snackbar、Dialog 或其他显式提示。
- 点击确认时根据最新可靠清单重新验证选择，并静默过滤已确认永久消失的身份。剩余有效身份按当前显示顺序原子保存。没有任何有效身份时，不执行写入，并沿用普通确认后的向下过渡返回 Home 编辑模式，不增加额外反馈；该竞态不引入专门的校验状态或按钮禁用状态。页面可见选择本来已经为空时，确认按钮继续沿用现有禁用规则。
- 保存失败时，Drawer 停留在收藏多选模式，保留当前有效身份及显示顺序，并显示现有收藏更新失败反馈。用户可以再次点击确认，或使用任一普通取消路径；不得持久化部分选择，也不得返回 Home 暗示添加成功。
- 执行变更前，如果已记录的目标引用已经失效，Drawer 丢弃全部未确认选择，且不得将其改投最左侧列表、其他织带或新建的替代目标。持久化列表或已有织带在对应目标被删除后引用失效。临时列表或临时织带只要其来源多选会话和 Home 编辑上下文仍然有效、且适用的列表或织带上限仍允许创建，就继续作为有效的创建意图；不得仅因尚无持久化容器而判断失效。会话被替换、Home 编辑上下文已经结束或不再允许创建时，该临时引用才失效。来源 Home 编辑上下文仍有效时，Drawer 返回该上下文并显示现有收藏更新失败反馈；上下文已经结束或被替换时，Avenor 沿用已经确定的退出或替换状态，不重新创建旧编辑模式，也不干扰更新的选择会话。

## 资料与 Private Space 边界

- Android 无需隐藏资料访问即可向 Avenor 正常暴露的普通、工作资料和克隆可启动条目，继续遵循现有应用清单、身份、排序、启动、收藏和刷新规则。
- 当前产品不支持 Android Private Space，也不声明 `ACCESS_HIDDEN_PROFILES`。
- Avenor 不主动查询、访问、展示、去重、排序、启动、收藏或恢复需要隐藏资料访问的 Private Space 条目状态。
- Avenor 不提供 Private Space 独立容器，也不提供显示、隐藏、锁定、解锁、收藏或恢复 Private Space 状态的控制。
- 在该边界下不出现 Private Space 条目是符合预期的产品行为，不属于 Drawer 应用清单不完整或加载错误。
- 平台暴露普通、工作资料或克隆条目不会使其被归类为 Private Space，也不会使其脱离当前产品契约。
- 未来支持 Private Space 是一项独立产品能力。它进入当前契约前，必须由项目作者作出新的决定，并重新审查产品交互、权限、隐私、兼容性和验证范围。

## 分组与排序

- 排序先根据完整的应用显示名称生成规范化排序形式，再使用 Android 当前系统语言区域提供的 locale-aware 排序规则；实际显示名称不会改变。
- 规范化排序形式使用平台提供的汉字转拉丁文字结果，消除拉丁字符重音差异并忽略大小写。因此，汉字名称和原本使用拉丁字符的名称参与同一套混合排序，而不是分别形成不同文字区块。
- 拼音和多音字结果以平台转写结果为准。Avenor 不附带或维护独立读音字典、拼音库或 Launcher 自定义字符优先级表。
- 分组依据同一套规范化完整名称排序形式，不只检查显示名称的第一个原始 Unicode 字符。
- 规范化 locale-aware 分组无法归入拉丁字母 A-Z 的条目统一进入 `#`，组内继续使用同一套完整名称比较器。Avenor 不单独规定数字、标点、Emoji 或其他文字在 `#` 内的人工优先级。
- 系统应用、下载应用、主应用与应用分身均参与同一套排序。
- 应用显示名称排序相同时，身份顺序为：主应用、应用分身、工作资料应用。
- 显示名称排序和身份类别都相同时，使用稳定的可启动应用条目身份作为最终 tie-breaker。刷新前后可观察顺序必须稳定；产品契约不规定具体实现字段或 API。
- 所有应用分组之后，Drawer 列表末尾固定包含一个标题为 `设置` 的独立分组。该标题是同一列表中的锚点，但不是应用分组，也不参与应用排序。
- 固定设置分组包含一条可点击条目，展示设置齿轮图标和名称 `设置`。只有点击该条目才进入 Settings。

## 字母索引

- Drawer 呈现可导航 Content 时，右侧索引固定可见。全屏 Loading 和 Error 状态不呈现任何列表锚点，因此隐藏整个索引，不采用部分显示。
- 索引包含 `#`、实际存在内容的 A–Z 分组，以及位于 Z 下方固定存在的 Settings 齿轮；空字母分组不显示。
- 索引文字采用 `11sp` 中等字重和固定 `20dp` 槽位。Settings 齿轮图形在完整的 `20dp` 索引槽位内采用 `11dp` 视觉尺寸；不得把槽位或索引触控范围缩小到图形边界。现有条目不会为了均分空余高度而拉伸。
- 最大索引模型包含 28 个槽位，即 `#`、A–Z 和 Settings。因此完整展示所需的最小可用高度为 `560dp`，按 `28 × 20dp` 计算；可用高度必须先排除状态栏、导航栏、屏幕开孔、Drawer padding 和系统手势 inset。
- 可用高度达到或超过 `560dp` 时，索引不滚动；低于 `560dp` 时，索引成为独立的纵向滚动区域，应用列表仍单独滚动。
- 初次按下有效索引项时，应用列表立即且无动画地跳转到该条目的锚点，并将锚点标题定位到可见列表顶部。该直达不等待抬手，并产生索引步进触觉反馈。
- 初次按下后，进入另一个有效索引项时，开始向该条目锚点平滑滚动。在同一索引槽位内移动不会改变列表位置。新选中的锚点会取消并替换尚未完成的平滑滚动目标；目标不得排队。
- 最终位置是最后选中的锚点位置。抬手或手势取消时，当前平滑滚动继续完成到该锚点；列表不得根据指针百分比计算位置、吸附到其他锚点或播放完成动画。
- 按住期间，放大气泡只展示当前字符；当前 token 为 Settings 时展示设置齿轮。气泡采用 `32sp` 中等字重和至少 `64dp × 64dp` 的区域，并在抬手或手势取消后立即消失。
- 字母索引持有触控期间，应用列表不独立消费该手势；索引移动只能通过上述离散锚点平滑滚动行为驱动列表。
- Settings 齿轮是索引锚点，不是打开 Settings 的控件。初次按下时立即跳转到 Drawer 列表末尾固定的设置分组；索引移动进入该 token 时平滑滚动到该分组，并像其他锚点变化一样产生索引步进触觉反馈。
- 该分组中的设置条目是 Drawer 内唯一打开 Settings 的控件。
- 同一进程内从 Settings 返回时保留 Drawer 列表位置。
- TalkBack 语义和无障碍专用的替代索引交互不在当前个人使用范围内。

## 应用清单变化与状态

- Drawer 展示期间，应用或分身新增、移除、启用、停用或更名时实时更新清单。
- 普通外部应用运行期间观察到的应用清单变化，应在返回 Home 时不呈现新的 Loading 状态的前提下完成协调。下次展示 Drawer 时使用已协调的清单，并遵循当前锚点和位置规则。
- 非当前普通、工作资料或克隆资料读取失败、但其他资料仍提供可用条目时，Drawer 将已有条目作为 Content 呈现，不阻断整个界面。失败资料中的条目可以缺失，且当前产品不要求提供部分读取失败提示。
- 资料局部失败不得导致 Avenor 崩溃、阻止已有条目启动，也不得被视为不可用条目已经永久移除的确认。没有留下任何可用清单的失败进入下文 Error 状态。
- 当前产品边界有意排除 Private Space 条目；这些条目不出现不属于应用清单失败。
- 普通实时更新后，当前锚点仍存在时，保留该锚点及锚点内的相对滚动位置。
- 当前锚点消失时，移动到排序中的下一个现存应用锚点，将其标题定位到可见列表顶部；后续滚动时标题不吸顶。
- 不存在后续应用锚点时，停留在应用列表底部，不自动移动到设置分组。设置锚点不是应用锚点，清单更新也不得打开 Settings。
- 清单更新不得自动启动应用，也不得打开应用操作面板或 Settings。

### 加载状态

- 尚无可用清单结果且正在读取时，应用区域显示进度指示器和本地化提示 `正在加载应用…`。
- 加载是进行中状态，不是空结果或错误；进度指示器不得与错误图标和重试操作同时展示。
- 在该状态的整个持续期间，应用列表、固定设置分组和 AlphabetIndex 均不展示。

### 空结果或读取失败

- 成功读取但没有任何可启动应用条目时，视为错误，不作为有效空 Drawer。
- 应用清单读取失败且没有留下任何可用的可启动条目时，使用同一错误状态。
- 应用区域隐藏进度指示器，显示非交互的 `40dp` 错误图标和本地化提示 `无法加载应用`，并提供独立的 `重试` 操作。
- 错误状态不再建议用户重启 Avenor。
- 显示该全屏错误期间，应用列表、固定设置分组和 AlphabetIndex 均保持不展示。
- 点击重试后清除可见错误状态，返回加载状态，并开始新一次应用清单读取。
- 用户停留在同一 Error 呈现期间，Activity 恢复、网络变化、软件包回调和其他普通生命周期事件不得自动重试或清除错误。离开 Drawer 后再次进入时，开始一次新的初始读取。
- 重试成功后显示应用列表；重试结果仍为空或读取失败时，重新进入同一错误状态。

## 验收意图

- 普通 Drawer 的透明顶部应用栏在内容滚动时保持固定；返回箭头通过正常向下过渡返回，中部和右侧空白区域不暴露不可用控件。
- 收藏多选必须以可见方式保持选择顺序，不启动或长按应用，不展示 Settings，并且只通过确认保存完整选择；所有取消路径都丢弃全部未确认条目。
- 从 Avenor 当前角色和最小权限边界内成功读取来源返回的每个可启动条目只出现一次。非当前资料局部读取失败时，其中的条目可以缺失，但不得阻断已有 Content。主应用、工作资料和克隆条目遵循适用的平台身份表现；需要 `ACCESS_HIDDEN_PROFILES` 的 Private Space 条目被有意排除。平台提供 badge 时，主应用与应用分身保持可辨识；Avenor 自有的备用区分方式不在当前范围内。
- 初次接触索引时立即落到目标锚点，并将其标题定位到可见列表顶部；之后每次进入新的有效 token 都平滑滚动到该 token 的锚点，且不排队滚动目标。
- 抬手或取消索引手势后，应用列表停留在最后选中的锚点，不保留任意指针百分比位置，也不吸附到其他位置；标题随后随列表正常滚动。
- 索引手势不会独立滚动列表，也不会触发应用条目操作。
- 清单实时更新后，已移除应用不能继续从失效界面启动。
- 输入不变时重复刷新，应用顺序和当前锚点内相对位置保持稳定。

# Home 交互规格

> 英文语义源：[home.md](home.md)。公共导航见 [navigation.zh-CN.md](../navigation.zh-CN.md)，双击锁屏见 [double-tap-lock.zh-CN.md](../features/double-tap-lock.zh-CN.md)，Home 精确视觉数值见 [Home 表现规范](../presentation/home.zh-CN.md)，公共视觉原则见 [design-foundations.zh-CN.md](../design-foundations.zh-CN.md)，完整空间草图见共享的[普通 Home](../wireframes/home.txt)与 [Home 编辑模式](../wireframes/home-edit-mode.txt)线框，阅读规则见[线框索引](../low-fidelity-wireframes.zh-CN.md)。

## 目的与结构

Home 是 Launcher 主界面。它是不可分页、不可折叠且不使用文件夹的固定界面。页面本身不滚动；只有已有内容的纵向收藏列表按照下述溢出规则独立滚动。内容按从上至下排列：

1. 基础信息区：时间在上，日期与星期在下。
2. 收藏列表区：最多包含两个地位相同的纵向收藏列表，容纳已接受并保存的可启动应用条目。
3. 次级收藏区：位于收藏列表区下方的条件性模块。

Home 采用内容驱动的纵向尺寸，不使用固定区域比例，整体始终不纵向滚动。Home 先解析平台 `safeDrawing` 边界和 Home 表现规范定义的内容矩形。基础信息区包裹必要内容和交互目标。收藏列表区与已有内容的次级收藏区自然高度能够放入剩余内容高度时，两者均使用自然高度，所有收藏列表都不纵向滚动。两者自然高度之和溢出时，次级收藏区保留自然高度，收藏列表区使用其上方剩余视口；只有溢出的收藏列表在该视口内部纵向滚动。次级收藏区使用完整 Home 内容宽度，没有内容时高度为零；每条收藏栏独立处理横向溢出，不移动其他 Home 区域。屏幕剩余空间只是未分配的透明 Home 空间，不是持续存在的产品区域。

收藏列表区最多支持两个持久化纵向列表。只有一个列表时使用完整收藏列表区宽度；两个列表在表现规范定义的间距后平均分配宽度。宽度根据可见列表数量计算，不采用固定百分比，因此不定义或授权第三个列表。两个列表产品地位相同，共享一个视口高度，并各自保留内容和滚动状态；只有自身内容超出视口时才滚动。“克制”和“无干扰”约束干扰和可避免的操作，不刻意限制收藏数量。

Home 精确 inset、间距、字体、条目几何、编辑控件，以及普通与编辑模式边界保持规则，只由 [Home 表现规范](../presentation/home.zh-CN.md)定义。

## 时间、日期与星期

- 时间显示在日期上方；所选系统字体支持时使用等宽数字特性，避免分钟变化导致时钟宽度跳动。
- 时间跟随系统 12/24 小时制，不显示秒。
- 日期与星期显示在时间下方，格式跟随当前语言区域，例如简体中文为 `2月1日 星期二`。应使用逻辑 `start` 对齐，而不是固定物理左偏移。
- 点击可见时间文字时，若系统时钟应用公开了可启动主界面，则进入该主界面。Avenor 不硬编码厂商时钟包名。若解析到的时钟应用未公开可启动主界面，则回退到其系统闹钟目标；若两个目标均不可用，则显示本地化失败反馈且不崩溃。
- 点击可见日期星期文字，通过隐式调用进入系统日历，不指定具体包名。
- 完整时间行和日期星期行目标遵循 Home 表现规范。

### 空白区域双击

- 基础信息模块在 Home 内容边界内保持完整宽度，并在当前文字和其他交互目标之外保留可用空白。该空白支持 [double-tap-lock.zh-CN.md](../features/double-tap-lock.zh-CN.md) 定义的可选双击锁屏能力。未来增加天气等信息时，也必须在模块中保留具有实际可操作性的空白部分。
- 时间和日期星期触控目标不属于该区域；两者已有的单击行为保持立即执行，不等待双击识别。
- 只有用户在 Android 系统设置中明确启用用途受限的 Avenor 无障碍服务后，该手势才生效。

## 收藏区域

- 新安装时收藏为空，显示简洁的空状态，引导用户前往 Drawer 添加应用。
- 每个收藏只属于一个直接访问目标：某个纵向收藏列表或某条收藏栏。收藏列表区是由纵向列表组成的横向序列，无论语言方向如何，均按物理位置从左到右排列。通过既有 Drawer 操作新增的收藏追加到当前最左侧列表；没有列表时，该操作以默认“中”尺寸创建一个列表。调整列表顺序会改变最左侧列表，因而也会改变后续 Drawer 新增的默认目标。新增收藏不会跳转到 Home，也不会进入编辑模式。
- 当前产品最多支持两个持久化纵向收藏列表。持久化列表必须至少包含一个收藏；因为取消收藏、卸载协调或已完成移动而失去最后一个条目时，立即删除该列表，剩余列表如存在则扩展至全部可用宽度。
- 产品不因列表视口已经铺满而拒绝新增；溢出内容扩展该列表的可滚动内容，并保持已有顺序。
- 同一个稳定可启动条目身份不得在任一列表内部、不同纵向列表之间或收藏栏之间重复保存或展示。
- 主应用、应用分身和工作资料可启动条目继续作为不同身份处理；它们可以独立归入收藏，包括分别归入不同收藏目标，并且不得仅按包名去重。
- 收藏展示尺寸是列表级属性。同一列表中的所有条目使用该列表已保存尺寸，不同列表可以保留不同尺寸值。所有新建或迁移列表初始使用“中”；编辑模式允许用户通过列表级尺寸控件，分别把每个持久化列表调整为“大／中／小”。
- 大、中、小条目的精确数值和名称处理由 [Home 表现规范](../presentation/home.zh-CN.md#纵向收藏列表)定义。
- 两个列表都不根据当前视口定义产品层面的槽位上限。可见列表使用共享的构图视口高度，并分别维护自己的内容长度和滚动位置。列表内容能够容纳时不滚动；超出共享视口后在自身内部纵向滚动，不改变其他列表的位置或滚动状态。
- 图标形状和 badge 完全采用平台提供的呈现，并在 Home、Drawer 及相关应用界面中保持一致。
- 点击条目后立即启动应用，普通点击不产生震动，并抑制短时间内的重复启动。
- 长按条目时产生长按触觉反馈，并打开 [app-action-sheet.zh-CN.md](app-action-sheet.zh-CN.md) 定义的应用操作面板。
- 收藏点击与长按参与 [navigation.zh-CN.md](../navigation.zh-CN.md) 定义的 Home 全域上滑仲裁。上滑取得手势所有权后，不得启动收藏、打开其操作面板或产生该收藏的长按反馈。
- 只有成功刷新应用清单，并确认应用已卸载、应用分身已删除或该可启动身份永久消失后，才自动删除对应收藏。
- 应用清单整体加载失败时，不得删除或隐藏任何已保存收藏。
- 应用仍存在但被停用时，保留其原有位置并展示为明确的禁用收藏。点击后不尝试正常启动，而是展示简短且已本地化的不可用 Toast；长按仍可用于适用的应用信息或管理操作。
- 出现临时启动失败时，保留收藏，展示简短且已本地化的错误 Toast，并刷新该条目状态。
- 后续成功刷新确认条目恢复可用时，在原位置恢复，不改变收藏顺序。

### 收藏持久化加载与失败

- 只有 Avenor 能够可靠解释完整的已存储收藏状态时，收藏持久化读取才算成功。无法读取或已损坏的结果不是空收藏列表，不得展示新安装时的正常空状态。
- 可读的已保存状态早于列表级尺寸时，保留每个有效收藏已有的列表成员关系和顺序，为每个非空迁移列表分配“中”尺寸，并省略空列表。迁移不得重复或静默丢弃有效收藏。
- 加载中、无法读取和完全为空的收藏状态，都是完整收藏构图的共享状态，只展示一次，不按列表重复展示。持久化空列表不得存在：列表失去最后一个条目时即删除，并重新计算剩余可见列表宽度。
- 初次读取或用户请求的重试进行期间，收藏区域显示进度指示器和本地化文案 `正在加载收藏…`。不得同时展示收藏条目、空状态引导、错误图标或重试操作。
- 无法可靠读取状态时，收藏区域隐藏进度指示器，展示共享的非交互状态图标、本地化文案 `无法加载收藏`，并提供独立的 `重试` 操作。
- 失败状态必须保留原始不可读数据，不得初始化、迁移、修复、清空、替换或以其他方式覆盖。进程重建和设备重启后不得把该失败重新解释为空列表。
- 失败或重试状态持续期间，所有添加收藏、取消收藏和编辑模式变更均为禁用状态。Home 时间日期、Home→Drawer 导航、Drawer 应用清单和应用启动继续可用。
- 选择重试后发起一次只读重新加载，将收藏区域切换为加载表现，并在本次尝试完成前禁用重复重试。重试不得写入、修复、迁移、清空或替换已存储收藏数据。
- 重试成功时，不执行额外写入，恢复准确可读的收藏状态及其顺序。可靠读取到空状态时，展示正常空状态引导并恢复收藏变更能力。
- 重试失败时，返回相同的持续失败表现，恢复重试操作，保留原始不可读数据，并继续禁用收藏变更。由于可见的收藏区域错误已经表达结果，不额外展示 Toast。用户可以再次重试。
- 新进程启动时执行一次正常初始读取。Avenor 不持续自动重试、轮询，也不以网络状态变化作为重试触发条件。任何其他安全读取触发条件均需技术验证，并且必须遵守相同的禁止写入边界。
- 如果检测到失败时收藏变更界面已经打开，则关闭该界面且不应用收藏变化。修复、导出、重置、备份和恢复行为需要后续产品决定与技术评估。

## 编辑模式

- 编辑模式可以从被选中收藏条目的启动器操作进入，也可以通过长按基础信息模块中符合条件的空白位置进入。符合条件的空白位置不包含时间、日期星期和任何其他交互目标。长按一经识别，即产生标准长按触觉反馈、进入编辑模式，并阻止同一触控序列继续触发双击锁屏或其他操作。操作面板入口仍使用“编辑”而不是“排序”命名，因为此模式同时支持顺序调整、列表归属调整和新增收藏。
- 编辑模式为每个纵向列表和收藏栏条目显示尾部拖动柄及物理左上角的取消收藏角标。各模块和收藏栏使用 [Home 表现规范](../presentation/home.zh-CN.md#编辑表现)定义的编辑表面。这些表面用于表达边界，不表示基础信息模块可以编辑。
- 每个持久化纵向列表在既有视口顶部获得表现规范定义的控制栏。物理从右到左依次为调整完整列表顺序、选择列表尺寸、删除完整列表。临时列表没有控制栏。只有一个持久化列表时，排序控件隐藏且不可交互，但其位置继续占位；存在两个列表时显示。这些物理位置在 RTL 语言环境下不镜像。
- 删除、尺寸和排序控件使用 Home 表现规范定义的视觉与紧凑目标例外。尺寸控件只包含当前本地化值。排序控件在活动拖动期间保持状态。普通删除列表和尺寸操作不产生触觉反馈。
- 控制栏不改变收藏列表区外部高度，也不移动相邻 Home 模块。它占用编辑模式视口顶部由表现规范定义的部分，应用在其下方滚动，且不得被覆盖。退出编辑模式后恢复完整应用视口并保留有意义的滚动位置。临时列表与相邻持久化列表顶部对齐，但可以把完整视口用于仅含新增入口的内容。
- 编辑模式保持每个列表已经选择的大、中、小条目表现。应用拖动柄保持在条目内部，不得增加条目高度或触发列表重新测量；准确图形和目标几何由 Home 表现规范定义。
- 每个应用条目的取消收藏控件提供本地化无障碍名称，位于物理左上角且不增加操作列，保留主要识别图形和平台 badge，并且不与尾部拖动柄重叠。准确紧凑视觉与目标几何由 Home 表现规范定义。
- 编辑模式禁用普通收藏启动和长按操作面板行为。点击应用的取消收藏角标时立即移除并持久化该收藏。所有应用移动、完整列表排序和完整收藏栏排序都只能从对应可见拖动柄开始，并且必须先识别平台标准长按阈值。长按成立时恰好产生一次平台标准 long-press 语义触觉反馈，并由该手势独占拖动；只有此后的移动才创建并移动预览。长按成立前松手不执行拖动；此前开始移动会取消候选，并在所属列表或收藏栏可滚动时继续作为普通滚动。该启动规则不适用于 Home–Drawer 导航、普通滚动或其他非编辑模式手势。应用拖动柄共享 Home 表现规范定义的资源和目标几何。
- 编辑模式移除成功后，Home 显示 Material Snackbar，文案为`已取消收藏`，右侧操作为`撤销`。Snackbar 使用平台长时长语义，并按适用的无障碍超时设置调整；它不阻断继续编辑 Home，显示期间只保存最近一次移除的临时快照。
- 点击`撤销`时恢复被移除的准确身份、目标、位置、已保存列表尺寸和受影响容器顺序。如果移除最后一个条目导致纵向列表或收藏栏被删除，撤销会在原位置重新创建该容器，并作为一个整体恢复其属性。撤销只提供普通按压反馈，不产生触觉反馈。
- 后续移除会替换当前 Snackbar，并永久丢弃前一次移除的撤销快照。Snackbar 消失、退出编辑模式、Android 系统 Home 操作、进程重建或离开 Avenor 时均丢弃快照，不保留撤销历史。撤销持久化失败时，以最后一次成功保存的收藏状态为准，并显示现有收藏更新失败反馈，不声称恢复成功。
- 如果活动撤销快照包含的任一身份在点击撤销前被成功添加到另一个收藏目标，则保留该次新收藏，并立即使完整撤销快照失效。Avenor 关闭已经失效的 Snackbar，不增加 Toast、Snackbar、Dialog，也不把该身份移回原目标。取消或失败的添加不会使撤销失效。
- 活动撤销快照需要重新创建一个因移除而消失的纵向收藏列表或收藏栏时，在撤销恢复、被替换、消失或因其他既有条件失效前，该已删除容器继续占用对应两个列表或五条收藏栏上限中的一个名额。Home 不提供会占用该保留名额的临时容器入口，向已有持久化目标新增仍然可用。因此撤销能够准确恢复原容器且不会突破任一上限；快照失效后立即释放该名额。
- 应用拖动柄使用独立跟手预览，保留抓取偏移，并可在整个 Home 安全内容区域内连续移动。持久化或临时纵向列表和收藏栏都是应用目标。整个手势期间预览保持来源表现；跨容器放置成功后，应用采用目标列表已保存尺寸或收藏栏表现。
- 源应用的原始布局槽位在整个拖动期间保持稳定并保留源几何。槽位可以保留不可交互表示，且不得同时存在两个可交互收藏。被拖动收藏不参与位置动画；目标变化或其他条目动画不得使预览自动平移、跳转、改变尺寸或回弹。
- 在同一个容器内，触控点进入另一应用有效主体时立即交换两个可见位置并持久化。一个容器是某个纵向收藏列表或某条收藏栏。同一次拖动继续经过其他有效主体时，可以继续交换并持久化。同容器间隙不接受插入，也不显示插入线。在无效区域松手时保留最后一次成功持久化的同容器顺序，不回退此前交换。
- 触控点进入另一应用容器时，目标类型互斥。已有应用主体显示交换高亮或边框，不显示插入线；第一项之前、条目之间、最后一项之后或空临时目标的有效边界显示插入线，不显示交换高亮。跨容器操作在松手前不改变可见归属；在当前有效目标上松手后，一次性执行并持久化交换或插入。插入从源容器移除应用，并保持目标原有条目的相对顺序。
- 例如左侧列表为 `[A, B, C]`、右侧列表为 `[D, E, F]` 时，把 `A` 放到 `E` 的主体后执行交换，结果为左侧 `[E, B, C]`、右侧 `[D, A, F]`。如果改为把 `A` 放到 `D` 与 `E` 之间的间隙，则执行插入，结果为左侧 `[B, C]`、右侧 `[D, A, E, F]`。
- 目标判断以手指触控点为准，不以预览中心或边缘为准。在交换主体和插入边界之间移动时切换反馈，不保存跨容器数据。横向或纵向边缘自动滚动期间，根据当前目标容器几何重新计算反馈，并继续以触控点为准。
- 应用级拖动在每个可滚动应用视口内部使用 `48dp` 自动滚动触发区：纵向列表为顶部和底部，收藏栏为左侧和右侧。在有效触发区内持续停留约 `120ms` 后，开始向该方向滚动。滚动速度随触控点接近边缘而连续增加；具体最低速度、最高速度和插值曲线由实现与设备体验校准。触控点离开触发区后立即停止，无需抬手。到达内容边界时停止，不循环、不回弹，也不增加触觉反馈或解释文案。
- 只有触控点当前所在的有效容器可以自动滚动。仍处于源容器时源容器可以滚动；进入另一纵向列表或收藏栏后，仅该目标容器沿自身轴向滚动。列表间隙、模块间隙、无效空白、纵向列表控制栏和收藏栏固定控制轨都会停止全部自动滚动。自动滚动只适用于应用级拖动，不适用于完整列表或完整收藏栏排序。
- 进入可用边缘触发区时，在稳定等待期间开始淡入 [Home 表现规范](../presentation/home.zh-CN.md#拖动与溢出反馈)定义的边缘提示；自动滚动生效后保持其最大表现。离开触发区、改变方向、取消拖动或对应方向不再可滚动时，旧提示快速淡出；新方向重新经历稳定等待和淡入。提示不包含箭头、文字、Ripple、无障碍节点或触觉反馈。插入与交换反馈位于提示上方，并在内容移动期间持续重新计算。
- 进入另一容器后在无效区域松手，应恢复应用最近一次成功持久化的容器与位置；如果同一手势此前已经完成同容器即时交换，则保留其最后一次成功持久化顺序。持久化失败时，为仍有效身份恢复最近一次成功保存的归属和顺序，保留更新的已确认应用清单协调结果，不声称完成，并显示现有收藏更新失败反馈。
- 系统 Back 和 Android 系统 Home 操作都可以退出编辑模式。如果活动拖动期间发生其中任一操作，应先取消未保存目标、移除预览和反馈、恢复最近一次成功持久化的可见状态，并使该手势后续 release 失效；已经持久化的同容器交换继续保留。随后退出并移除编辑表面和控件，不撤销已完成变化。Back 返回普通 Home；Android 系统 Home 操作也按照现有 Launcher 导航契约落到普通 Home。
- 编辑表面、可见拖动柄和可见新增控件共同表示当前处于编辑模式；当前不定义额外的 Home 标题、横幅、完成按钮或界面内退出操作。

### 选择纵向列表尺寸

- 点击中间尺寸控件时打开深色主题 Material 锚定单选菜单。位置根据控件当前实际屏幕坐标计算，不使用固定屏幕位置。菜单首选显示在控件下方，空间不足时翻转到上方，否则限制在安全内容内，不允许滚动、裁切或移动底层 Home 内容。准确位置偏移属于 Home 表现规范。
- 菜单按大、中、小顺序排列。每个条目使用不随 RTL 镜像的固定物理从左到右顺序：单选标记、内置 Android 默认通用应用图标、尺寸文字。不会读取失败的本地图标仅作装饰，不包含 badge 或身份，也不在运行时从收藏或 Android 读取。准确行高和预览尺寸属于 Home 表现规范。
- 单选标记、图标、文字和条目剩余空间共同组成一个选择目标和一个无障碍节点。只有完整条目显示受边界限制的菜单 Ripple；单选标记与预览图标均不可独立交互或聚焦。当前条目通过不只依赖颜色的方式表达选中。菜单使用平台 Material 深色表面、轻微圆角和默认 elevation，不增加自定义边框；宽度容纳最长本地化条目，三项保持一致。
- 尺寸控件的无障碍名称包含当前完整值，例如 `Favorite list size, Medium` 或`收藏列表尺寸，中`。点击当前条目只关闭菜单，不执行写入、反馈或布局工作。选择其他条目时立即保存列表级尺寸、关闭菜单，并执行一次普通重新布局，不使用缩放动画、触觉反馈、Toast 或 Snackbar。点击外部、按系统 Back 或再次点击尺寸控件都会关闭菜单且不改变值；Back 只关闭菜单，编辑模式保持。菜单打开期间，阻止底层列表滚动、应用拖动、整列拖动和其他 Home 编辑操作。
- 重新布局保持收藏列表区外部高度和列表宽度不变，不影响另一列表的尺寸、顺序或滚动位置。切换前最靠顶部的可见应用身份继续作为切换后的首个可见应用，并在有效时保持其相对应用视口顶部的偏移，否则限制到最近有效偏移。切换为更大尺寸后内容溢出时立即允许滚动；切换为更小尺寸后内容已经容纳时停止滚动，并修正到有效范围。持久化失败时恢复最近一次成功保存的尺寸及对应布局，并显示现有收藏更新失败反馈。

### 删除与调整纵向列表顺序

- 点击`删除收藏列表`时打开 Android 平台默认样式的 Dialog，而不是 BottomSheet。标题为`删除收藏列表？`，正文为`此列表中的所有应用都将从收藏中移除。`，左侧操作为`取消`，右侧破坏性操作为`删除`。Dialog 不列举应用名称或数量。展示期间阻止 Home 滚动、拖动和其他编辑操作；点击取消、按系统 Back 或点击 Dialog 外部均只关闭 Dialog，不产生修改。
- 确认`删除`后关闭 Dialog，删除并持久化完整列表，然后显示`已删除列表`和`撤销`。该操作沿用只保留最近一次移除的生命周期：撤销会原子恢复原物理位置、已保存列表尺寸、完整成员和应用顺序；后续移除或任何既有失效条件都会使该快照失效。删除左侧列表后，剩余列表成为 Drawer 默认新增目标；撤销会恢复此前顺序。删除最后一个列表时不创建空替代列表；仍有列表时，该列表立即扩展至完整收藏构图宽度。
- 完整列表拖动遵循共享的拖动柄长按启动规则，并且只能从可见列表级排序目标开始。长按成立前只显示不透明度按压态；松手不执行操作，移动则取消拖动候选且不创建预览。长按成立时产生一次平台标准 long-press 语义触觉反馈，并让拖动独占进入就绪状态；首次后续移动才创建并开始移动预览，不再滚动列表或启动应用级拖动。
- 完整列表使用源列表当前可见视口的冻结、不可交互静态布局预览。预览保留原宽度、可见高度、内容、滚动位置和抓取偏移，不包含视口外内容，也不暴露独立无障碍节点。源位置保留等宽、等高占位。该契约要求可观察的静态预览，不强制使用截图或某个具体 Compose 实现。
- 目标判断以手指触控点为准。进入另一个持久化列表主体时，显示完整列表目标高亮，立即交换两个物理左右位置、持久化新顺序，并产生一次短移动触觉反馈。列表间隙不插入，也不显示插入线；继续进入另一主体可以再次交换。在无效位置松手、按系统 Back 或触发 Android 系统 Home 操作时，移除预览和反馈，但保留最后一次成功持久化的交换；后两种操作随后按既有规则退出编辑模式。

### 编辑模式新增收藏

- 编辑模式在每个持久化纵向收藏列表的真实末尾显示一个在列表宽度内水平居中的新增控件，每条已有收藏栏也以一个新增控件收尾。该控件随所属列表或收藏栏滚动，不属于收藏或拖动目标，也不持久化。
- 新增控件是带前置文本`＋`的本地化纯文字操作，不使用独立图标资源或装饰控件。持久目标显示`＋ 添加应用`；临时目标以文案命名将创建的容器。完整本地化文案是可见操作和单一语义目标；辅助技术不必朗读装饰性加号。目标几何属于 Home 表现规范，且不得拉伸或重新测量收藏条目。
- 没有纵向收藏列表时，编辑模式显示一个占据完整已设置 padding 的收藏列表区宽度、且仅含新增控件的临时列表。只有一个持久化列表时，编辑模式让该列表与一个临时列表平均分配宽度，以预览双列表布局。确认至少一个应用后，临时列表以默认“中”尺寸创建；取消或退出编辑模式时不持久化。已有两个持久化列表时，不再显示临时列表入口。
- 收藏栏少于五条时，编辑模式还会在所有已有收藏栏之后显示一条临时空收藏栏，其中仅包含一个新增控件。普通 Home 永远不显示该临时收藏栏；已有五条持久化收藏栏时，不再显示临时收藏栏入口。
- 如果活动撤销快照保留了对应容器类型唯一剩余的可用名额，同样不显示临时纵向列表或临时收藏栏入口。
- 点击新增控件时记录其明确的目标列表或目标收藏栏，并以 [drawer.zh-CN.md](drawer.zh-CN.md) 定义的收藏多选模式打开 Drawer。Drawer 以程序触发的方式完成向上过渡；编辑模式仍禁用手势触发的 Home-to-Drawer 过渡。
- 已确认应用按显示的选择顺序追加到已记录目标。用户从临时列表或临时收藏栏确认至少一个应用时，才将该目标及其首批条目作为一个整体创建并持久化。取消、没有条目可确认或通过 Android 系统 Home 操作离开时，不创建空目标。
- 打开 Drawer 收藏多选时，记录当前编辑上下文中每个 Home 纵向列表和收藏栏的滚动位置。通过取消、系统 Back 或有效下滑退出普通取消后，Drawer 完成反向过渡，并把所有 Home 容器准确恢复到此前位置，不进行自动滚动；Drawer 自身滚动不得改变这些 Home 位置。若期间可靠应用清单协调使准确偏移不再有效，且此前最靠顶部的可见身份仍存在，则保留该身份及其偏移，否则限制到最近有效位置。确认成功后，所有非目标容器沿用同一恢复规则。若仍然有效的首个新增身份没有完整显示，仅目标容器执行使该条目完整进入视口所需的最小纵向或横向滚动，不强制对齐起点；该条目已经完整可见时不滚动。刚持久化的临时容器从内容起点展示，自然显示首个条目。多个新增条目继续保持选择顺序，但只保证首个仍有效新增条目完整可见；返回时全部新增身份均已失效则不滚动任何容器。该显示过程不增加高亮、Snackbar 或触觉反馈。Android 系统 Home 操作会取消尚未提交的选择、退出编辑模式并落到普通 Home，不保留本次临时编辑视口；已经开始的原子保存改为遵循 Drawer 保存契约，不被取消。

- 从收藏拖动柄开始的拖动负责移动条目；在收藏列表内其他位置开始的纵向拖动，在该列表存在溢出时滚动该列表；在收藏栏其他位置开始的横向拖动，在收藏栏存在溢出时滚动该收藏栏。编辑模式不换页，也不展开折叠列表。
- 同容器应用交换在交换发生时保存；在另一容器的有效目标上松手时，按照上述互斥目标规则完成并保存一次跨容器交换或插入。
- 编辑模式禁用 Home→Drawer 拖动；条目拖动、列表滚动和边缘自动滚动在编辑模式结束前保持手势所有权。

## 次级收藏区

- 次级收藏区是位于收藏列表区下方的条件性 Home 模块，使用表现规范定义的间距。
- 次级收藏区使用完整 Home 内容宽度，不参与纵向收藏列表的宽度分配。
- 没有内容时，次级收藏区高度为零，不保留空白占位。
- Home 本身不因次级收藏区而纵向滚动。该区域由最多五条纵向堆叠的横向收藏栏组成；当前产品将五条写死为上限，未来由用户配置收藏栏数量的 Settings 能力不在当前契约内。
- 每条收藏栏包含有限且由用户定义的可启动应用条目。条目能够容纳时收藏栏保持静止，超出可见宽度时横向滚动，并且不循环滚动。容器、条目和间距数值属于 Home 表现规范。
- 每条收藏栏的横向滚动位置遵循 [navigation.zh-CN.md](../navigation.zh-CN.md) 的共享恢复生命周期：同一进程内普通 Avenor 界面往返、外部应用返回、退出编辑模式和 Android 系统 Home 操作后保留有意义的位置；Drawer 收藏多选沿用已记录位置恢复和仅目标最小显示规则；进程重建后每条收藏栏回到内容起点。期间内容变化使准确位置失效时，尽可能保留此前沿收藏栏轴向首个可见身份及其偏移，否则限制到最近有效位置。
- 每个次级收藏条目使用 [Home 表现规范](../presentation/home.zh-CN.md#收藏栏)定义的固定收藏栏表现和按内容测量宽度。所有语言按实际渲染宽度测量，不按字符数量判断。该表现没有用户尺寸控件；大、中、小菜单只适用于纵向收藏列表。
- 条目从每条收藏栏起始侧排列。名称较短时条目自然收缩；剩余空间保持未使用，不重新均分。普通与编辑模式保持已计算宽度；编辑控件可以使名称更早省略，但不得扩宽条目。
- 编辑模式中，已有内容的次级收藏区与每条收藏栏使用 Home 表现规范定义的编辑处理。收藏栏可以滚动时，每个仍有更多内容的方向显示短距离条件式渐隐，到达边界后消失；边缘局部条目可以继续作为主要溢出提示。不溢出时不显示渐隐，也不滚动。
- 编辑模式中，每条收藏栏分为逻辑 start 删除轨、中部横向滚动应用视口和逻辑 end 排序轨。两个轨道都是完整交互目标，在应用滚动时保持固定，并使用 Home 表现规范定义的几何。只有一条持久化收藏栏时，end 排序表现和交互隐藏，但轨道继续占位。临时收藏栏不显示收藏栏级控件。至少有两条持久化收藏栏时全部显示排序目标；减少到一条时隐藏且不改变轨道几何。
- start 控件名称为`删除收藏栏`。点击后复用删除完整列表的 Android 平台默认确认机制。Dialog 标题为`删除收藏栏？`，正文为`此收藏栏中的所有应用都将从收藏中移除。`，左侧操作为`取消`，右侧破坏性操作为`删除`。Dialog 不列举应用或数量，并阻止底层 Home 编辑操作。点击取消、按系统 Back 或点击外部只关闭而不修改。确认后关闭 Dialog，删除并持久化完整收藏栏，然后显示`已删除收藏栏`和`撤销`。撤销遵循只保留最近一次操作的 Snackbar 生命周期，并整体恢复收藏栏位置、完整成员和应用顺序；不要求恢复此前横向滚动位置。
- 可见 end 侧收藏栏拖动柄遵循共享长按启动规则。识别前的横向移动取消候选并继续普通收藏栏滚动；识别后拖动会纵向调整收藏栏顺序。不透明、不可交互的静态布局预览冻结完整可见收藏栏，包括固定轨道、可见完整或局部条目、边界和适用渐隐。它保留原几何、滚动位置、内容和抓取偏移；不渲染视口外内容，也不能滚动、接收输入或暴露无障碍节点。源位置保留等尺寸占位。该预览不强制使用截图或具体 Compose 实现。
- 排序目标判断以手指触控点为准。进入另一持久化收藏栏主体时，高亮完整目标，立即交换两条收藏栏、持久化顺序并产生一次短移动触觉反馈；收藏栏间隙不插入，也不显示插入线。继续进入其他主体可以再次交换。在无效位置松手、按系统 Back 或触发 Android 系统 Home 操作时，移除预览和反馈，但保留最后一次成功持久化的收藏栏顺序；后两种操作随后按既有规则退出编辑模式。应用拖动柄目标与固定收藏栏控件彼此独立且不得重叠。
- 收藏栏条目背景、边界、圆角和按压数值属于 Home 表现规范。
- 次级收藏区不按产品预设类型区分收藏栏或条目；内容完全由用户定义，并由与当前收藏条目一致的可启动应用条目组成。当前收藏栏不显示标题，不预留标题行或高度，也不提供命名或重命名操作。未来主题设置中的“是否显示标题”属于当前契约之外的可叠加能力。
- 次级收藏遵循与纵向收藏列表相同的唯一归属规则。把某个身份归入收藏栏是改变该身份唯一的直接访问目标，而不是创建第二份收藏副本。
- 次级收藏通过上述编辑模式收藏栏新增控件添加。已经归入任一收藏目标的身份不可再次选择。已有身份可以按照上述全局同容器与跨容器拖动契约，在收藏栏和纵向列表之间移动或交换。
- 点击次级收藏条目后立即启动对应应用。长按条目时产生长按触觉反馈，并打开 [app-action-sheet.zh-CN.md](app-action-sheet.zh-CN.md) 定义的应用操作面板。
- 每条收藏栏都有明确的首个和末个应用条目，之后是仅在编辑模式显示的新增控件。从临时收藏栏确认应用会创建一条新收藏栏；收藏栏因移除单个应用收藏、移动或应用清单协调而失去最后一个应用条目时立即删除，该自动空容器清理不显示删除完整收藏栏的确认 Dialog。收藏栏命名仍不在当前契约内。
- 可见模块下方尚未分配的透明空间不是次级收藏区。

### 编辑模式期间的应用清单变化

任何会结束编辑模式的应用清单事件，也会取消正在进行的拖动、移除跟手预览和目标反馈，并且不提交尚未完成的移动或交换。

| 清单事件 | 当前行为 |
| --- | --- |
| 安装新应用 | 保持编辑模式；收藏不受影响 |
| 移除未收藏应用 | 保持编辑模式；收藏不受影响 |
| 收藏应用名称变化 | 原位置更新名称，保持编辑模式 |
| 收藏应用图标或平台 badge 变化 | 原位置更新，保持编辑模式 |
| 收藏应用被卸载 | 结束编辑模式、删除该收藏、保留此前已保存移动，并提示用户 |
| 已收藏应用分身被删除 | 结束编辑模式、删除该分身收藏、保留此前已保存移动，并提示用户 |
| 收藏应用被停用 | 结束编辑模式、在原保存位置保留为禁用收藏、保留此前已保存移动，并提示用户 |
| 收藏身份暂时无法确认 | 结束编辑模式、保留该条目和顺序等待刷新，并提示用户 |
| 完整应用清单加载失败 | 结束编辑模式、保留所有收藏及已保存顺序，并提示用户 |
| 收藏数量降低到两个以下，且没有其他应用清单规则要求退出 | 保持编辑模式，包括零收藏状态，使新增控件继续可用 |

- 已确认收藏发生变化时，统一使用本地化提示：`收藏应用已发生变化，编辑模式已结束`。
- 应用清单或身份刷新失败时，统一使用本地化提示：`暂时无法更新应用状态，编辑模式已结束`。
- 上述两类消息均使用短 Toast 展示。

## 验收意图

- 一个纵向收藏列表使用完整 Home 收藏列表区宽度；两个列表在表现规范定义的间距后平均分配。每个列表只在自身内容超出共享视口时滚动；失去最后一个条目时立即删除并重新计算剩余宽度。收藏栏失去最后一个应用条目时同样自动删除。
- 次级收藏区仅在有内容时显示，使用完整 Home 内容宽度，并按 Home 表现规范包含最多五条横向收藏栏。每条包含用户定义的可启动应用条目，仅在内容溢出时滚动，且到达末项后不循环回首项。点击条目启动应用；长按打开应用操作面板。
- 每个已保存的可启动条目身份在所有纵向收藏列表和收藏栏中最多出现一次。即使属于同一包族，主应用、应用分身和工作资料条目仍是可以独立归属的身份。
- 加载中、无法读取和完全为空的收藏状态在完整收藏构图中只展示一次；持久化空列表不得存在。
- 编辑模式之外，Home→Drawer 上滑在收藏区域按照滚动边界交接规则可用，并且可以从其他所有由 Avenor 管理的 Home 元素起始；不得同时产生元素的点击或长按操作。
- 平台提供 badge 时，主应用与应用分身保持可辨识；Avenor 自有的备用区分方式不在当前范围内。
- 同一进程内返回 Home 时，保留每个纵向收藏列表和收藏栏有意义的滚动状态；进程重建遵循 [navigation.zh-CN.md](../navigation.zh-CN.md)。
- 不可读收藏状态必须与有效空列表保持可区分，不能通过收藏操作覆盖，并且能够通过成功的只读重试恢复，同时不阻断独立的应用发现与启动路径。

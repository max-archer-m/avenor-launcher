# Home 交互规格

> 英文语义源：[home.md](home.md)。公共导航见 [navigation.zh-CN.md](../navigation.zh-CN.md)，双击锁屏见 [double-tap-lock.zh-CN.md](../features/double-tap-lock.zh-CN.md)，公共视觉规则见 [design-foundations.zh-CN.md](../design-foundations.zh-CN.md)，完整空间草图见共享的[普通 Home](../wireframes/home.txt)与 [Home 编辑模式](../wireframes/home-edit-mode.txt)线框，阅读规则见[线框索引](../low-fidelity-wireframes.zh-CN.md)。

## 目的与结构

Home 是 Launcher 主界面。它是不可分页、不可折叠且不使用文件夹的固定界面。页面本身不滚动；只有主收藏与伴收藏区域按照下述溢出规则独立滚动。内容按从上至下排列：

1. 基础信息区：时间在上，日期与星期在下。
2. 中部收藏构图：由主收藏与伴收藏组成，包含所有已接受并保存的可启动应用条目。
3. 底部次级功能区：后续由用户收藏产生的条件性能力；当前没有内容，因此不占空间。

Home 采用内容驱动的纵向尺寸，不使用固定区域比例。基础信息区包裹其必要内容和交互目标；中部收藏构图随内容增长，但不得超过剩余的安全可用高度，超出后仅在对应收藏分组内部滚动，Home 整体始终不可滚动。底部次级功能区在没有用户创建的收藏内容时高度为零。屏幕剩余空间只是未分配的透明 Home 空间，不是持续存在的产品区域。

中部收藏构图内，主收藏区约占左侧 55% 的可用横向空间，伴收藏区约占右侧 45%。实现时先从收藏构图总宽度中扣除固定的左侧 `8dp` padding、右侧 `8dp` padding 和两组之间的 `16dp` 间距，再将剩余宽度按 55:45 分配。布局取整可以产生最小的不可避免像素误差，但不得形成额外可见空隙或重叠。这是构图层级，不是用户可调节的分栏线。“克制”和“无干扰”不要求刻意限制收藏应用数量，而是约束干扰和可避免的操作。两组共享一个收藏构图视口高度，但保持独立的纵向滚动位置。视口高度取两组内容需求中较大的一个，但不得超过剩余安全可用高度；内容较少的一组保留未使用空间，不拉伸条目，也不将空间借给另一组。

Home 内容采用 `16dp` 横向与纵向容器 padding。相邻且可见的 Home 区域之间使用 `16dp` 间距。这些数值是 Home 可用边界内的内部布局距离，不是外部 margin。

## 时间、日期与星期

- 时间左对齐并位于日期上方，采用 `57sp` 字号、`64sp` 行高和粗体。所选系统字体支持时使用等宽数字特性，避免分钟变化导致时钟宽度跳动。
- 时间跟随系统 12/24 小时制，不显示秒。
- 日期与星期显示在时间下方，相对时间文字使用 `8dp` 的 start 内缩，采用 `16sp` 字号、`24sp` 行高和正常字重，格式跟随当前语言区域，例如简体中文为 `2月1日 星期二`。该内缩只影响可见文字；完整的日期星期行仍保持 `48dp` 可聚焦触控目标。应使用逻辑 `start` 对齐，而不是固定物理左偏移。
- 点击可见时间文字时，若系统时钟应用公开了可启动主界面，则进入该主界面。Avenor 不硬编码厂商时钟包名。若解析到的时钟应用未公开可启动主界面，则回退到其系统闹钟目标；若两个目标均不可用，则显示本地化失败反馈且不崩溃。
- 点击可见日期星期文字，通过隐式调用进入系统日历，不指定具体包名。
- 时间所在行高度至少为 `64dp`，不在其实际行区域之外另行扩大触控范围。
- 日期星期行高度为 `48dp`，文字垂直居中；完整行即为其可聚焦触控目标。

### 空白区域双击

- 基础信息模块在 Home 内容边界内保持完整宽度，并在当前文字和其他交互目标之外保留可用空白。该空白支持 [double-tap-lock.zh-CN.md](../features/double-tap-lock.zh-CN.md) 定义的可选双击锁屏能力。未来增加天气等信息时，也必须在模块中保留具有实际可操作性的空白部分。
- 时间和日期星期触控目标不属于该区域；两者已有的单击行为保持立即执行，不等待双击识别。
- 只有用户在 Android 系统设置中明确启用用途受限的 Avenor 无障碍服务后，该手势才生效。

## 收藏区域

- 新安装时收藏为空，显示简洁的空状态，引导用户前往 Drawer 添加应用。
- 每个收藏只属于两个直接访问分组中的一个：主收藏或伴收藏。从 Drawer 新增的收藏默认归入主收藏，之后可以通过 Home 编辑模式在两组之间移动；新增收藏不会跳转到 Home，也不会进入编辑模式。
- 主收藏表示作者相对最高频的直接访问应用，占约 55% 的区域。
- 伴收藏是相对主收藏使用频率较低的直接访问应用，占约 45% 的区域。“伴收藏”不表示隐藏、禁用、不可用或可有可无；两组具有相同的启动和编辑可用性。
- 从 Drawer 新增的收藏追加到主收藏。产品不因主收藏视口已经铺满而拒绝新增；溢出内容扩展主收藏的可滚动内容，并保持已有顺序。Avenor 不自动把条目放入伴收藏。
- 同一个可启动应用条目不能重复收藏。主应用与应用分身是不同条目，可以分别收藏。
- 主收藏与伴收藏必须在视觉上可以区分，但不能退化为两种普通列表密度。每个条目四周均使用 `8dp` 内部 padding。主收藏使用 `40dp × 40dp` 应用图标和默认 `56dp` 高的交互目标；伴收藏使用 `32dp × 32dp` 应用图标和默认 `48dp` 高的交互目标。图标与名称之间使用 `16dp` 横向间距，与 Drawer 应用条目一致。共享 padding 的纵向部分形成这两个默认高度，不为了扩大默认高度而额外叠加行 padding。
- 图标与应用名称之间使用 `16dp` 横向间距。主收藏名称采用 `16sp` 字号、`24sp` 行高和正常字重；伴收藏名称采用 `14sp` 字号、`20sp` 行高和正常字重。两者均跟随系统字体缩放、保持单行、无法完整显示时使用末尾省略号，并且不使用跑马灯。
- 产品不根据当前视口为任一分组规定槽位上限。两组使用共享的收藏构图视口高度，同时保持各自独立的内容范围和滚动位置：内容能够完整容纳时，该组不可滚动；内容超出共享视口时，该组独立纵向滚动，不改变另一组的位置或滚动状态。两组不得借用彼此的可见空间；收藏较少时保留未使用空间，不放大图标或间距。
- 图标形状和 badge 完全采用平台提供的呈现，并在 Home、Drawer 及相关应用界面中保持一致。
- 点击条目后立即启动应用，普通点击不产生震动，并抑制短时间内的重复启动。
- 长按条目时产生长按触觉反馈，并打开 [app-action-sheet.zh-CN.md](app-action-sheet.zh-CN.md) 定义的应用操作面板。
- 收藏点击与长按参与 [navigation.zh-CN.md](../navigation.zh-CN.md) 定义的 Home 全域上滑仲裁。上滑取得手势所有权后，不得启动收藏、打开其操作面板或产生该收藏的长按反馈。
- 只有成功刷新应用清单，并确认应用已卸载、应用分身已删除或该可启动身份永久消失后，才自动删除对应收藏。
- 应用清单整体加载失败时，不得删除或隐藏任何已保存收藏。
- 应用仍存在但被停用时，保留其原有位置并展示为明确的禁用收藏。点击后不尝试正常启动，而是展示简短且已本地化的不可用 Toast；长按仍可用于适用的应用信息或管理操作。
- 出现临时启动失败时，保留收藏，展示简短且已本地化的错误 Toast，并刷新该条目状态。
- 后续成功刷新确认条目恢复可用时，在原位置恢复，不改变收藏顺序。

### 收藏持久化加载与失败

- 只有 Avenor 能够可靠解释完整的已存储收藏状态时，收藏持久化读取才算成功。无法读取或已损坏的结果不是空收藏列表，不得展示新安装时的正常空状态。
- 加载中、无法读取和完全为空的收藏状态，都是完整收藏构图的共享状态：横跨主收藏与伴收藏区域，并只展示一次，不在两组中重复展示。可靠读取的非空状态中某一组没有条目时，不触发共享空状态；该组保留自己的构图区域，不拉伸条目，也不创建固定空槽。
- 初次读取或用户请求的重试进行期间，收藏区域显示进度指示器和本地化文案 `正在加载收藏…`。不得同时展示收藏条目、空状态引导、错误图标或重试操作。
- 无法可靠读取状态时，收藏区域隐藏进度指示器，展示非交互的 `40dp` 错误图标、本地化文案 `无法加载收藏`，并提供独立的 `重试` 操作。
- 失败状态必须保留原始不可读数据，不得初始化、迁移、修复、清空、替换或以其他方式覆盖。进程重建和设备重启后不得把该失败重新解释为空列表。
- 失败或重试状态持续期间，所有添加收藏、取消收藏和编辑模式变更均为禁用状态。Home 时间日期、Home→Drawer 导航、Drawer 应用清单和应用启动继续可用。
- 选择重试后发起一次只读重新加载，将收藏区域切换为加载表现，并在本次尝试完成前禁用重复重试。重试不得写入、修复、迁移、清空或替换已存储收藏数据。
- 重试成功时，不执行额外写入，恢复准确可读的收藏状态及其顺序。可靠读取到空状态时，展示正常空状态引导并恢复收藏变更能力。
- 重试失败时，返回相同的持续失败表现，恢复重试操作，保留原始不可读数据，并继续禁用收藏变更。由于可见的收藏区域错误已经表达结果，不额外展示 Toast。用户可以再次重试。
- 新进程启动时执行一次正常初始读取。Avenor 不持续自动重试、轮询，也不以网络状态变化作为重试触发条件。任何其他安全读取触发条件均需技术验证，并且必须遵守相同的禁止写入边界。
- 如果检测到失败时收藏变更界面已经打开，则关闭该界面且不应用收藏变化。修复、导出、重置、备份和恢复行为需要后续产品决定与技术评估。

## 编辑模式

- 编辑模式从被选中收藏条目的启动器操作进入；只要能够为某个收藏打开该操作面板，编辑操作就可用。该操作使用“编辑”而不是“排序”命名，因为此模式同时支持顺序调整和分组归属调整。
- 编辑模式为每个收藏显示拖动柄。每个可见的 Home 模块都使用 [design-foundations.zh-CN.md](../design-foundations.zh-CN.md) 定义的淡灰色、轻微透明、小圆角编辑表面。当前产品中即基础信息模块和收藏构图模块；高度为零的底部次级功能区没有编辑表面。这些表面用于表达模块边界，不表示基础信息模块可以编辑。
- 编辑模式保持普通模式的收藏条目高度：主收藏条目仍为 `56dp` 高，伴收藏条目仍为 `48dp` 高。两组使用相同的 `24dp` 拖动柄图形。每个拖动柄热区宽度为 `24dp` 图形加左右各 `12dp` padding，即总宽度 `48dp`；热区高度跟随当前条目的完整高度（主收藏 `56dp`、伴收藏 `48dp`）。图形右侧不额外设置 margin，视觉间距来自条目已有的 padding。拖动柄包含在这些行内，不得增加行高，也不得使任一分组列表拉伸、压缩或重新测量。
- 拖动柄拖动使用独立的跟手预览。预览保留抓取偏移，并可在整个 Home 安全内容区域内连续移动，包括两组及其间距。只有主收藏和伴收藏的有效区域接受放置；其他 Home 区域允许预览经过但不接受放置。被拖动收藏不参与列表位置动画，目标变化或其他条目动画不得使预览自动平移、跳转或回弹。
- 源收藏的原始布局槽位在整个拖动期间保持稳定并保留源行高度，因此列表不会因临时移除源条目而收缩，共享视口不会改变，其他收藏也不会整体跳动。尚未选中交换目标时，该槽位可以保留源收藏的不可交互表示；组内交换目标移动到此处后，由目标覆盖或替代该不可交互表示。槽位中不得同时存在两个可交互收藏。组内交换可以在拖动期间实时更新可见列表位置；跨组交换和插入只显示目标反馈，松手前不改变两组可见列表。已保存状态只在当前有效操作松手时最终确定。
- 当触控点仍在源组内时，只支持交换。触控点进入其他收藏的有效主体区域后，该收藏成为交换目标；拖动期间目标收藏立即与源收藏交换位置，独立预览仍由手指控制且不参与目标动画。触控点进入另一个有效主体后，当前可见交换更新为新的目标。同组间隙不显示插入线，也不接受插入。触控点停留在被拖动收藏自身、源位置或无效区域时，不产生新的交换。
- 当触控点进入另一组时，目标类型互斥。已有收藏主体表示跨组交换：目标显示交换高亮或边框且不显示插入线，但拖动期间不改变两组的可见列表位置或分组归属。有效间隙表示跨组插入：插入线标记目标边界，不显示交换边框，且松手前不改变两组内容。松手后才一次性执行当前跨组交换或插入；插入会从源组移除被拖动收藏，并按该边界插入目标组，同时保持目标组原有收藏的相对顺序。第一项之前、条目之间、最后一项之后以及空目标组都属于有效插入目标。
- 例如主收藏为 `[A, B, C]`、伴收藏为 `[D, E, F]` 时，把 `A` 放到 `E` 的主体后执行交换，结果为主收藏 `[E, B, C]`、伴收藏 `[D, A, F]`。如果改为把 `A` 放到 `D` 与 `E` 之间的间隙，则执行插入，结果为主收藏 `[B, C]`、伴收藏 `[D, A, E, F]`。
- 目标判断以手指触控点为准，不以预览中心或边缘为准。预览可以在视觉上覆盖目标，但不能改变目标类型。从交换主体移动到插入间隙时，交换边框切换为插入线；反向移动时，插入线切换为交换反馈。目标切换不修改已保存数据。边缘自动滚动期间，根据当前目标组几何位置重新计算反馈并继续以触控点为准；滚动或组切换不得造成无法解释的目标跳变。
- 组内交换在触控点进入有效收藏主体时实时更新可见位置；跨组交换和插入只显示目标反馈，拖动期间不改变两组可见列表。当前操作在有效目标上松手后一次性执行并立即保存。无效区域松手时恢复原始分组和位置，不改变已保存状态。被拖动预览保持独立；组内交换过渡可以动画目标收藏，但跨组反馈不得移动预览或任一列表。如果持久化失败，应为身份仍然有效的收藏恢复最近一次成功保存的分组归属和顺序，然后保留时间上更新的已确认应用清单协调结果。失败恢复不得重新加入后续应用清单事件已确认移除或失效的应用、分身或可启动身份。不得将该操作表现为已完成，并展示现有的收藏更新失败反馈。
- 系统 Back 是当前唯一退出编辑模式的渠道。如果活动拖动期间发生 Back，应先取消该拖动、移除跟手预览和目标反馈、恢复最近一次已保存的可见分组与顺序，并使该手势后续的 release 失效，不能触发保存。随后退出并移除编辑表面和拖动柄，但不撤销 Back 之前已完成的移动。
- 编辑表面和可见拖动柄共同表示当前处于编辑模式；当前不定义额外标题、横幅、完成按钮或退出操作。

- 从收藏拖动柄开始的拖动负责移动条目；在收藏分组内其他位置开始的纵向拖动，在该组存在溢出时滚动该组。编辑模式不换页，也不展开折叠分组。
- 收藏松手时，如果当前目标有效，则完成当前组内交换、跨组交换或跨组插入并立即保存；跨组松手遵循上述互斥目标、预览、无效放置和保存规则。
- 编辑模式禁用 Home→Drawer 拖动；条目拖动、分组滚动和边缘自动滚动在编辑模式结束前保持手势所有权。

## 底部次级功能区

- 底部次级功能区是后续收藏能力的产品定义边界，不是持续存在的空容器。
- 只有用户创建了适用的收藏内容时，它才存在并占据高度。当前产品尚未定义此类内容或创建行为，因此其当前高度为零。
- 可见模块下方尚未分配的透明空间不是底部次级功能区，不获得任何模块行为或编辑模式表面。
- 该区域出现前，其内容、选择、滚动、织带、分页、尺寸和创建行为都需要新的作者决定，并同步更新适用的 Home 与导航契约。

### 编辑模式期间的应用清单变化

任何会结束编辑模式的应用清单事件，也会取消正在进行的拖动、移除跟手预览和目标反馈，并且不提交尚未完成的移动或交换。

| 清单事件 | 当前行为 |
| --- | --- |
| 安装新应用 | 保持编辑模式；收藏不受影响 |
| 移除未收藏应用 | 保持编辑模式；收藏不受影响 |
| 收藏应用名称变化 | 原位置更新名称，保持编辑模式 |
| 收藏应用图标或平台 badge 变化 | 原位置更新，保持编辑模式 |
| 收藏应用被卸载 | 结束编辑模式、删除该收藏、保留此前已保存移动，并提示用户 |
| 已收藏应用分身被删除 | 结束编辑模式、删除该分身收藏、保留此前已保存移动，并提示用户 |
| 收藏应用被停用 | 结束编辑模式、在原保存位置保留为禁用收藏、保留此前已保存移动，并提示用户 |
| 收藏身份暂时无法确认 | 结束编辑模式、保留该条目和顺序等待刷新，并提示用户 |
| 完整应用清单加载失败 | 结束编辑模式、保留所有收藏及已保存顺序，并提示用户 |
| 收藏数量降低到两个以下 | 仍有至少一个收藏时保持编辑模式；没有收藏时退出 |

- 已确认收藏发生变化时，统一使用本地化提示：`收藏应用已发生变化，编辑模式已结束`。
- 应用清单或身份刷新失败时，统一使用本地化提示：`暂时无法更新应用状态，编辑模式已结束`。
- 上述两类消息均使用短 Toast 展示。

## 验收意图

- 空状态和已有收藏状态保持相同的固定 Home 结构。主收藏与伴收藏共同形成一个中部构图；扣除收藏构图 padding 与组间间距后，剩余宽度大约遵循 55:45。两组共享收藏构图视口高度，但分组内容能够容纳时各自保持静止，超出时各自独立滚动。
- 加载中、无法读取和完全为空的收藏状态在完整收藏构图中只展示一次；单独一组为空时，不替换另一组已有的可读内容，也不触发共享空状态。
- 编辑模式之外，Home→Drawer 上滑在收藏区域按照滚动边界交接规则可用，并且可以从其他所有由 Avenor 管理的 Home 元素起始；不得同时产生元素的点击或长按操作。
- 平台提供 badge 时，主应用与应用分身保持可辨识；Avenor 自有的备用区分方式不在当前范围内。
- 同一进程内返回 Home 时保留有意义的列表状态；进程重建遵循 [navigation.zh-CN.md](../navigation.zh-CN.md)。
- 不可读收藏状态必须与有效空列表保持可区分，不能通过收藏操作覆盖，并且能够通过成功的只读重试恢复，同时不阻断独立的应用发现与启动路径。

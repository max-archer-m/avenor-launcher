# Home 交互规格

> 英文语义源：[home.md](home.md)。公共导航见 [navigation.zh-CN.md](../navigation.zh-CN.md)，双击锁屏见 [double-tap-lock.zh-CN.md](../features/double-tap-lock.zh-CN.md)，公共视觉规则见 [design-foundations.zh-CN.md](../design-foundations.zh-CN.md)，完整空间草图见共享的[普通 Home](../wireframes/home.txt)与 [Home 编辑模式](../wireframes/home-edit-mode.txt)线框，阅读规则见[线框索引](../low-fidelity-wireframes.zh-CN.md)。

## 目的与结构

Home 是 Launcher 主界面。它是不可分页、不可折叠且不使用文件夹的固定界面。页面本身不滚动；只有已有内容的纵向收藏列表按照下述溢出规则独立滚动。内容按从上至下排列：

1. 基础信息区：时间在上，日期与星期在下。
2. 收藏列表区：最多包含两个地位相同的纵向收藏列表，容纳已接受并保存的可启动应用条目。
3. 次级收藏区：位于收藏列表区下方的条件性模块。

Home 采用内容驱动的纵向尺寸，不使用固定区域比例，整体始终不纵向滚动。基础信息区包裹必要内容和交互目标。收藏列表区与已有内容的次级收藏区在包含 `16dp` 间距后的自然高度能够放入剩余安全高度时，两者均使用自然高度，所有收藏列表都不纵向滚动。两者自然高度之和超出该边界时，次级收藏区保留织带形成的自然高度，收藏列表区使用其上方剩余的可见视口；只有溢出的收藏列表在该视口内部纵向滚动。次级收藏区使用完整的 Home 可用内容宽度，没有内容时高度为零；每条织带独立处理横向溢出，不移动其他 Home 区域。屏幕剩余空间只是未分配的透明 Home 空间，不是持续存在的产品区域。

收藏列表区当前最多支持两个持久化纵向列表。只有一个列表时，它使用收藏构图的全部可用宽度；存在两个列表时，先扣除构图左右各 `8dp` 的内部 padding 和 `16dp` 列表间距，再由两个列表平均分配剩余宽度。宽度根据当前可见列表数量计算，不采用固定百分比；该规则不定义或授权第三个列表。两个列表产品地位相同，共享一个视口高度，并各自保留内容和滚动状态；只有自身内容超出视口时才滚动。“克制”和“无干扰”约束干扰和可避免的操作，不刻意限制收藏数量。

Home 内容采用 `16dp` 横向与纵向容器 padding。相邻且可见的 Home 区域之间使用 `16dp` 间距。这些数值是 Home 可用边界内的内部布局距离，不是外部 margin。

## 时间、日期与星期

- 时间左对齐并位于日期上方，采用 `57sp` 字号、`64sp` 行高和粗体。所选系统字体支持时使用等宽数字特性，避免分钟变化导致时钟宽度跳动。
- 时间跟随系统 12/24 小时制，不显示秒。
- 日期与星期显示在时间下方，相对时间文字使用 `8dp` 的 start 内缩，采用 `16sp` 字号、`24sp` 行高和正常字重，格式跟随当前语言区域，例如简体中文为 `2月1日 星期二`。该内缩只影响可见文字；完整的日期星期行仍保持 `48dp` 可聚焦触控目标。应使用逻辑 `start` 对齐，而不是固定物理左偏移。
- 点击可见时间文字时，若系统时钟应用公开了可启动主界面，则进入该主界面。Avenor 不硬编码厂商时钟包名。若解析到的时钟应用未公开可启动主界面，则回退到其系统闹钟目标；若两个目标均不可用，则显示本地化失败反馈且不崩溃。
- 点击可见日期星期文字，通过隐式调用进入系统日历，不指定具体包名。
- 时间所在行高度至少为 `64dp`，不在其实际行区域之外另行扩大触控范围。
- 日期星期行高度为 `48dp`，文字垂直居中；完整行即为其可聚焦触控目标。

### 空白区域双击

- 基础信息模块在 Home 内容边界内保持完整宽度，并在当前文字和其他交互目标之外保留可用空白。该空白支持 [double-tap-lock.zh-CN.md](../features/double-tap-lock.zh-CN.md) 定义的可选双击锁屏能力。未来增加天气等信息时，也必须在模块中保留具有实际可操作性的空白部分。
- 时间和日期星期触控目标不属于该区域；两者已有的单击行为保持立即执行，不等待双击识别。
- 只有用户在 Android 系统设置中明确启用用途受限的 Avenor 无障碍服务后，该手势才生效。

## 收藏区域

- 新安装时收藏为空，显示简洁的空状态，引导用户前往 Drawer 添加应用。
- 每个收藏只属于一个直接访问目标：某个纵向收藏列表或某条次级收藏织带。通过既有 Drawer 操作新增的收藏追加到第一个收藏列表；没有列表时，该操作以默认“中”尺寸创建第一个列表。新增收藏不会跳转到 Home，也不会进入编辑模式。
- 当前产品最多支持两个持久化纵向收藏列表。持久化列表必须至少包含一个收藏；因为取消收藏、卸载协调或已完成移动而失去最后一个条目时，立即删除该列表，剩余列表如存在则扩展至全部可用宽度。
- 产品不因列表视口已经铺满而拒绝新增；溢出内容扩展该列表的可滚动内容，并保持已有顺序。
- 同一个稳定可启动条目身份不得在任一列表内部、不同纵向列表之间或次级收藏织带之间重复保存或展示。
- 主应用、应用分身和工作资料可启动条目继续作为不同身份处理；它们可以独立归入收藏，包括分别归入不同收藏目标，并且不得仅按包名去重。
- 收藏展示尺寸是列表级属性。同一列表中的所有条目使用该列表已保存尺寸，不同列表可以保留不同尺寸值。当前产品不提供尺寸选择交互：所有新建或迁移列表均使用“中”。“大”和“小”仍是已定义的展示 token，但在当前交互契约中不可由用户选择。
- “大”使用 `48dp` 应用图标、`64dp` 条目高度和正常字重的 `18sp/28sp` 名称；“中”使用 `40dp` 图标、`56dp` 条目高度和正常字重的 `16sp/24sp` 名称；“小”使用 `32dp` 图标、`48dp` 条目高度和正常字重的 `14sp/20sp` 名称。三种尺寸在几何允许时均使用条目四周 `8dp` padding、`16dp` 图标名称间距、系统字体缩放和一行静止末尾省略名称，不使用跑马灯。
- 两个列表都不根据当前视口定义产品层面的槽位上限。可见列表使用共享的构图视口高度，并分别维护自己的内容长度和滚动位置。列表内容能够容纳时不滚动；超出共享视口后在自身内部纵向滚动，不改变其他列表的位置或滚动状态。
- 图标形状和 badge 完全采用平台提供的呈现，并在 Home、Drawer 及相关应用界面中保持一致。
- 点击条目后立即启动应用，普通点击不产生震动，并抑制短时间内的重复启动。
- 长按条目时产生长按触觉反馈，并打开 [app-action-sheet.zh-CN.md](app-action-sheet.zh-CN.md) 定义的应用操作面板。
- 收藏点击与长按参与 [navigation.zh-CN.md](../navigation.zh-CN.md) 定义的 Home 全域上滑仲裁。上滑取得手势所有权后，不得启动收藏、打开其操作面板或产生该收藏的长按反馈。
- 只有成功刷新应用清单，并确认应用已卸载、应用分身已删除或该可启动身份永久消失后，才自动删除对应收藏。
- 应用清单整体加载失败时，不得删除或隐藏任何已保存收藏。
- 应用仍存在但被停用时，保留其原有位置并展示为明确的禁用收藏。点击后不尝试正常启动，而是展示简短且已本地化的不可用 Toast；长按仍可用于适用的应用信息或管理操作。
- 出现临时启动失败时，保留收藏，展示简短且已本地化的错误 Toast，并刷新该条目状态。
- 后续成功刷新确认条目恢复可用时，在原位置恢复，不改变收藏顺序。

### 收藏持久化加载与失败

- 只有 Avenor 能够可靠解释完整的已存储收藏状态时，收藏持久化读取才算成功。无法读取或已损坏的结果不是空收藏列表，不得展示新安装时的正常空状态。
- 可读的已保存状态早于列表级尺寸时，保留每个有效收藏已有的列表成员关系和顺序，为每个非空迁移列表分配“中”尺寸，并省略空列表。迁移不得重复或静默丢弃有效收藏。
- 加载中、无法读取和完全为空的收藏状态，都是完整收藏构图的共享状态，只展示一次，不按列表重复展示。持久化空列表不得存在：列表失去最后一个条目时即删除，并重新计算剩余可见列表宽度。
- 初次读取或用户请求的重试进行期间，收藏区域显示进度指示器和本地化文案 `正在加载收藏…`。不得同时展示收藏条目、空状态引导、错误图标或重试操作。
- 无法可靠读取状态时，收藏区域隐藏进度指示器，展示非交互的 `40dp` 错误图标、本地化文案 `无法加载收藏`，并提供独立的 `重试` 操作。
- 失败状态必须保留原始不可读数据，不得初始化、迁移、修复、清空、替换或以其他方式覆盖。进程重建和设备重启后不得把该失败重新解释为空列表。
- 失败或重试状态持续期间，所有添加收藏、取消收藏和编辑模式变更均为禁用状态。Home 时间日期、Home→Drawer 导航、Drawer 应用清单和应用启动继续可用。
- 选择重试后发起一次只读重新加载，将收藏区域切换为加载表现，并在本次尝试完成前禁用重复重试。重试不得写入、修复、迁移、清空或替换已存储收藏数据。
- 重试成功时，不执行额外写入，恢复准确可读的收藏状态及其顺序。可靠读取到空状态时，展示正常空状态引导并恢复收藏变更能力。
- 重试失败时，返回相同的持续失败表现，恢复重试操作，保留原始不可读数据，并继续禁用收藏变更。由于可见的收藏区域错误已经表达结果，不额外展示 Toast。用户可以再次重试。
- 新进程启动时执行一次正常初始读取。Avenor 不持续自动重试、轮询，也不以网络状态变化作为重试触发条件。任何其他安全读取触发条件均需技术验证，并且必须遵守相同的禁止写入边界。
- 如果检测到失败时收藏变更界面已经打开，则关闭该界面且不应用收藏变化。修复、导出、重置、备份和恢复行为需要后续产品决定与技术评估。

## 编辑模式

- 编辑模式可以从被选中收藏条目的启动器操作进入，也可以通过长按基础信息模块中符合条件的空白位置进入。符合条件的空白位置不包含时间、日期星期和任何其他交互目标。长按一经识别，即产生标准长按触觉反馈、进入编辑模式，并阻止同一触控序列继续触发双击锁屏或其他操作。操作面板入口仍使用“编辑”而不是“排序”命名，因为此模式同时支持顺序调整、列表归属调整和新增收藏。
- 编辑模式为每个收藏显示拖动柄。每个当前已定义且可编辑的 Home 模块都使用 [design-foundations.zh-CN.md](../design-foundations.zh-CN.md) 定义的淡灰色、轻微透明、小圆角编辑表面。当前产品中即基础信息模块和收藏列表区；次级收藏区的编辑表面尚未由本契约定义。这些表面用于表达模块边界，不表示基础信息模块可以编辑。
- 编辑模式保持每个列表已经选择的“大／中／小”条目高度。所有列表使用相同的 `24dp` 拖动柄图形。每个拖动柄热区宽度为 `24dp` 图形加左右各 `12dp` padding，即总宽度 `48dp`；热区高度跟随当前条目的完整高度。图形右侧不额外设置 margin，视觉间距来自条目已有的 padding。拖动柄包含在行内，不得增加行高或重新测量列表。
- 拖动柄拖动使用独立的跟手预览。预览保留抓取偏移，并可在整个 Home 安全内容区域内连续移动，包括两个列表及其间距。只有持久化或临时纵向收藏列表接受这些当前已定义的放置；其他 Home 区域允许预览经过但不接受放置。被拖动收藏不参与列表位置动画，目标变化或其他条目动画不得使预览自动平移、跳转或回弹。
- 源收藏的原始布局槽位在整个拖动期间保持稳定并保留源行高度，因此列表不会因临时移除源条目而收缩，共享视口不会改变，其他收藏也不会整体跳动。尚未选中交换目标时，该槽位可以保留源收藏的不可交互表示；列表内交换目标移动到此处后，由目标覆盖或替代该不可交互表示。槽位中不得同时存在两个可交互收藏。列表内交换可以在拖动期间实时更新可见位置；跨列表交换和插入只显示目标反馈，松手前不改变两个列表。已保存状态只在当前有效操作松手时最终确定。
- 当触控点仍在源列表内时，只支持交换。触控点进入其他收藏的有效主体区域后，该收藏成为交换目标；拖动期间目标收藏立即与源收藏交换位置，独立预览仍由手指控制且不参与目标动画。触控点进入另一个有效主体后，当前可见交换更新为新的目标。同列表间隙不显示插入线，也不接受插入。触控点停留在被拖动收藏自身、源位置或无效区域时，不产生新的交换。
- 当触控点进入另一列表时，目标类型互斥。已有收藏主体表示跨列表交换：目标显示交换高亮或边框且不显示插入线，但拖动期间不改变两个列表的可见位置或归属。有效间隙表示跨列表插入：插入线标记目标边界，不显示交换边框，且松手前不改变两个列表。松手后才一次性执行当前跨列表交换或插入；插入会从源列表移除被拖动收藏，并按该边界插入目标列表，同时保持目标列表原有收藏的相对顺序。第一项之前、条目之间、最后一项之后以及空临时目标列表都属于有效插入目标。
- 例如列表 1 为 `[A, B, C]`、列表 2 为 `[D, E, F]` 时，把 `A` 放到 `E` 的主体后执行交换，结果为列表 1 `[E, B, C]`、列表 2 `[D, A, F]`。如果改为把 `A` 放到 `D` 与 `E` 之间的间隙，则执行插入，结果为列表 1 `[B, C]`、列表 2 `[D, A, E, F]`。
- 目标判断以手指触控点为准，不以预览中心或边缘为准。预览可以在视觉上覆盖目标，但不能改变目标类型。从交换主体移动到插入间隙时，交换边框切换为插入线；反向移动时，插入线切换为交换反馈。目标切换不修改已保存数据。边缘自动滚动期间，根据当前目标列表几何位置重新计算反馈并继续以触控点为准；滚动或列表切换不得造成无法解释的目标跳变。
- 列表内交换在触控点进入有效收藏主体时实时更新可见位置；跨列表交换和插入只显示目标反馈，拖动期间不改变两个列表。当前操作在有效目标上松手后一次性执行并立即保存。无效区域松手时恢复原始列表和位置，不改变已保存状态。被拖动预览保持独立；列表内交换过渡可以动画目标收藏，但跨列表反馈不得移动预览或任一列表。如果持久化失败，应为身份仍然有效的收藏恢复最近一次成功保存的列表归属和顺序，然后保留时间上更新的已确认应用清单协调结果。失败恢复不得重新加入后续应用清单事件已确认移除或失效的应用、分身或可启动身份。不得将该操作表现为已完成，并展示现有的收藏更新失败反馈。
- 系统 Back 和 Android 系统 Home 操作都可以退出编辑模式。如果活动拖动期间发生其中任一操作，应先取消该拖动、移除跟手预览和目标反馈、恢复最近一次已保存的可见列表与顺序，并使该手势后续的 release 失效，不能触发保存。随后退出并移除编辑表面、拖动柄和新增控件，但不撤销退出前已经完成的移动或新增。Back 返回普通 Home；Android 系统 Home 操作也按照现有 Launcher 导航契约落到普通 Home。
- 编辑表面、可见拖动柄和可见新增控件共同表示当前处于编辑模式；当前不定义额外的 Home 标题、横幅、完成按钮或界面内退出操作。

### 编辑模式新增收藏

- 编辑模式在每个持久化纵向收藏列表的真实末尾显示一个在列表宽度内水平居中的新增控件，每条已有次级收藏织带也以一个新增控件收尾。该控件随所属列表或织带滚动，不属于收藏或拖动目标，也不持久化。
- 每个新增控件使用标准 `24dp` 加号图形，交互目标的宽高至少为 `48dp`。所在行或织带保持所属列表或织带的普通高度；该控件不得拉伸或重新测量收藏条目。
- 没有纵向收藏列表时，编辑模式显示一个仅含新增控件的全宽临时列表。只有一个持久化列表时，编辑模式让该列表与一个临时列表平均分配宽度，以预览双列表布局。确认至少一个应用后，临时列表以默认“中”尺寸创建；取消或退出编辑模式时不持久化。已有两个持久化列表时，不再显示临时列表入口。
- 次级收藏织带少于五条时，编辑模式还会在所有已有织带之后显示一条临时空织带，其中仅包含一个新增控件。普通 Home 永远不显示该临时织带；已有五条持久化织带时，不再显示临时织带入口。
- 点击新增控件时记录其明确的目标列表或目标织带，并以 [drawer.zh-CN.md](drawer.zh-CN.md) 定义的收藏多选模式打开 Drawer。Drawer 以程序触发的方式完成向上过渡；编辑模式仍禁用手势触发的 Home-to-Drawer 过渡。
- 已确认应用按显示的选择顺序追加到已记录目标。用户从临时列表或临时织带确认至少一个应用时，才将该目标及其首批条目作为一个整体创建并持久化。取消、没有条目可确认或通过 Android 系统 Home 操作离开时，不创建空目标。
- 确认或普通取消后，Drawer 完成向下退出过渡。确认后返回原有 Home 编辑模式并保留有意义的滚动上下文；普通取消也返回该编辑模式，且不改变收藏。Android 系统 Home 操作会取消选择并退出编辑模式，最终显示普通 Home。

- 从收藏拖动柄开始的拖动负责移动条目；在收藏列表内其他位置开始的纵向拖动，在该列表存在溢出时滚动该列表。编辑模式不换页，也不展开折叠列表。
- 收藏松手时，如果当前目标有效，则完成当前列表内交换、跨列表交换或跨列表插入并立即保存；跨列表松手遵循上述互斥目标、预览、无效放置和保存规则。
- 编辑模式禁用 Home→Drawer 拖动；条目拖动、列表滚动和边缘自动滚动在编辑模式结束前保持手势所有权。

## 次级收藏区

- 次级收藏区是位于收藏列表区下方的条件性 Home 模块，与收藏列表区保持 `16dp` 纵向间距。
- 次级收藏区使用完整的 Home 可用内容宽度，不参与纵向收藏列表的宽度分配。
- 没有内容时，次级收藏区高度为零，不保留空白占位。
- Home 本身不因次级收藏区而纵向滚动。该区域由最多五条纵向堆叠的横向织带组成；当前产品将五条写死为上限，未来由用户配置织带数量的 Settings 能力不在当前契约内。
- 每条织带高 `56dp`，相邻织带之间使用 `8dp` 纵向间距，并包含一组有限且由用户定义的可启动应用条目。条目能够容纳时织带保持静止，超出可见宽度时该织带横向滚动；织带不循环滚动。
- 每个次级收藏条目在 `128dp` 固定宽度内展示 `40dp` 平台应用图标和一行静止应用名称，其高度、图标尺寸、`16dp` 图标名称间距及正常字重的 `16sp/24sp` 名称与收藏列表“中”尺寸一致。图标是主要识别线索，名称是次要视觉标签。名称无法完整显示时使用末尾省略。
- 每条织带中的条目左对齐，相邻固定宽度条目之间保持 `8dp`；剩余横向空间保持未使用，不重新均分给条目。
- 每个条目使用浅色前景语义色 `6%` alpha（不透明度）作为极浅半透明背景，并使用同一语义色 `12%` alpha（不透明度）的 `1dp` 边界和 `12dp` 圆角。该处理在明确条目范围的同时保留透明 Home 背景的可感知性；普通按压反馈继续使用当前浅色 ripple 契约。
- 次级收藏区不按产品预设类型区分织带或条目；内容完全由用户定义，并由与当前收藏条目一致的可启动应用条目组成。织带是否显示标题以及标题行为为`待决定`；当前契约既不要求也不禁止标题。
- 次级收藏遵循与纵向收藏列表相同的唯一归属规则。把某个身份归入次级织带是改变该身份唯一的直接访问目标，而不是创建第二份收藏副本。
- 次级收藏通过上述编辑模式织带新增控件添加。已经归入任一收藏目标的身份不可再次选择。已有身份在次级织带与纵向收藏列表之间移动的交互仍不在当前已定义边界内。
- 点击次级收藏条目后立即启动对应应用。长按条目时产生长按触觉反馈，并打开 [app-action-sheet.zh-CN.md](app-action-sheet.zh-CN.md) 定义的应用操作面板。
- 每条织带都有明确的首个和末个应用条目，之后是仅在编辑模式显示的新增控件。从临时织带确认应用会创建一条新织带；织带因移除收藏或应用清单协调而失去最后一个应用条目时立即删除。织带命名、已有成员移动和织带排序仍不在当前契约内。
- 可见模块下方尚未分配的透明空间不是次级收藏区。

### 编辑模式期间的应用清单变化

任何会结束编辑模式的应用清单事件，也会取消正在进行的拖动、移除跟手预览和目标反馈，并且不提交尚未完成的移动或交换。

| 清单事件 | 当前行为 |
| --- | --- |
| 安装新应用 | 保持编辑模式；收藏不受影响 |
| 移除未收藏应用 | 保持编辑模式；收藏不受影响 |
| 收藏应用名称变化 | 原位置更新名称，保持编辑模式 |
| 收藏应用图标或平台 badge 变化 | 原位置更新，保持编辑模式 |
| 收藏应用被卸载 | 结束编辑模式、删除该收藏、保留此前已保存移动，并提示用户 |
| 已收藏应用分身被删除 | 结束编辑模式、删除该分身收藏、保留此前已保存移动，并提示用户 |
| 收藏应用被停用 | 结束编辑模式、在原保存位置保留为禁用收藏、保留此前已保存移动，并提示用户 |
| 收藏身份暂时无法确认 | 结束编辑模式、保留该条目和顺序等待刷新，并提示用户 |
| 完整应用清单加载失败 | 结束编辑模式、保留所有收藏及已保存顺序，并提示用户 |
| 收藏数量降低到两个以下，且没有其他应用清单规则要求退出 | 保持编辑模式，包括零收藏状态，使新增控件继续可用 |

- 已确认收藏发生变化时，统一使用本地化提示：`收藏应用已发生变化，编辑模式已结束`。
- 应用清单或身份刷新失败时，统一使用本地化提示：`暂时无法更新应用状态，编辑模式已结束`。
- 上述两类消息均使用短 Toast 展示。

## 验收意图

- 一个纵向收藏列表使用全部构图宽度；两个列表在扣除固定 padding 与列表间距后平均分配可用宽度。每个列表只在自身内容超出共享视口时滚动；失去最后一个条目时立即删除，并重新计算剩余列表宽度。次级织带失去最后一个应用条目时同样自动删除。
- 次级收藏区仅在有内容时显示于收藏列表区下方，使用完整的 Home 可用内容宽度，并包含最多五条高 `56dp`、由用户定义可启动应用条目组成的横向织带。每个 `128dp` 宽条目展示 `40dp` 图标和一行静止应用名称；织带只在内容溢出时横向滚动，到达末项后不循环回首项。点击条目启动对应应用，长按条目打开现有应用操作面板。
- 每个已保存的可启动条目身份在所有纵向收藏列表和次级织带中最多出现一次。即使属于同一包族，主应用、应用分身和工作资料条目仍是可以独立归属的身份。
- 加载中、无法读取和完全为空的收藏状态在完整收藏构图中只展示一次；持久化空列表不得存在。
- 编辑模式之外，Home→Drawer 上滑在收藏区域按照滚动边界交接规则可用，并且可以从其他所有由 Avenor 管理的 Home 元素起始；不得同时产生元素的点击或长按操作。
- 平台提供 badge 时，主应用与应用分身保持可辨识；Avenor 自有的备用区分方式不在当前范围内。
- 同一进程内返回 Home 时保留有意义的列表状态；进程重建遵循 [navigation.zh-CN.md](../navigation.zh-CN.md)。
- 不可读收藏状态必须与有效空列表保持可区分，不能通过收藏操作覆盖，并且能够通过成功的只读重试恢复，同时不阻断独立的应用发现与启动路径。

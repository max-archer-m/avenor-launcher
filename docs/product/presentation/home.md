# Home Presentation Specification

> Public semantic source: English. Chinese counterpart: [home.zh-CN.md](home.zh-CN.md).

## Responsibility

This document owns exact Home layout, typography, component geometry, and visual states. [Home behavior](../surfaces/home.md) owns state and action results; [design foundations](../design-foundations.md) owns shared principles and reusable tokens; the [style settings panel presentation](style-settings-panel.md) owns the panel surface and controls shared with Drawer.

## Surface and basic information

- Home preserves wallpaper without a full-screen dim, tint, Scrim, glass surface, or blur. Foreground text and monochrome artwork use shared `primaryTextColor` and may use one fixed glyph-following dark shadow. Exact shadow values are `To be decided` through author-device calibration.
- Home applies uniform `8dp` content padding inside `safeDrawing`; adjacent visible modules use `8dp` spacing.
- The basic-information module adds no padding. Its time and date rows use `8dp` start and end margins inside the padded boundary, producing `16dp` row boundaries from safe edges. The time row adds `8dp` top margin for a final `16dp` top distance. Date text adds another `8dp` start inset and begins `24dp` from the safe start edge while its complete row target remains at `16dp`.
- The time row is at least `64dp` high and uses `57sp/64sp` bold display text. The date row is `48dp` high and uses normal-weight shared `primaryTextFontSize`, its line height, and `primaryTextColor`.
- The favorite main list and its modules add no outer padding beyond Home content padding.
- A favorite whose latest reliable state is disabled keeps its ordinary measured geometry in either module type while its application icon and name use the shared `38%` unavailable opacity. Application-level remove controls and movement feedback remain at their ordinary opacity because those editing actions are still available.

## Vertical favorite modules

- Modules use the complete padded content width. Their large, medium, and small item geometry and right/below name arrangements use the applicable Drawer application-item presentation values.
- One-item-per-row with a right-side name follows the established Home list geometry: large uses a `48dp` icon and `64dp` item height; medium uses `40dp` and `56dp`; small uses `32dp` and `48dp`. Large, medium, and small names respectively use normal-weight shared `largeAppNameFontSize`, `primaryTextFontSize`, and `secondaryTextFontSize`, each with its shared line height and `primaryTextColor`; all retain the Drawer single-line ellipsis rule.
- Every size permits one or two items per row with right-side names and one through four with below-icon names. Exact multi-column cell geometry reuses the applicable Drawer presentation values. Step controls use the shared style settings panel geometry and the established enabled and disabled presentation at one and the applicable maximum. They update in the same frame as a name-placement change: right-to-below at two enables increment, while below-to-right from three or four displays two with increment disabled.
- Normal-mode items use no module-level title bar. While the style settings panel is collapsed, application-level editing adds one remove control but no application-reorder handle or reserved handle space; the non-remove portion of the complete item remains the long-press movement target.

## Horizontal favorite ribbons

- A ribbon is full width, one row, `56dp` high, and has no container padding. Multiple ribbons or adjacent modules use the shared `8dp` module spacing.
- Each entry uses an `8dp` start inset, `40dp` icon, `8dp` icon-to-name gap, one normal-weight `primaryTextFontSize` line measured up to `64dp`, and `8dp` trailing inset. The name uses its shared line height and `primaryTextColor`. Total width is content-measured up to `128dp`; longer names use end ellipsis. Entry spacing is `8dp`.
- Each entry uses `primaryTextColor` at `6%` for background, `12%` for a `1dp` boundary, and `12dp` radius. Press Ripple clips to that outline.

## Add-favorite entries

- The two main-list add-favorite entries form one row after the last module, using the shared `8dp` module spacing above that row. They divide the padded content width equally with `8dp` spacing between them and are at least `48dp` high.
- A trailing module add-favorite entry occupies the next entry position after its module's last application. In a vertical module it uses that module's current size, name-placement, items-per-row cell geometry, and applicable icon-to-name gap; in a ribbon it uses the ribbon entry geometry. Its icon slot therefore matches the owning module's application-icon slot: `48dp`, `40dp`, or `32dp` for a Large, Medium, or Small vertical module, and `40dp` for a ribbon. The add artwork remains the shared `24dp x 24dp` plus icon centered inside that slot. The label follows the owning module's right-side or below-icon name placement instead of forcing one horizontal arrangement. Neither case adds a separate row height or container padding beyond the module's own arrangement.
- Every add-favorite entry uses the ribbon entry surface treatment: `primaryTextColor` at `6%` for background, `12%` for a `1dp` boundary, and `12dp` radius. Press Ripple clips to that outline. The entry adds no wallpaper dim, tint, Scrim, or blur.
- Each main-list add-favorite entry combines the shared `24dp x 24dp` functional-icon plus artwork in `primaryTextColor` with its localized label in normal-weight shared `primaryTextFontSize`, its shared line height, and `primaryTextColor`. The icon and label are horizontally centered as one unit with an `8dp` icon-to-label gap. A trailing module entry instead uses the owning module's icon slot, name placement, gap, font size, line height, and label geometry defined above. Every label remains one line and uses end ellipsis. The plus character is not part of the localized string.
- During an exclusive unresolved save, an add-favorite entry uses the shared `38%` disabled opacity without an additional Loading state or progress indicator.
- While a moving application hovers a valid main-list add-favorite entry, that entry shows the same emphasis as a selected module: a complete `2dp` `primaryTextColor` outline with `12dp` corners drawn fully inside its bounds, adding no fill or tint and changing neither its measurement nor surrounding spacing. This drop emphasis replaces the insertion line for that release and never appears together with one, keeping destination release and boundary insertion visually distinct.

## Edit dock and style settings panel

- The edit dock is fixed inside `safeDrawing` at the bottom of safe content and remains exactly `32dp` high whether the style settings panel is collapsed or expanded. The system bottom safe inset is outside that height. With the panel collapsed, the favorite main-list viewport ends directly at the dock with `0dp` intervening spacing.
- The dock has no general horizontal padding. Its non-interactive instruction occupies the physical-left region remaining after the affordance target and uses `8dp` start and end padding within that region. The text is vertically centered, remains complete on one line without ellipsis, and uses medium-weight shared `secondaryTextFontSize`, its line height, and `primaryTextColor`.
- The physical-right upward or downward affordance occupies a `48dp x 32dp` target flush with the dock's top, end, and bottom edges. Its visible directional artwork uses the shared `24dp x 24dp` functional-icon size and `primaryTextColor`; the exact drawable asset is selected during implementation. The author accepts this dock-specific target as an exception to the shared `48dp` minimum target height.
- The expanded panel hosts the shared [style settings panel](style-settings-panel.md) as an inline Home layout region. It uses the shared horizontal outer margin, rounded surface, edge shadow, row geometry, and applicable application-size, name-placement, and items-per-row controls. Home adds no bottom outer margin: the panel sits directly above the still-visible edit dock with `0dp` spacing. It remains non-modal, has no Scrim, and stays outside the favorite main-list viewport.
- While the panel is expanded, the basic-information region is not laid out. The panel measures to its current content instead of using a fixed height. It grows only within the available safe layout without covering the favorite main list or edit dock. The main-list viewport retains at least `112dp`; the panel's maximum height is therefore the remaining safe content height after the fixed `32dp` edit dock and that minimum viewport are reserved. Content exceeding the resulting panel height scrolls inside the panel. A content-driven height change uses the shared short-duration property-animation token and preserves the main list's logical scroll position.
- Modules expose no separate module-reorder handle or reserved handle space. When the style settings panel is expanded, every editable unselected module instead receives four non-interactive rounded corner marks in `secondaryTextColor`. Each mark forms one curved corner with `16dp` arms, `2dp` stroke, `4dp` inset, and `8dp` radius. The marks indicate that the complete module surface supports selection and long-press movement; they do not define a smaller touch target or change ordinary module measurement. Waiting for long-press recognition does not alter them. During an exclusive unresolved edit save they use the shared `38%` disabled opacity and cannot imply that another movement is available.
- The expanded selection layer replaces the selected module's four corner marks with a complete `2dp` `primaryTextColor` outline using `12dp` corners. The outline is drawn fully inside the module bounds, adds no fill or tint, and changes neither module measurement nor inter-module spacing. During an exclusive unresolved edit save it uses the shared `38%` disabled opacity. Selection, lifted movement, insertion position, and unavailable mutation therefore remain visually distinct. The layer may not expose application-level press or drag feedback. Any contrast shadow shared with other Home foreground treatment remains subject to author-device calibration.
- The panel has no module-type row and reserves no visual space for a custom module name. With no selection, it renders the contracted selection prompt as one non-interactive shared read-only row. A selected vertical module starts directly with its applicable controls. A selected ribbon renders the contracted fixed-style message as one non-interactive shared read-only row and does not render disabled style controls. Both informational rows use the shared `56dp` row geometry, medium-weight shared `secondaryTextFontSize` and its line height, and `primaryTextColor`. The panel exposes no add action and no complete-module deletion control.
- Application remove controls use a white X on a solid error-red `20dp x 20dp` circle. The visible circle is also the author-accepted `20dp x 20dp` interaction target and must remain inside its owning item. With a right-side name, the icon begins `8dp` from the item's physical left and top, while the remove circle touches those item edges; the resulting overlap at the icon's top-left is `12dp x 12dp`. A ribbon uses the same geometry. With a below-icon name, the icon-and-name unit retains its centered arrangement and the remove circle is positioned `8dp` left and `8dp` above that icon's top-left, again producing a `12dp x 12dp` overlap.

## Drag and overflow feedback

- Ribbon overflow may use the existing inward `48dp` `primaryTextColor` gradient from transparent to at most `8%` opacity. It changes no geometry or input ownership.
- At long-press recognition, module movement freezes a complete visual snapshot of the rendered source module. The lifted preview preserves the initial pointer offset, uses no source placeholder, remains at `100%` opacity and `1.0` scale, and does not live-update during that gesture. Remaining modules close the source gap without changing widths. The preview uses a `12dp` elevation-style shadow as its only additional lift treatment.
- Every movement candidate displays exactly one non-layout `2dp` `primaryTextColor` insertion line at the resolved order boundary. Module movement uses a horizontal line across the module's available width at the boundary between adjacent modules. A one-column vertical application layout uses a horizontal line across the candidate item's available width at its top or bottom edge. A multi-column row or ribbon uses a vertical line across the candidate item's measured height at its physical-left or physical-right edge. A wrapped-row boundary uses only the edge belonging to the currently resolved before-or-after candidate; it never duplicates the same semantic boundary at both rows. The line overlays content without reserving space or displacing items.
- Module and application movement use the same resource-backed edge auto-scroll values. Each applicable start/end or top/bottom edge band is `48dp`, capped at half of the viewport's corresponding dimension when that dimension is less than `96dp`. Continuous residence in one eligible band for `120ms` activates scrolling. Speed then increases linearly from `0dp/s` at the band's inner boundary to exactly `180dp/s` at the viewport's outer edge.
- Application movement retains one source placeholder at the source item's measured dimensions. The placeholder has no fill and uses a `1dp` `primaryTextColor` outline at `12%` opacity with the source item's existing shape. Its lifted preview keeps source presentation at `100%` opacity and `1.0` scale until a valid cross-module release saves successfully, adding only the same `12dp` elevation-style shadow used by module movement. The destination uses the insertion line defined above as its only candidate emphasis and does not perform a provisional full-list reorder or add a whole-module highlight.
- While a movement pointer occupies an eligible edge-auto-scroll band, the applicable edge displays one inward `48dp` gradient from transparent to at most `8%` `primaryTextColor` at the outer edge. It is directional, non-layout feedback; it appears during the activation delay, remains while that edge request is eligible or active, and disappears immediately when eligibility ends. It does not replace the insertion line or add another haptic.

# Home 交互规格

> 英文语义源：[home.md](home.md)。公共导航见 [navigation.zh-CN.md](navigation.zh-CN.md)，公共视觉规则见 [design-foundations.zh-CN.md](design-foundations.zh-CN.md)。

## 目的与结构

Home 是 Launcher 主界面，内容按从上至下的单列结构排列：

1. 基础信息区：时间在上，日期与星期在下。
2. 收藏应用列表区：按用户定义顺序展示所有已保存的可启动应用条目。

基础信息区在普通情况下约占可用纵向空间的 20%–30%，但内容完整和无障碍优先于强制百分比。收藏列表占用剩余空间，从区域顶部开始排列，仅在内容超出时滚动；滚动条只在滚动期间展示。

Home 内容采用 16dp 横向内边距和暂定 32dp 纵向内边距。这里使用 padding 而不是 margin，因为这些数值表达的是 Home 容器边界与内部内容之间的安全距离。

## 时间、日期与星期

- 时间左对齐并位于日期上方，采用 `57sp` 字号、`64sp` 行高和粗体。所选系统字体支持时使用等宽数字特性，避免分钟变化导致时钟宽度跳动。
- 时间跟随系统 12/24 小时制，不显示秒。
- 日期与星期在时间下方左对齐，采用 `16sp` 字号、`24sp` 行高和正常字重，格式跟随当前语言区域，例如简体中文为 `2月1日 星期二`。
- 点击可见时间文字，通过隐式调用进入系统时钟，不指定具体包名。
- 点击可见日期星期文字，通过隐式调用进入系统日历，不指定具体包名。
- 时间所在行高度至少为 `64dp`，不在其实际行区域之外另行扩大触控范围。
- 日期星期行的可见高度为 `40dp`，文字垂直居中；触控输入层可以将可聚焦目标自动扩展到至少 `48dp`，但不得绘制更大的背景或改变可见的 40dp 布局。

## 收藏列表

- 新安装时收藏为空，显示简洁的空状态，引导用户前往 Drawer 添加应用。
- 从 Drawer 收藏应用后，将其追加到列表末尾。
- 同一个可启动应用条目不能重复收藏。主应用与应用分身是不同条目，可以分别收藏。
- 条目使用竖直单列。每个条目至少高 `56dp`，包含 `40dp` 的平台应用图标、存在时的平台分身或资料 badge，以及应用名称；图标与名称之间为 `16dp`。
- 应用名称只占一行。能够完整展示时保持静止；发生溢出时，使用 [design-foundations.zh-CN.md](design-foundations.zh-CN.md) 定义的公共跑马灯行为。
- 图标形状和 badge 完全采用平台提供的呈现，并在 Home、Drawer 及相关应用界面中保持一致。
- 点击条目后立即启动应用，普通点击不产生震动，并抑制短时间内的重复启动。
- 长按条目时产生长按触觉反馈，并打开 [app-action-sheet.zh-CN.md](app-action-sheet.zh-CN.md) 定义的应用操作面板。
- 只有成功刷新应用清单，并确认应用已卸载、应用分身已删除或该可启动身份永久消失后，才自动删除对应收藏。
- 应用清单整体加载失败时，不得删除或隐藏任何已保存收藏。
- 应用仍存在但被停用时，保留其原有位置并展示为明确的禁用收藏。点击后不尝试正常启动，而是展示简短且已本地化的不可用 Toast；长按仍可用于适用的应用信息或管理操作。
- 出现临时启动失败时，保留收藏，展示简短且已本地化的错误 Toast，并刷新该条目状态。
- 后续成功刷新确认条目恢复可用时，在原位置恢复，不改变收藏顺序。

### 收藏持久化加载与失败

- 只有 Avenor 能够可靠解释完整的已存储收藏状态时，收藏持久化读取才算成功。无法读取或已损坏的结果不是空收藏列表，不得展示新安装时的正常空状态。
- 初次读取或用户请求的重试进行期间，收藏区域显示进度指示器和本地化文案 `正在加载收藏…`。不得同时展示收藏条目、空状态引导、错误图标或重试操作。
- 无法可靠读取状态时，收藏区域隐藏进度指示器，展示错误图标、本地化文案 `无法加载收藏` 和 `重试` 操作。
- 失败状态必须保留原始不可读数据，不得初始化、迁移、修复、清空、替换或以其他方式覆盖。进程重建和设备重启后不得把该失败重新解释为空列表。
- 失败或重试状态持续期间，所有添加收藏、取消收藏和排序变更均为禁用状态。Home 时间日期、Home→Drawer 导航、Drawer 应用清单和应用启动继续可用。
- 选择重试后发起一次只读重新加载，将收藏区域切换为加载表现，并在本次尝试完成前禁用重复重试。重试不得写入、修复、迁移、清空或替换已存储收藏数据。
- 重试成功时，不执行额外写入，恢复准确可读的收藏状态及其顺序。可靠读取到空状态时，展示正常空状态引导并恢复收藏变更能力。
- 重试失败时，返回相同的持续失败表现，恢复重试操作，保留原始不可读数据，并继续禁用收藏变更。由于可见的收藏区域错误已经表达结果，不额外展示 Toast。用户可以再次重试。
- 新进程启动时执行一次正常初始读取。Avenor 不持续自动重试、轮询，也不以网络状态变化作为重试触发条件。任何其他安全读取触发条件均需技术验证，并且必须遵守相同的禁止写入边界。
- 如果检测到失败时收藏变更界面已经打开，则关闭该界面且不应用收藏变化。修复、导出、重置、备份和恢复行为需要后续产品决定与技术评估。

## 排序模式

- 排序模式只在 Home 至少包含两个收藏时可用，并从被选中收藏条目的启动器操作进入。收藏为零或一个时隐藏排序操作。
- 每个收藏条目右侧显示三条横线形式的拖动柄，视觉上可参考常见媒体列表的排序手柄。
- 将条目拖过另一个已保存位置时交换位置，并针对已完成的位置变化提供一次短震动。
- 变化后的顺序立即保存。
- 系统 Back 是当前唯一退出排序模式的渠道，退出时不撤销已经完成的移动。
- 可见拖动柄就是当前排序模式的状态提示；当前不定义额外标题、横幅、完成按钮或退出操作。

### 自动滚动

- 收藏列表可见区域顶部和底部各 `48dp` 是排序自动滚动区域。
- 被拖动条目停留在自动滚动区域时，列表沿对应方向滚动；指针越接近外侧边缘，速度越快。具体速度曲线是需要在实体设备验证的公共实现 token。
- 指针离开两个边缘区域，或列表到达对应实际边界时，立即停止自动滚动。
- 自动滚动期间跨过一个已保存位置时，执行与普通拖动相同的位置交换、立即保存和一次短震动。仅停留在边缘区域或滚动但未跨过位置时不产生震动。
- 松手后保留当前位置并立即保存。
- 排序模式独占收藏列表的纵向拖动手势。排序结束前禁用 Home→Drawer 拖动，因此底部自动滚动不会触发 Drawer 过渡。

### 排序期间的应用清单变化

| 清单事件 | 当前行为 |
| --- | --- |
| 安装新应用 | 保持排序模式；收藏不受影响 |
| 移除未收藏应用 | 保持排序模式；收藏不受影响 |
| 收藏应用名称变化 | 原位置更新名称，保持排序模式 |
| 收藏应用图标或平台 badge 变化 | 原位置更新，保持排序模式 |
| 收藏应用被卸载 | 结束排序、删除该收藏、保留此前已保存移动，并提示用户 |
| 已收藏应用分身被删除 | 结束排序、删除该分身收藏、保留此前已保存移动，并提示用户 |
| 收藏应用被停用 | 结束排序、在原保存位置保留为禁用收藏、保留此前已保存移动，并提示用户 |
| 收藏身份暂时无法确认 | 结束排序、保留该条目和顺序等待刷新，并提示用户 |
| 完整应用清单加载失败 | 结束排序、保留所有收藏及已保存顺序，并提示用户 |
| 收藏数量降低到两个以下 | 应用对应事件处理后结束排序模式 |

- 已确认收藏发生变化时，统一使用本地化提示：`收藏应用已发生变化，排序已结束`。
- 应用清单或身份刷新失败时，统一使用本地化提示：`暂时无法更新应用状态，排序已结束`。
- 上述两类消息均使用短 Toast 展示。

## 验收意图

- 空、较短和可滚动收藏列表均保持相同的顶部对齐结构。
- 平台提供 badge 时，主应用与应用分身保持可辨识；Avenor 自有的备用区分方式不在当前范围内。
- 同一进程内返回 Home 时保留有意义的列表状态；进程重建遵循 [navigation.zh-CN.md](navigation.zh-CN.md)。
- 不可读收藏状态必须与有效空列表保持可区分，不能通过收藏操作覆盖，并且能够通过成功的只读重试恢复，同时不阻断独立的应用发现与启动路径。

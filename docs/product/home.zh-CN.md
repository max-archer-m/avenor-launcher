# Home 交互规格

> 英文语义源：[home.md](home.md)。公共导航见 [navigation.zh-CN.md](navigation.zh-CN.md)，公共视觉规则见 [design-foundations.zh-CN.md](design-foundations.zh-CN.md)，完整空间草图见共享的[普通 Home](wireframes/home.txt)与 [Home 编辑模式](wireframes/home-edit-mode.txt)线框，阅读规则见[线框索引](low-fidelity-wireframes.zh-CN.md)。

## 目的与结构

Home 是 Launcher 主界面。它是不可分页、不可折叠且不使用文件夹的固定界面。页面本身不滚动；只有主收藏与伴收藏区域按照下述溢出规则独立滚动。内容按从上至下排列：

1. 基础信息区：时间在上，日期与星期在下。
2. 中部收藏构图：由主收藏与伴收藏组成，包含所有已接受并保存的可启动应用条目。
3. 底部次级功能区：为空间预留，后续产品能力的内容与交互尚未定义。

三个区域以 Home 安全可用高度的约 20:60:20 为构图目标：基础信息区约占 20%，完整的主收藏与伴收藏构图约占 60%，底部次级功能区约占 20%。该比例用于指导整体构图，不得覆盖安全 inset、内容完整性或最小交互目标。底部区域为空时，收藏容器也不得向其中扩张。

中部收藏构图内，主收藏区约占左侧 60% 的可用横向空间，伴收藏区约占右侧 40%。这是构图层级，不是用户可调节的分栏线。“克制”和“无干扰”不要求刻意限制收藏应用数量，而是约束干扰和可避免的操作。两组均保持固定可见区域，并且仅在各自内容超出自身视口后独立纵向滚动。

Home 内容采用 16dp 横向内边距和暂定 32dp 纵向内边距。这里使用 padding 而不是 margin，因为这些数值表达的是 Home 容器边界与内部内容之间的安全距离。

## 时间、日期与星期

- 时间左对齐并位于日期上方，采用 `57sp` 字号、`64sp` 行高和粗体。所选系统字体支持时使用等宽数字特性，避免分钟变化导致时钟宽度跳动。
- 时间跟随系统 12/24 小时制，不显示秒。
- 日期与星期在时间下方左对齐，采用 `16sp` 字号、`24sp` 行高和正常字重，格式跟随当前语言区域，例如简体中文为 `2月1日 星期二`。
- 点击可见时间文字时，若系统时钟应用公开了可启动主界面，则进入该主界面。Avenor 不硬编码厂商时钟包名。若解析到的时钟应用未公开可启动主界面，则回退到其系统闹钟目标；若两个目标均不可用，则显示本地化失败反馈且不崩溃。
- 点击可见日期星期文字，通过隐式调用进入系统日历，不指定具体包名。
- 时间所在行高度至少为 `64dp`，不在其实际行区域之外另行扩大触控范围。
- 日期星期行高度为 `48dp`，文字垂直居中；完整行即为其可聚焦触控目标。

## 收藏区域

- 新安装时收藏为空，显示简洁的空状态，引导用户前往 Drawer 添加应用。
- 每个收藏只属于两个直接访问分组中的一个：主收藏或伴收藏。从 Drawer 新增的收藏默认归入主收藏，之后可以通过 Home 编辑模式在两组之间移动；新增收藏不会跳转到 Home，也不会进入编辑模式。
- 主收藏表示作者相对最高频的直接访问应用，占约 60% 的区域。
- 伴收藏仍是重要的直接访问应用，但相对使用频率低于主收藏，占约 40% 的区域。“伴收藏”不表示隐藏、禁用或可有可无。
- 从 Drawer 新增的收藏追加到主收藏。产品不因主收藏视口已经铺满而拒绝新增；溢出内容扩展主收藏的可滚动内容，并保持已有顺序。Avenor 不自动把条目放入伴收藏。
- 同一个可启动应用条目不能重复收藏。主应用与应用分身是不同条目，可以分别收藏。
- 主收藏与伴收藏必须在视觉上可以区分，但不能退化为两种普通列表密度。主收藏使用 `48dp × 48dp` 应用图标，并位于至少 `64dp × 64dp` 的交互目标中；伴收藏使用 `32dp × 32dp` 应用图标，并位于至少 `48dp × 48dp` 的交互目标中。
- 两组都展示一行应用名称。名称无法完整显示时使用末尾省略号并保持静止；Home 不使用跑马灯。
- 产品不根据当前视口为任一分组规定槽位上限。两组分别测量自身视口和内容范围：内容能够完整容纳时，该组不可滚动；内容超出视口时，该组独立纵向滚动，不改变另一组的位置或滚动状态。两组不得借用彼此的可见空间；收藏较少时保留未使用空间，不放大图标或间距。
- 图标形状和 badge 完全采用平台提供的呈现，并在 Home、Drawer 及相关应用界面中保持一致。
- 点击条目后立即启动应用，普通点击不产生震动，并抑制短时间内的重复启动。
- 长按条目时产生长按触觉反馈，并打开 [app-action-sheet.zh-CN.md](app-action-sheet.zh-CN.md) 定义的应用操作面板。
- 收藏点击与长按参与 [navigation.zh-CN.md](navigation.zh-CN.md) 定义的 Home 全域上滑仲裁。上滑取得手势所有权后，不得启动收藏、打开其操作面板或产生该收藏的长按反馈。
- 只有成功刷新应用清单，并确认应用已卸载、应用分身已删除或该可启动身份永久消失后，才自动删除对应收藏。
- 应用清单整体加载失败时，不得删除或隐藏任何已保存收藏。
- 应用仍存在但被停用时，保留其原有位置并展示为明确的禁用收藏。点击后不尝试正常启动，而是展示简短且已本地化的不可用 Toast；长按仍可用于适用的应用信息或管理操作。
- 出现临时启动失败时，保留收藏，展示简短且已本地化的错误 Toast，并刷新该条目状态。
- 后续成功刷新确认条目恢复可用时，在原位置恢复，不改变收藏顺序。

### 收藏持久化加载与失败

- 只有 Avenor 能够可靠解释完整的已存储收藏状态时，收藏持久化读取才算成功。无法读取或已损坏的结果不是空收藏列表，不得展示新安装时的正常空状态。
- 初次读取或用户请求的重试进行期间，收藏区域显示进度指示器和本地化文案 `正在加载收藏…`。不得同时展示收藏条目、空状态引导、错误图标或重试操作。
- 无法可靠读取状态时，收藏区域隐藏进度指示器，展示非交互的 `40dp` 错误图标、本地化文案 `无法加载收藏`，并提供独立的 `重试` 操作。
- 失败状态必须保留原始不可读数据，不得初始化、迁移、修复、清空、替换或以其他方式覆盖。进程重建和设备重启后不得把该失败重新解释为空列表。
- 失败或重试状态持续期间，所有添加收藏、取消收藏和编辑模式变更均为禁用状态。Home 时间日期、Home→Drawer 导航、Drawer 应用清单和应用启动继续可用。
- 选择重试后发起一次只读重新加载，将收藏区域切换为加载表现，并在本次尝试完成前禁用重复重试。重试不得写入、修复、迁移、清空或替换已存储收藏数据。
- 重试成功时，不执行额外写入，恢复准确可读的收藏状态及其顺序。可靠读取到空状态时，展示正常空状态引导并恢复收藏变更能力。
- 重试失败时，返回相同的持续失败表现，恢复重试操作，保留原始不可读数据，并继续禁用收藏变更。由于可见的收藏区域错误已经表达结果，不额外展示 Toast。用户可以再次重试。
- 新进程启动时执行一次正常初始读取。Avenor 不持续自动重试、轮询，也不以网络状态变化作为重试触发条件。任何其他安全读取触发条件均需技术验证，并且必须遵守相同的禁止写入边界。
- 如果检测到失败时收藏变更界面已经打开，则关闭该界面且不应用收藏变化。修复、导出、重置、备份和恢复行为需要后续产品决定与技术评估。

## 编辑模式

- 编辑模式从被选中收藏条目的启动器操作进入；只要能够为某个收藏打开该操作面板，编辑操作就可用。该操作使用“编辑”而不是“排序”命名，因为此模式同时支持顺序调整和分组归属调整。
- 编辑模式为每个收藏显示拖动柄。基础信息区、收藏构图区和底部预留区分别使用 [design-foundations.zh-CN.md](design-foundations.zh-CN.md) 定义的淡灰色、轻微透明、小圆角编辑表面。三个表面用于表达 Home 模块边界，不表示时间日期区或底部预留区可以编辑。
- 在同一组内拖动时调整该组内部顺序。拖入另一组时，以目标组的可见位置为目标：放到空位置时，将被拖动收藏移动到目标组；放到已有收藏的位置时，交换两个收藏的分组归属和位置。跨组操作不得删除、覆盖或取消收藏任何一个条目。
- 有效跨组拖动期间，目标位置提供与组内排序相同的实时让位或占位反馈；收藏进入预览位置时采用目标组的图标和交互目标规格。拖动接近任一溢出分组的起始或末端边缘时，自动滚动目标分组，使屏外已保存位置仍然可达。无效位置松手时返回最后一个有效位置，不改变已保存状态。
- 每次完成位置变化、跨组移动或跨组交换时提供一次短震动并立即保存；两个受影响条目都采用其最终所在分组的视觉规格。
- 系统 Back 是当前唯一退出编辑模式的渠道。退出时移除编辑表面和拖动柄，但不撤销已经完成的移动。
- 编辑表面和可见拖动柄共同表示当前处于编辑模式；当前不定义额外标题、横幅、完成按钮或退出操作。

- 从收藏拖动柄开始的拖动负责移动条目；在收藏分组内其他位置开始的纵向拖动，在该组存在溢出时滚动该组。编辑模式不换页，也不展开折叠分组。
- 松手后保留当前位置并立即保存。
- 编辑模式禁用 Home→Drawer 拖动；条目拖动、分组滚动和边缘自动滚动在编辑模式结束前保持手势所有权。

## 底部次级功能区

- 即使未来能力尚未定义，底部次级功能区仍保留 Home 安全可用高度的约 20%。
- 该区域不属于任一收藏分组的可见视口。底部区域为空时不得扩大任一分组，但两组都可以通过自身滚动内容保留更多收藏。
- 当前契约不为该区域定义内容、数据、选择、滚动、织带、分页或其他交互。横向织带或任何替代形式都需要后续作者决定，并更新适用的 Home 与导航契约。

### 编辑模式期间的应用清单变化

| 清单事件 | 当前行为 |
| --- | --- |
| 安装新应用 | 保持编辑模式；收藏不受影响 |
| 移除未收藏应用 | 保持编辑模式；收藏不受影响 |
| 收藏应用名称变化 | 原位置更新名称，保持编辑模式 |
| 收藏应用图标或平台 badge 变化 | 原位置更新，保持编辑模式 |
| 收藏应用被卸载 | 结束编辑模式、删除该收藏、保留此前已保存移动，并提示用户 |
| 已收藏应用分身被删除 | 结束编辑模式、删除该分身收藏、保留此前已保存移动，并提示用户 |
| 收藏应用被停用 | 结束编辑模式、在原保存位置保留为禁用收藏、保留此前已保存移动，并提示用户 |
| 收藏身份暂时无法确认 | 结束编辑模式、保留该条目和顺序等待刷新，并提示用户 |
| 完整应用清单加载失败 | 结束编辑模式、保留所有收藏及已保存顺序，并提示用户 |
| 收藏数量降低到两个以下 | 仍有至少一个收藏时保持编辑模式；没有收藏时退出 |

- 已确认收藏发生变化时，统一使用本地化提示：`收藏应用已发生变化，编辑模式已结束`。
- 应用清单或身份刷新失败时，统一使用本地化提示：`暂时无法更新应用状态，编辑模式已结束`。
- 上述两类消息均使用短 Toast 展示。

## 验收意图

- 空状态和已有收藏状态保持相同的固定 Home 结构。主收藏与伴收藏共同形成一个中部构图，横向层级大约遵循 60:40。分组内容能够容纳时保持静止，超出时各自独立滚动。
- 编辑模式之外，Home→Drawer 上滑在收藏区域按照滚动边界交接规则可用，并且可以从其他所有由 Avenor 管理的 Home 元素起始；不得同时产生元素的点击或长按操作。
- 平台提供 badge 时，主应用与应用分身保持可辨识；Avenor 自有的备用区分方式不在当前范围内。
- 同一进程内返回 Home 时保留有意义的列表状态；进程重建遵循 [navigation.zh-CN.md](navigation.zh-CN.md)。
- 不可读收藏状态必须与有效空列表保持可区分，不能通过收藏操作覆盖，并且能够通过成功的只读重试恢复，同时不阻断独立的应用发现与启动路径。

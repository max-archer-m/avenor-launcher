# Requirements Brief：产品基础与当前范围

> 本文先以中文整理作者输入，并提供英文公共版本：[product-foundation.md](product-foundation.md)。两份文档应保持语义一致。

## 问题

作者将 Android 手机作为绝对主力设备，常用三星和 Google 手机。每次进入主屏幕，或需要从主屏幕获取信息和寻找应用时，都会使用 Launcher；目前没有可靠的使用时长或次数统计。

作者偏好“自定义 Home 页 + 应用抽屉”的模式，但当前替代方案没有同时满足以下需求：

- 系统原生 Launcher 和同类产品通常采用列表或自由 Grid 网格来放置应用与 Widget。
- 高自由度方案虽然允许大量自定义，却缺少足以持续维持美观、舒适和极简结果的约束。
- 极简方案可能减少视觉噪音，但不一定符合作者希望的 Home 与 Drawer 组合及个人布局方式。

因此，作者希望建立一个首先满足自身长期日用需求、具有明确设计约束的 Android Launcher。

## 证据边界

### 已知事实与作者经验

- 作者长期使用 Android，并将其作为主力手机平台。
- 作者使用过系统原生桌面和多个第三方 Launcher 作为替代方案。
- 现阶段问题证据来自作者的持续使用体验和对自身需求的理解。
- 当前没有使用次数、任务耗时、访谈、外部用户反馈或市场研究数据。

### 待验证假设

- 有限且有意图的布局规则，可能比无限制自定义更容易持续形成美观、舒适且极简的日用桌面。
- 作者以外的 Android 用户是否存在相同需求尚未验证。
- 未来是否适合在 GitHub 或应用商店长期发布与维护尚未验证。

## 项目动机

- 产品动机：建立完全属于作者、能够长期日用的桌面工具。
- 学习动机：通过真实项目学习 Agent 体系，为 Agent 工程师或提示词工程师方向积累实践。

学习动机可以影响项目过程和复盘方式，但不能代替用户价值、产品验收或质量标准。

## 目标用户与使用场景

### 首要用户

作者本人。所有当前产品取舍首先以作者能否稳定日用为判断依据。

人体工学决策主要针对右手持机并以右手拇指操作，以及左手持机并以右手点控两种方式优化；其他操作姿势属于次要考虑，而非同等优化目标。

### 次要用户

当前没有明确的次要用户。未来上传 GitHub 或应用商店不代表已经验证了大众需求，也不扩大当前目标用户范围。

### 主要场景

- 进入 Android 默认主屏幕。
- 从 Home 进入 Drawer，找到并启动已安装应用。
- 进入 Settings，完成维持 Launcher 基础工具能力所必需的设置。
- 在设备无网络连接时继续完成上述核心任务。

具体使用频率、任务耗时和信息获取类型尚无统计。Settings 的当前设置项已在当前产品范围中定义。

## 产品目标

为作者提供一个可长期日用、完全本地化且遵循最少权限原则的 Android Launcher，通过 Home、Drawer 和 Settings 完成最基础的桌面工具任务。

当前产品范围覆盖工具属性，不覆盖视觉精修、丰富自定义能力、联网信息或大众市场适用性。

作者希望产品最终具有符合自身需求的个性化能力，并能够覆盖部分现有方案缺失或需要付费才能获得的能力。该方向目前属于作者期望和待验证假设，不代表已经完成市场对比，也不构成当前验收标准。

## 平台与交付边界

- 最低支持版本：Android 12（API 31）。
- 当前真实验证设备：Samsung Galaxy S23 Ultra（Android 16）和 Google Pixel 8（Android 17）。
- 最低版本验证环境：在取得有代表性的真实设备前，使用 Android 12/API 31 模拟器。
- 设备范围：普通 Android 手机，仅支持竖屏。
- 设备范围外：横屏、折叠屏、平板、桌面模式和外接显示器适配。
- 发行边界：维护 GitHub 项目供作者本人日用，不安排应用商店、GitHub Release APK、官网 APK 或其他公开分发。
- 应用商店目标 API、审核和数据披露要求不适用于当前发行边界；公开分发进入当前范围时必须重新审查。

Android 17 对应 API 37，依据 [Android 17 SDK 设置指南](https://developer.android.com/about/versions/17/setup-sdk)。Google Play 自 2026-08-31 起要求新应用和更新至少面向 Android 16（API 36），依据 [Google Play 目标 API 要求](https://developer.android.com/google/play/requirements/target-sdk)；该要求约束 `targetSdk`，不规定项目的 `minSdk`。本项目当前不发布到 Google Play，因此其目标 API 要求仅作为未来兼容参考。产品兼容边界要求 `minSdk` 为 31。对于 `1.0.0`，技术评估必须验证 `targetSdk` 36，并使用最新且兼容的稳定版 `compileSdk`；当前候选为 API 37，如果 API 37 仍要求预览版或候选发布版工具链，则保留 API 36。创建 Android 工程时，必须在构建配置中落实并验证最终选值。审查日期：2026-08-09。

## 当前产品范围

### 范围内

- Home：作为一个不可分页、不可折叠的 Android 默认主屏幕界面，展示系统时间、日期、收藏列表区、次级收藏区和进入 Drawer 的入口。Home 在平台 `safeDrawing` 边界内统一设置 `8dp` 内容 padding。页面本身不纵向滚动；收藏列表区当前最多包含两个地位相同的纵向列表，只有内容超出共享视口时才分别独立滚动。次级收藏区使用完整的已设置 padding 的 Home 内容宽度，位于收藏列表区下方并保持 `8dp` 纵向间距，没有内容时高度为零，最多包含五条分别独立横向滚动的收藏栏。
- Favorites：作者能够按照 Home 与应用操作面板规格维护最多两个纵向收藏列表和收藏栏中的应用条目。一个纵向列表使用完整的已设置 padding 的收藏列表区宽度；两个列表在扣除间距后平均分配该宽度。“大／中／小”是可选择并持久化的列表级展示值；所有新建或迁移列表初始使用“中”。
- 双击锁屏：用户明确启用 Avenor 用途受限的无障碍服务后，可以在 Home 基础信息区符合条件的空白位置请求系统锁屏操作。该服务属于可选能力，不阻断独立 Launcher 路径。
- Drawer：采用单列表展示从 Android 暴露来源中成功读取的全部可启动应用入口；平台能够暴露且 Avenor 成功读取时包含应用分身入口。非当前资料的局部读取失败不得阻断其他资料中已经可用的条目。
- Settings：展示当前默认 Launcher 状态，提供进入 Android 系统默认主屏幕应用设置的入口及次要产品信息入口。语言根据系统语言区域自动选择受支持资源；手动语言选择不在当前范围内。
- 核心任务在无网络时完整可用。
- 核心产品数据保存在本地，不依赖自建服务器、账号或云同步。
- 仅申请核心功能所必需且能够说明用途的系统权限。

### 范围外

- 以美观度为目标的视觉精修。
- Widget、文件夹式分组、Home 分页、主题，以及丰富或无限制的布局与视觉自定义。
- 一键清除或恢复全部本地配置。
- 天气等需要网络的数据功能。
- 账号、云同步或自建服务器。
- 行为分析、自动排序、推荐、AI 助手或 Agent 集成。
- Android Private Space 的访问、展示、管理、收藏和状态恢复，包括声明 `ACCESS_HIDDEN_PROFILES`。
- 商业模式验证、应用商店正式发布或大众市场适配。

“范围外”表示不属于当前产品契约，不代表永久拒绝。广告、推荐流及以延长停留时间为目标的设计仍受项目概览中的长期边界约束。

## 可叠加需求

可叠加需求可在实际需要时加入当前产品契约，但不定义也不阻塞能力层级之间的转换。横屏、折叠屏与平板适配、主题与颜色、天气信息和 Widget 属于当前候选。文件夹式分组与当前直接访问原则冲突，因此不属于候选。

可叠加需求不会仅因能够独立加入而自动成为当前范围，也不因“可随时加入”而免除范围、隐私、安全、验证和维护评估。

## 功能要求

- 用户能够把 Avenor Launcher 作为 Android 主屏幕入口启动。
- Home 显示来自设备系统的时间和日期。
- Home 显示作者保存在本地的收藏应用，并允许启动所选收藏应用。
- Home 在平台 `safeDrawing` 边界内统一设置 `8dp` 内容 padding，采用内容驱动的纵向尺寸，并在相邻且可见的模块之间使用 `8dp` 间距；Home 本身不纵向滚动。基础信息模块自身不增加 padding。时间行与日期行相对已设置 padding 的 Home 内容边界再增加 `8dp` start 和 end margin，因此行边界最终距对应安全边缘 `16dp`；时间行另增加 `8dp` top margin，使其最终距安全顶边 `16dp`。日期可见文字相对时间文字再增加 `8dp` start 内缩，因此最终距安全 start 边缘 `24dp`，但完整日期行热区仍位于 `16dp` 行边界。纵向收藏列表容器、收藏栏容器和单个收藏条目除 Home 统一内容 padding 外不再增加 padding。普通模式与编辑模式保持相同的模块和容器几何；编辑表面、边界和控件不再增加一层外侧缩进。基础信息区包裹必要内容和交互目标。收藏列表区与已有内容的次级收藏区自然高度能够放入剩余内容高度时，两者保持自然高度，收藏列表保持静止；两者总高度溢出时，次级收藏区保留收藏栏形成的自然高度，收藏列表区获得其上方剩余视口，只有溢出的列表在内部纵向滚动。次级收藏区使用完整的已设置 padding 的 Home 内容宽度，没有内容时高度为零。
- 次级收藏内容完全由用户定义，不按产品预设类型区分。当前写死上限为五条高 `56dp` 的横向收藏栏容器；收藏栏容器和条目均不增加 padding，收藏栏容器纵向间距为 `8dp`。每条收藏栏包含有限且由用户定义的应用序列：条目能够容纳时保持静止，溢出时横向滚动，且不循环。每个条目按内容测量，使用 `8dp` start 间距、纵向居中的 `40dp` 应用图标、`8dp` 图标名称间距、一行正常字重的静止 `16sp/24sp` 应用名称和 `8dp` trailing 间距；名称实测宽度最多为 `64dp`，因此条目最大宽度为 `128dp`。名称上限约等于当前字体缩放下四个全角中文字符的字宽，但所有语言均按渲染宽度而非字符数量判断；较长名称末尾省略，较短名称使条目相应收窄。该固定中等高度呈现不提供用户尺寸选择。条目左对齐，相邻间距 `8dp`，并使用已确认的浅色前景语义色 `6%` alpha 背景、同一语义色 `12%` alpha 的 `1dp` 边界、`12dp` 圆角和当前浅色 ripple。普通模式与编辑模式保持每个条目的计算宽度；编辑控件可以使名称更早省略，但不得扩展条目。点击条目启动对应应用，长按条目打开现有应用操作面板。编辑模式中，次级收藏模块使用共享编辑表面，每条收藏栏使用独立透明的 `1dp` 边界和条件式溢出边缘渐隐，每个条目显示共享的尾部拖动柄与物理左上角取消收藏角标。当前收藏栏不显示标题或预留标题高度；未来标题可见性主题设置不在本契约内。
- 每个已保存的可启动条目身份只能归入一个纵向收藏列表或一条收藏栏，并且在所有目标中最多出现一次。主应用、应用分身和工作资料条目继续作为不同身份处理，不得仅按包名去重。已经收藏的身份在编辑模式多选中不可选择；已有收藏可以按照全局容器拖动契约，在纵向列表和收藏栏之间移动或交换。
- 收藏列表区和每个纵向列表除 Home 统一内容 padding 外不再增加 padding。纵向列表形成物理从左到右的横向序列，在 RTL 语言环境下也不镜像，列表间距为 `8dp`。一个持久化列表占用已设置 padding 的收藏列表区完整宽度；两个持久化列表在扣除间距后平均分配该宽度，共享一个视口高度并独立滚动。持久化列表失去最后一个条目时立即删除，并重新计算剩余宽度。“大”使用 `48dp` 图标、`64dp` 目标和 `18sp/28sp` 名称；“中”使用 `40dp`、`56dp` 和 `16sp/24sp`；“小”使用 `32dp`、`48dp` 和 `14sp/20sp`。同一列表内尺寸统一；所有新建或迁移列表初始使用“中”，编辑模式尺寸控件可以分别为每个列表保存选定的“大／中／小”。收藏条目不增加 padding；图标使用 `16dp` start margin 并纵向居中，随后保持 `16dp` 图标名称间距。所有尺寸均使用正常字重、系统字体缩放和一行静止末尾省略名称。
- Drawer 操作面板新增仍默认把单个应用追加到物理位置最左侧的纵向收藏列表，不跳转 Home，也不进入编辑模式；没有列表时，以“中”尺寸创建一个列表。调整列表顺序会改变该默认目标。Home 编辑模式额外提供居中的本地化纯文本新增操作，使用前置文本`＋`，不使用独立图标资源或装饰容器；热区高度至少为 `48dp`，宽度足以容纳文案。每个持久化列表末尾和已有收藏栏显示`＋ 添加应用`；纵向列表少于两个时显示的临时列表使用`＋ 新建收藏列表`；收藏栏少于五条时显示的临时收藏栏使用`＋ 新建收藏栏`。完整文案是单一交互与无障碍目标，并为已记录目标打开 Drawer 多选；确认后按选择顺序追加条目，临时列表或收藏栏只有在至少确认一个条目时才持久化。可见视口已经铺满时仍然接受新增。
- Drawer 收藏多选会记录每个 Home 列表和收藏栏的滚动位置。普通取消在位置仍有效时准确恢复；期间发生可靠清单变化时，尽可能保留此前最靠顶部的可见身份及偏移，否则限制到最近有效位置。确认成功后对所有非目标采用同一规则；仅在需要时沿目标自身轴向执行最小滚动，使首个仍有效的新增条目完整可见，不强制起点对齐，也不增加高亮、Snackbar 或触觉反馈。新临时目标从内容起点展示；没有任何新增身份仍有效时不滚动目标。
- 编辑模式可以从收藏操作面板进入，也可以通过长按基础信息区符合条件的空白位置进入。该模式增加应用拖动柄、取消收藏角标、新增控件、收藏栏级固定控件和共享编辑表面。每个应用条目的取消收藏角标复用 X 图形资源，在条目左上角的 `20dp × 20dp` 实色 error 红色背景上显示白色 X。交互热区与可见控件共用 `20dp × 20dp` 边界，由 `8dp` 边缘间距与 `24dp` X 资源尺寸的一半组成，并作为作者明确批准的常规 `48dp` 最小值例外。每个应用条目拖动柄保留 `24dp` 可见图形，并将其居中放入贴合条目物理右侧边缘、宽 `40dp`、占满条目高度且没有 end margin 的热区；该宽度同样是作者批准的紧凑热区例外。收藏栏级拖动柄保留既有固定控制轨几何。所有应用、完整列表和完整收藏栏拖动都只能从对应拖动柄开始，并且必须先识别平台标准长按阈值。长按成立时产生一次平台标准 long-press 语义触觉反馈；只有此后的移动才创建并移动预览。长按成立前松手不执行操作，提前移动则取消拖动候选，并在所属视口可滚动时继续作为普通滚动。Home–Drawer 导航和非编辑模式滚动不采用此启动规则。同容器主体经过时立即交换并持久化，同容器间隙不插入；跨容器已有主体和间隙显示互斥的交换或插入反馈，并在有效松手时保存一次。跨容器预览在松手前保持尺寸，之后采用目标呈现。系统 Back 和 Android 系统 Home 操作都退出编辑模式；Android 系统 Home 操作还会取消活动中的 Drawer 多选并落到普通 Home。
- 应用拖动在当前有效应用视口内部使用 `48dp` 边缘区。稳定停留约 `120ms` 后，仅该容器沿自身轴向自动滚动，速度随触控点接近边缘而增加；离开边缘区、进入无效空白或固定控件、到达内容边界、取消或中断时停止。完整列表与完整收藏栏拖动不自动滚动。可用边缘淡入最高 `8%` 不透明度、不可交互的浅色前景渐变，并位于持续重新计算的插入和交换反馈下方；不可滚动方向不显示提示，滚动本身不增加触觉、箭头、文字、Ripple 或无障碍节点。
- 编辑模式取消单个应用收藏时立即持久化，并显示不阻断交互的长时 Snackbar，文案为`已取消收藏`，操作为`撤销`。只允许撤销当前可见 Snackbar 对应的最近一次移除。撤销恢复准确身份、目标、位置、列表尺寸，以及因变空而自动删除的列表或收藏栏。Snackbar 消失、发生后续移除、退出编辑模式、Android 系统 Home 操作、进程重建或离开 Avenor 时，丢弃该临时快照且不保留撤销历史。
- 每条可编辑持久化收藏栏包含固定的 `40dp × 56dp` 逻辑 start 删除控制轨、中部横向应用视口和固定的 `40dp × 56dp` 逻辑 end 排序控制轨。start 控制轨整体为删除热区，并把可见的 `24dp × 24dp` 实色 error 红底白色 X 水平居中，两侧各留 `8dp`。end 控制轨与应用条目拖动柄热区同宽，并以相同的横向间距居中放置可见 `24dp` 拖动柄。两侧控制轨均位于滚动内容之外，且不调整按内容测量、最大宽度为 `128dp` 的应用条目。只有一条持久化收藏栏时，隐藏排序呈现、交互、按压反馈和无障碍节点，但保留 `40dp` end 控制轨；至少两条时，每条都显示排序。临时收藏栏不提供任一收藏栏级操作。明确删除完整收藏栏时，先显示平台默认`删除收藏栏？` Dialog，包含解释正文、`取消`和破坏性的`删除`；Back 和点击外部取消且不修改。确认后持久化删除，并提供只保留最近一次操作的`已删除收藏栏`／`撤销`。收藏栏因最后一个应用离开而自动删除时不显示该 Dialog。
- 完整收藏栏排序使用拖动开始时整个可见收藏栏容器的冻结、不可交互静态布局预览，包括两侧高 `56dp` 的控制轨、可见的完整或局部条目、边界和适用边缘渐隐，并保持原宽度、`56dp` 容器高度、横向滚动状态和抓取偏移；源位置保留等大占位。手指触控点进入另一持久化收藏栏主体时立即交换并持久化顺序，同时产生一次短触觉步进；间隙不插入，无效松手或中断保留最后一次已保存交换。
- 每个持久化纵向列表在既有视口顶部具有固定的 `40dp` 高编辑模式控制栏。控制栏不设置 padding、填充、圆角整体表面、外边框或后续内容间距，只保留浅色前景语义色 `12%` alpha 的 `1dp` 下分隔线。三个相邻的 `40dp × 40dp` 热区无间隙贴合物理右侧，不在 RTL 环境下镜像，也不预留推测性的未来槽位；物理从右到左依次为调整列表顺序、尺寸、删除列表。临时列表没有控制栏，只有一个持久化列表时隐藏排序控件但保留最右侧 `40dp` 位置。删除控件居中显示 `24dp × 24dp` 实色 error 红底白色 X；尺寸内部只显示固定字号的本地化 `L/M/S` 或 `大/中/小` 当前值文字；排序居中显示 `24dp` 拖动柄。尺寸与排序没有常驻独立背景，并在自身热区内保留有界按压态；删除则调整红色状态。三个控件均不使用 Ripple。控制栏只将编辑模式应用视口缩小 `40dp`，不改变收藏区外部高度。
- 尺寸操作打开基于坐标锚定的深色 Material 单选菜单，通常以实际按钮为中心显示在其下方 `4dp`；需要时翻转至上方，或以至少 `8dp` 距离限制在安全内容边界内。该有限菜单不滚动或裁切。大、中、小三个条目统一高 `64dp`，保持不镜像的物理顺序：单选标记、以 `48dp/40dp/32dp` 显示的项目内 Android 默认通用图标资源、再到本地化标签。完整条目是一个 Ripple 和无障碍目标。选择后立即持久化并重新布局所属列表，保持此前最靠顶部的可见身份及有效偏移；点击外部、Back 或再次点击控件时关闭且不修改，持久化失败时恢复最近保存尺寸。
- 删除完整纵向列表时，必须显示 Android 默认样式 Dialog，包含`删除收藏列表？`、解释正文、`取消`和破坏性的`删除`；Back 和点击外部均取消且不修改。确认后持久化删除，并提供只保留最近一次操作的`已删除列表`／`撤销`，恢复物理位置、尺寸、完整成员和顺序。完整列表排序只能从其排序柄开始，使用当前可见列表视口的冻结静态预览和等大源占位；手指进入另一列表主体时立即交换并持久化物理位置，列表间隙不插入。
- 只有用户授权的 Avenor 无障碍服务已经启用时，在 Home 基础信息区符合条件的空白位置双击才请求一次系统锁屏操作。时间、日期星期、系统 inset、收藏和其他所有交互目标均不属于触发区域；授权缺失或撤销只影响该能力。
- 收藏持久化结果无法读取或已经损坏时，产品将其展示为可恢复的加载失败，而不是空收藏列表。Avenor 保留原始数据、禁用收藏变更，并在提供只读重试期间保持独立的 Drawer 与应用启动路径可用。
- 用户能够从 Home 访问 Drawer。
- Drawer 具有固定且透明的 `56dp` 顶部应用栏。普通模式只显示左侧 `24dp` 返回箭头及其 `48dp` 触控目标；中部未来搜索槽位和右侧保持视觉空白且不可交互。收藏多选模式改为显示取消、本地化目标说明和确认。
- 收藏多选按稳定身份实时协调应用清单且不中断该模式：新条目以未选状态出现，已选条目的名称或图标原位更新，资料临时不可用或局部读取失败时保留条目与选择。确认永久消失的身份会被静默移除并连续重排选择序号。点击确认时重新验证，并仅按显示顺序原子保存剩余有效身份；有效结果为空时不写入、不增加反馈并正常返回。保存失败时保留有效选择并显示现有更新失败反馈：可靠 Content 允许再次确认或取消；清单不可用时，必须先通过 Error 状态重试恢复 Content 才重新启用确认，期间仍可取消。已记录目标引用失效时取消完整选择，且不得改投其他目标；只有来源 Home 编辑上下文仍有效时，才携带现有失败反馈返回该上下文，已经结束或被替换的上下文不得重新创建。只要来源选择会话和 Home 编辑上下文仍有效、并且适用容器上限允许创建，临时目标就保持为有效创建意图；不得仅因尚无持久化容器而使其失效。
- Drawer 收藏多选复用应用清单、排序、应用条目、应用锚点和 AlphabetIndex，同时隐藏 Settings。顶部中间文案区分添加与创建、纵向列表与收藏栏，但不为容器建立持久名称或序号。每行固定预留 `40dp` 前置区域并居中显示 `24dp` 指示器：可选且未选中时为透明内部和 `1dp` outline 圆形；选中后以浅色角色填充、使用深色 `14sp/20sp` 显示从一开始的序号，并为整行增加 `8%` 浅色背景。已经收藏且不可选择的条目保留空心指示器并使用 disabled 内容透明度，点击无响应。完整行仍是唯一的切换选择交互和无障碍目标，并报告未选中、已选序号或已收藏禁用状态。确认提交完整有序选择；取消、Back、下滑退出和 Android 系统 Home 操作都会丢弃选择，但已经开始的原子保存除外。
- 有效确认会启动一次独占原子保存。结果返回前保持选择可见，禁用确认，并使取消、条目选择、AlphabetIndex、下滑退出和 Back 均无操作；不增加 Loading 或进度表现。应用清单变化等待保存后协调。成功只过渡一次；失败恢复交互，保留当前有效选择以供重试，并显示现有失败反馈。Android 系统 Home 操作可以把 Avenor 切到后台但不取消保存；最终成功继续持久化，失败时回到最后一次成功持久化状态且不声称成功。
- 收藏多选复用 Drawer 的 Loading 与 Error 状态，同时保留取消和目标上下文。Loading 不显示条目、Settings 或 AlphabetIndex，并禁用确认。完整 Error 保留内存中的有序选择、隐藏不可靠条目、禁用确认，并允许只读单次重试或普通取消，不重复反馈。重试成功根据最新可靠清单协调选择顺序和最近有效位置；重试失败返回同一 Error。可靠清单中全部条目均已收藏时，保持带 AlphabetIndex 的 disabled Content；可靠清单没有可启动条目时使用既有 Error，不新增 Empty。独占保存期间的清单失败等待保存结果。
- 无论 Avenor Launcher 是否已设为默认主屏幕，Drawer 都采用单列表展示从 Android 在 Avenor 当前角色与最小权限边界下正常暴露的可见且可启动来源中成功读取的全部应用入口，并允许启动所选入口。
- 非当前资料无法读取、但其他资料仍提供可用条目时，Drawer 继续展示并允许启动已有条目，不崩溃，也不以全界面 Error 替换可用内容。当前产品不要求提供部分读取失败提示。
- 当 Android 平台向 Launcher 暴露应用分身入口时，Drawer 将其作为独立的可启动入口展示，不得仅按包名去重。
- Android 无需隐藏资料访问即可暴露的普通、工作资料和克隆可启动条目继续属于当前范围。需要 `ACCESS_HIDDEN_PROFILES` 的 Private Space 条目不属于当前产品范围。
- Launcher 为所有用户可见文案提供英文和简体中文资源，根据系统语言区域自动选择，不支持的语言区域回退为英文。
- 用户能够从 Settings 打开 Android 系统的默认主屏幕应用设置。
- 当前产品不提供一键清除或恢复全部本地配置；用户通过具体设置项修改配置。
- Home、Drawer 和 Settings 的核心路径不得依赖网络、账号、云同步或自建服务器。
- 未来若增加天气等联网能力，其不可用、未授权或断网状态不得阻断核心路径。

## 非功能要求

- **本地优先：** 当前产品状态和核心数据保存在设备本地。
- **离线可用：** 无网络时，Home、Drawer、应用启动和核心 Settings 仍可使用。
- **最少权限：** 每项权限必须对应当前核心能力，并记录用途、触发时机、拒绝行为和渠道政策影响。
- **无障碍服务最小化：** 可选双击锁屏服务不是无障碍工具，不请求读取窗口内容，不为产品行为或分析观察其他应用界面，并且除用户明确触发的系统锁屏请求外不执行其他全局操作。不以设备管理员作为回退方案。
- **可见性最小化：** 当前产品只要求发现并启动 Android 在 Avenor 当前角色与最小权限边界下正常暴露的应用入口；无限制访问全部已安装包数据不属于当前范围。Avenor 不声明 `ACCESS_HIDDEN_PROFILES`，也不把可见性扩展至 Android Private Space。具体 API 以及其他必要的清单声明或权限由技术与隐私审查决定。
- **可靠性：** 当前产品必须支持作者在真实主力设备上持续日常使用；具体稳定性门槛待确认。
- **兼容性：** 支持 Android 12/API 31 至 Android 17/API 37 的普通手机竖屏环境。在 API 31 模拟器上验证最低边界，并至少在已记录的 API 36 和 API 37 两台真实设备上验证主要日用行为。

## 验收标准

- Given Avenor Launcher 已在支持的 Android 设备上设为主屏幕应用，when 用户执行回到主屏幕的系统操作，then 系统显示 Avenor Launcher 的 Home。
- Given 用户进入 Home，when 系统完成基础内容加载，then Home 显示系统时间、日期、已保存的收藏应用和 Drawer 入口。
- Given 用户长按基础信息模块中符合条件的空白位置，when 长按得到识别，then Avenor 产生长按反馈并进入 Home 编辑模式，不同时请求双击锁屏或打开 Drawer。
- Given 次级收藏区存在内容，when Home 展示该区域，then 该区域展示最多五条高 `56dp` 且间距 `8dp` 的横向收藏栏容器；容器和条目均不增加 padding，其中包含由用户定义、按内容测量且不按产品预设类型分组的可启动应用条目。每个条目采用 `8dp` start 间距、`40dp` 图标、`8dp` 图标名称间距、最多 `64dp` 的名称实测宽度和 `8dp` trailing 间距，最大宽度为 `128dp`；短名称使条目收窄，长名称末尾省略。条目左对齐且间距为 `8dp`，点击启动应用，长按打开现有应用操作面板，每条收藏栏的横向滚动在明确首项和末项停止且不循环。
- Given 某个稳定可启动条目身份已经归入任一收藏目标，when Avenor 呈现收藏状态，then 该身份不得再次出现在同一或其他列表或收藏栏；具有不同稳定身份的主应用、应用分身或工作资料条目仍可独立归属。
- Given 用户从 Drawer 新增收藏，包括最左侧列表可见视口已经铺满的情况，when 新增操作执行，then Avenor 将其追加并保存到当前物理位置最左侧的纵向收藏列表、必要时以“中”尺寸创建一个列表、关闭操作面板、保留 Drawer 位置，且不跳转 Home 或进入编辑模式。
- Given Home 编辑模式已经生效，when 用户点击持久化列表、临时列表、已有收藏栏或临时收藏栏的新增控件，then Drawer 完成向上过渡，以多选模式展示并记录该明确目标。
- Given 用户已经在 Drawer 多选中选择应用，when 用户确认，then Avenor 按照显示的选择序号顺序将其一次性追加到已记录目标、返回同一个 Home 编辑模式、保留所有非目标滚动位置，并在需要时最小滚动以显示首个仍有效的目标新增条目；只有至少确认一个条目时才创建临时列表或临时收藏栏对应的正式目标。
- Given 普通 Home 中存在一个纵向收藏列表，when Home 展示收藏列表区，then 该列表在列表和区域均无 padding 的情况下使用全部可用宽度；given 存在两个列表，then 两者在扣除 `8dp` 列表间距后平均分配宽度，列表和区域同样均无 padding。
- Given 某个纵向收藏列表失去最后一个条目，when 该变更完成，then Avenor 删除该列表，并立即按照剩余持久化列表数量重新分配收藏列表区。Given 某条收藏栏失去最后一个应用条目，when 移除、移动或应用清单协调完成，then Avenor 删除该收藏栏，不保留空容器。
- Given Home 编辑模式已经生效，when 展示任一收藏，then 条目左上角显示 `20dp × 20dp` 实色 error 红底、白色 X 的取消收藏控件及作者批准的同尺寸热区，并在尾部显示居中的 `24dp` 拖动柄及其独立、贴合物理右侧边缘、占满条目高度、宽 `40dp` 且没有 end margin 的热区；两者不得重叠，普通启动和长按操作在编辑模式结束前不可用。
- Given 用户点击收藏的取消收藏角标，when 移除已经保存，then Avenor 立即移除该条目，并显示包含`已取消收藏`和`撤销`的 Snackbar；when 用户在 Snackbar 消失前点击撤销，then 准确条目及任何自动删除的容器恢复至原目标和位置。
- Given 撤销 Snackbar 正在显示，when 用户又移除一个收藏、Snackbar 消失、编辑模式结束、发生 Android 系统 Home 操作、进程重建或离开 Avenor，then 丢弃此前临时快照，且无法通过撤销历史恢复。
- Given Home 编辑模式展示持久化纵向列表，when 顶部控制栏出现，then 控制栏只显示 `1dp` 下分隔线，三个相邻的 `40dp × 40dp` 热区贴合物理右侧，并按物理从右到左的排序、尺寸、删除顺序排列。只有存在两个持久化列表时显示排序，隐藏时仍保留其最右侧位置；临时列表没有控制栏，RTL 不镜像这些位置。
- Given 用户点击列表尺寸控件，when 锚定菜单打开，then 它使用控件当前屏幕坐标，避让安全 inset 和边界且不移动 Home，使用三个完整条目热区，以单选标记—图标—文字顺序展示真实 `48dp/40dp/32dp` 的本地默认图标预览，并通过不只依赖颜色的方式标记当前值。
- Given 应用拖动在可滚动收藏视口的有效 `48dp` 边缘区内停留约 `120ms`，when 对应方向仍有更多内容，then 仅当前有效容器以随边缘接近程度增加的速度自动滚动，并在持续重新计算的插入或交换反馈下方显示局部浅色前景边缘提示；离开触发区或到达边界时同时停止滚动和提示。
- Given 用户选择另一列表尺寸，when 持久化成功，then 菜单关闭，整个所属列表不带缩放动画或额外反馈地重新布局一次，保留此前最靠顶部的可见身份及有效偏移，且不改变另一列表；选择当前值或关闭菜单时不写入。
- Given 用户触发删除列表，when 平台默认 Dialog 正在显示，then Home 编辑被阻断，且取消、Back 或点击外部只关闭弹窗而不修改；when 用户确认`删除`，then 完整列表被持久化删除，并可通过`已删除列表`／`撤销`恢复其物理位置、尺寸、成员和顺序。
- Given 用户按下可见的列表级排序柄，when 尚未识别平台标准长按阈值，then 只改变容器不透明度，不显示 Ripple、缩放、闪烁、动画阴影、预览或拖动触觉；松手不执行操作，移动则取消拖动候选。Given 长按成立，then 恰好一次平台标准 long-press 语义触觉反馈让拖动所有权进入就绪状态，但不创建预览；when 此后开始移动，then Avenor 冻结当前可见列表视口为不可交互预览，同时保留等大源占位。
- Given Drawer 多选中存在未确认条目，when 用户点击取消、按 Back 或完成有效下滑退出，then Avenor 丢弃全部选择、返回 Home 编辑模式，并把每个 Home 容器准确恢复到进入前的滚动位置；when 发生 Android 系统 Home 操作，then 同时退出编辑模式、显示普通 Home，且不保留临时编辑视口。
- Given Drawer 收藏多选正在进行，when 可靠清单确认某个已选身份永久消失，then 静默移除该行并连续重排后续选择序号；新条目、元数据更新、资料临时不可用或局部读取失败都不打断该模式，也不增加反馈。
- Given Drawer 收藏多选展示应用条目，when 条目可选且未选中，then 固定前置区域显示空心圆；when 用户点击完整条目选中，then 圆形填充并显示从一开始的序号，整行增加选中背景，且不产生第二个交互或无障碍目标；已经收藏的条目保持可见禁用，点击无操作。
- Given 有效确认启动保存，when 原子操作尚未返回，then 除 Android 系统 Home 操作外，重复确认及所有 Drawer 多选交互均无操作，且不显示 Loading；when 保存成功，then 只执行一次向下返回；when 保存失败且可靠清单仍可用，then 恢复交互和当前有效有序选择，以既有失败反馈允许再次确认；when 清单仍不可用，then Error 保留该选择，并要求清单重试成功后才恢复确认。
- Given 收藏多选在清单 Loading 时打开，或后续失去全部可靠清单，when 展示该非 Content 状态，then 保留取消和目标上下文、禁用确认、隐藏条目、Settings 与 AlphabetIndex，并由 Error 在内存中保留有序选择，以供只读重试或取消，不把身份视为永久消失。
- Given 重试恢复可靠清单，when 多选 Content 返回，then 仍有效选择保持顺序，已确认消失身份静默移除并重排，临时不可用身份保持选择，且此前位置恢复或限制到最近有效位置，不显示成功反馈；given 可靠条目均已收藏，then 保持 disabled Content 与 AlphabetIndex，不显示 Empty 或 Error。
- Given 用户确认经过重新验证的选择，when 仍有有效身份，then Avenor 只按显示顺序原子保存这些身份；when 持久化失败，then Drawer 保留选择以供重试或取消，并显示现有更新失败反馈；given 评估已记录的目标引用，then 来源会话仍有效且容器上限允许创建的临时意图无需持久化容器也保持有效；已删除的持久化目标，或者上下文结束、被替换或不再允许创建的临时目标，会取消完整选择而不改投其他目标。
- Given 收藏列表内容能够完整容纳，when 用户在该列表内拖动，then 该列表不滚动且上滑可以进入 Drawer 过渡；given 内容存在溢出，then 该列表先滚动，并仅在到达末端后把同一手势的剩余偏移量转交给 Drawer 过渡。
- Given 用户在某个纵向列表或收藏栏内部拖动应用，when 触控点进入另一应用主体，then Avenor 立即交换并持久化两个位置；同容器间隙不插入，后续无效松手保留最后一次成功保存的交换。
- Given 用户把应用拖入另一纵向列表或收藏栏，when 触控点进入已有应用主体，then Avenor 只显示交换反馈；有效松手保存双方身份的目标和位置，不丢失或重复条目。
- Given 用户把应用拖入另一纵向列表或收藏栏，when 触控点进入第一项之前、条目之间、最后一项之后或空临时目标的有效边界，then Avenor 只显示插入线；有效松手保存一次插入、保持目标相对顺序、采用目标呈现，并在源容器变空时删除源容器。
- Given 编辑模式中存在持久化收藏栏，when 展示收藏栏控件，then 两侧相同的 `40dp × 56dp` 控制轨保持固定，start 轨把 `24dp × 24dp` 实色 error 红色删除样式水平居中且两侧各留 `8dp`，end 轨以相同间距居中放置 `24dp` 排序柄。Given 只有一条持久化收藏栏，then end 控制轨继续占位，但不提供排序图形、交互、按压反馈或无障碍节点；given 至少存在两条，then 每条都提供排序，临时收藏栏不提供任一收藏栏级操作。
- Given 用户触发删除收藏栏，when 平台默认 Dialog 正在显示，then Home 编辑被阻断，且取消、Back 或点击外部只关闭而不修改；when 用户确认`删除`，then 完整收藏栏被持久化删除，并可通过只保留最近一次操作的`已删除收藏栏`／`撤销`恢复位置、成员和应用顺序。
- Given 用户按下收藏栏可见的固定排序柄，when 在长按成立前开始移动，then Avenor 取消拖动候选、不创建预览，并在可用时保留普通横向滚动。Given 平台标准长按成立，then Avenor 恰好产生一次平台标准 long-press 语义触觉反馈，让拖动所有权进入就绪状态但不创建预览；when 此后开始移动，then Avenor 把当前完整可见收藏栏窗口冻结为不可交互预览并保留等大源占位。When 手指进入另一持久化收藏栏主体，then Avenor 高亮目标，立即交换并持久化两条收藏栏的位置，产生一次短移动触觉步进，且收藏栏间隙不插入。
- Given 存在两个纵向收藏列表，when 列表级预览对应的手指触控点进入另一列表主体，then Avenor 高亮完整目标，立即交换并持久化物理左右顺序，产生一次短移动触觉反馈，并把 Drawer 默认新增目标改为新的最左侧列表；列表间隙不插入。
- Given 活动拖动被 Back 或 Android 系统 Home 操作中断，或者在无效 Home 区域松手，then Avenor 移除未保存的预览和反馈，并恢复最近一次成功持久化状态，但不撤销已经即时保存的同容器交换；Android 系统 Home 操作还会落到普通 Home。
- Given 无障碍服务已经启用，when 用户完全在基础信息区符合条件的空白位置内完成有效双击，then Avenor 请求一次系统锁屏操作；given 服务未启用或已经撤销，then 该手势不执行操作，且所有独立 Launcher 路径保持可用。
- Given 收藏持久化状态无法可靠读取，when Home 展示收藏区域，then 明确区分失败与空列表、保留原始数据、禁用收藏写入、提供只读重试，并保持 Drawer 应用发现和应用启动可用；when 重试失败，then 恢复相同的内联错误，不额外展示 Toast，也不覆盖数据。
- Given 用户位于 Home，when 用户执行已定义的 Drawer 入口操作，then Drawer 以单列表显示从 Android 暴露来源中成功读取的可启动应用入口。
- Given Avenor Launcher 未设为默认主屏幕，when 用户直接启动 Avenor Launcher 并进入 Drawer，then Drawer 仍显示从 Android 平台规则下应当可见且可启动的来源中成功读取的全部应用入口。
- Given 非当前资料读取失败、但其他资料提供可用条目，when Drawer 展示应用清单，then 可用条目保持可见且可启动，不发生崩溃或全界面 Error；失败资料中的条目可以缺失，且不要求提供部分读取失败提示。
- Given Android 向 Launcher 暴露同一应用的分身入口，when Drawer 展示应用列表，then 每个分身入口均独立出现并可启动。
- Given 某个条目需要通过 `ACCESS_HIDDEN_PROFILES` 访问 Android Private Space，when Avenor 构建 Drawer 应用清单，then Avenor 不申请该权限、不访问或展示该条目、不创建 Private Space 独立容器，也不提供 Private Space 显示、隐藏、锁定、解锁、收藏或状态恢复行为。
- Given Drawer 中存在可启动应用，when 用户选择其中一个应用，then 系统启动所选应用。
- Given 系统语言区域为英文或简体中文，when Avenor 展示或刷新界面，then 使用对应资源；given 其他语言区域，then 使用英文回退资源。
- Given 用户进入 Settings，when 用户选择默认主屏幕应用设置入口，then 系统打开对应的 Android 设置页面。
- Given 设备无网络连接，when 用户访问 Home、Drawer、启动应用或使用核心 Settings，then 核心任务仍能完成。
- Given 某项非核心联网能力不可用或未获得授权，when 用户执行核心任务，then 该能力不会阻断 Home、Drawer、应用启动或核心 Settings。
- Given 当前产品考虑使用系统权限，when 进行需求与渠道审查，then 每项权限均能追踪到必要的核心能力和拒绝后的行为。

## 成功判断与护栏

### 已确认方向

- 当前产品的核心成功含义是：Home、Drawer 和 Settings 已形成能够支持作者持续日常使用的最小工具闭环。
- 完成开发本身不能作为唯一成功证明，必须在作者的真实主力设备上观察使用结果。
- 成功判断以作者本人的日用体验为依据，不把未收集的外部用户意见当作验收证据。
- 核心路径不得发生由 Avenor Launcher 引起的崩溃或无响应。
- Drawer 不得遗漏、重复或错误展示从 Android 来源中成功读取的条目。非当前资料发生局部读取失败时，其中的条目可以缺失，但不得阻断其他可用条目。
- 用户选择应用后必须正确启动目标应用。
- 本地配置不得意外丢失或损坏。
- 权限被拒绝时，只能降级依赖该权限的能力，不得阻断其他核心任务。
- 设备离线时，Home、Drawer、应用启动和核心 Settings 必须保持可用。

性能、功耗、内存和启动响应的最低可接受水平将在质量基线中另行定义，不属于本产品基础基线的完成条件。

## 用户控制

当前产品允许用户维护 Home 的收藏应用并使用独立 Settings 入口，但不提供一键清除、导出、云端删除或恢复全部配置。用户可以通过 Android 系统清除应用数据。收藏变化必须由明确的用户操作触发；语言呈现跟随系统语言区域，不根据已观察行为自适应。

## 本地数据边界

- 唯一的持久用户内容数据是 Home 收藏的可启动应用入口，以及它的纵向列表或收藏栏目标和用户定义位置。每个纵向列表具有稳定成员、顺序和一个“大／中／小”列表级呈现值；每条收藏栏在次级收藏区中具有稳定顺序，每个次级收藏在所属收藏栏内具有一个位置。每个稳定条目身份只有一个收藏目标，不得跨列表或收藏栏重复；入口标识必须足以区分平台暴露的主应用、应用分身和工作资料条目，不得只按包名存储或去重。最近一次编辑模式移除快照属于临时撤销状态，不属于持久撤销历史。
- 从系统语言区域得出的语言呈现和当前产品契约中的其他界面设置属于本地行为，不属于行为分析数据。
- 时间和日期直接来自设备系统，不作为历史数据保存。
- 当前产品不采集或保存无障碍窗口内容或事件、通知、联系人、位置、剪贴板、文件、照片、稳定设备标识、应用使用历史或分析事件。
- 当前产品不建立账号、云同步、服务器、云备份或跨设备备份。在后续经作者批准的恢复契约另有定义前，Avenor 自有收藏数据禁用 Android 云备份和设备到设备迁移备份。

## 依赖与风险

- Android 默认主屏幕角色、应用枚举方式、应用分身可见性及相关清单声明/权限尚未完成技术与隐私核实。
- 未来支持 Android Private Space 必须作为作者批准的独立产品能力，并重新审查交互、权限、隐私、兼容性和验证范围；技术实现中的发现不会使其进入当前范围。
- Settings 包含当前默认 Launcher 状态、系统默认主屏幕设置入口，以及 Settings 交互规格定义的产品信息入口。手动选择应用语言不在当前范围内。
- 当前证据只代表作者本人，不能支持大众市场需求结论。
- “美观、舒适且极简”尚未转化为可观察标准，也不属于当前验收目标。
- 以学习 Agent 体系为项目动机可能诱发超出产品需要的流程或技术复杂度，应通过范围变更机制控制。

# Requirements Brief：产品基础与首个里程碑

> 本文先以中文整理作者输入，并提供英文公共版本：[product-foundation.md](product-foundation.md)。两份文档应保持语义一致。
>
## 问题

作者将 Android 手机作为绝对主力设备，常用三星和 Google 手机。每次进入主屏幕，或需要从主屏幕获取信息和寻找应用时，都会使用 Launcher；目前没有可靠的使用时长或次数统计。

作者偏好“自定义 Home 页 + 应用抽屉”的模式，但当前替代方案没有同时满足以下需求：

- 系统原生 Launcher 和同类产品通常采用列表或自由 Grid 网格来放置应用与 Widget。
- 高自由度方案虽然允许大量自定义，却缺少足以持续维持美观、舒适和极简结果的约束。
- 极简方案可能减少视觉噪音，但不一定符合作者希望的 Home 与 Drawer 组合及个人布局方式。

因此，作者希望建立一个首先满足自身长期日用需求、具有明确设计约束的 Android Launcher。

## 证据边界

### 已知事实与作者经验

- 作者长期使用 Android，并将其作为主力手机平台。
- 作者使用过系统原生桌面和多个第三方 Launcher 作为替代方案。
- 现阶段问题证据来自作者的持续使用体验和对自身需求的理解。
- 当前没有使用次数、任务耗时、访谈、外部用户反馈或市场研究数据。

### 待验证假设

- 有限且有意图的布局规则，可能比无限制自定义更容易持续形成美观、舒适且极简的日用桌面。
- 作者以外的 Android 用户是否存在相同需求尚未验证。
- 未来是否适合在 GitHub 或应用商店长期发布与维护尚未验证。

## 项目动机

- 产品动机：建立完全属于作者、能够长期日用的桌面工具。
- 学习动机：通过真实项目学习 Agent 体系，为 Agent 工程师或提示词工程师方向积累实践。

学习动机可以影响项目过程和复盘方式，但不能代替用户价值、产品验收或质量标准。

## 目标用户与使用场景

### 首要用户

作者本人。所有首版取舍首先以作者能否稳定日用为判断依据。

### 次要用户

当前没有明确的次要用户。未来上传 GitHub 或应用商店不代表已经验证了大众需求，也不扩大首个里程碑的目标用户范围。

### 主要场景

- 进入 Android 默认主屏幕。
- 从 Home 进入 Drawer，找到并启动已安装应用。
- 进入 Settings，完成维持 Launcher 基础工具能力所必需的设置。
- 在设备无网络连接时继续完成上述核心任务。

具体使用频率、任务耗时和信息获取类型尚无统计。Settings 的最低设置项已在首个里程碑范围中确认。

## 产品目标

为作者提供一个可长期日用、完全本地化且遵循最少权限原则的 Android Launcher，通过 Home、Drawer 和 Settings 完成最基础的桌面工具任务。

首个里程碑验证工具属性，而不是视觉完成度、丰富自定义能力、联网信息或大众市场适用性。

作者希望产品最终具有符合自身需求的个性化能力，并能够覆盖部分现有方案缺失或需要付费才能获得的能力。该方向目前属于作者期望和待验证假设，不代表已经完成市场对比，也不构成 V1 验收标准。

## 平台与交付边界

- 最低版本：Android 16（API 36）。
- 目标版本：Android 17（API 37）。
- 当前真实验证设备：Samsung Galaxy S23 Ultra（Android 16）和 Google Pixel 8（Android 17）。
- V1 设备范围：普通 Android 手机，仅支持竖屏。
- V1 不支持：横屏、折叠屏、平板、桌面模式和外接显示器适配。
- V1 交付方式：维护 GitHub 项目供作者本人日用，不安排应用商店、GitHub Release APK、官网 APK 或其他公开分发。
- 应用商店目标 API、审核和数据披露要求不是 V1 初始门禁；决定公开分发时必须重新审查。

Android 17 对应 API 37，依据 [Android 17 SDK 设置指南](https://developer.android.com/about/versions/17/setup-sdk)。Google Play 自 2026-08-31 起要求新应用和更新至少面向 Android 16（API 36），依据 [Google Play 目标 API 要求](https://developer.android.com/google/play/requirements/target-sdk)；该要求约束 `targetSdk`，不规定项目的 `minSdk`。本项目选择 Android 16 作为最低版本，是基于作者真实设备和降低早期兼容维护成本的产品决定。本项目当前不发布到 Google Play，因此其目标 API 要求仅作为未来兼容参考。实际 `compileSdk`、`targetSdk` 和 `minSdk` 仍须在工程初始化时由构建配置落实并验证。审查日期：2026-08-07。

## 首个里程碑范围

### 范围内

- Home：作为 Android 默认主屏幕入口，展示系统时间、日期、收藏应用和进入 Drawer 的入口。
- Favorites：作者能够维护 Home 展示的收藏应用；具体编辑交互在垂直切片中定义。
- Drawer：初始采用单列表展示 Android 平台暴露的全部可启动应用入口；平台能够暴露时必须包含应用分身入口。
- Settings：提供语言选择和进入 Android 系统默认主屏幕应用设置的入口。
- 核心任务在无网络时完整可用。
- 核心产品数据保存在本地，不依赖自建服务器、账号或云同步。
- 仅申请核心功能所必需且能够说明用途的系统权限。

### 范围外

- 以美观度为目标的视觉精修。
- Widget、文件夹、主题，以及丰富或无限制的布局与视觉自定义。
- 一键清除或恢复全部本地配置。
- 天气等需要网络的数据功能。
- 账号、云同步或自建服务器。
- 行为分析、自动排序、推荐、AI 助手或 Agent 集成。
- 商业模式验证、应用商店正式发布或大众市场适配。

“范围外”表示不属于首个里程碑，不代表永久拒绝。广告、推荐流及以延长停留时间为目标的设计仍受项目概览中的长期边界约束。

## 可叠加需求

可叠加需求可以在实际需要时交付，但不定义也不阻塞 V1、V2 及后续能力层级之间的转换。横屏、折叠屏与平板适配、主题与颜色、天气信息、Widget 和文件夹属于当前候选。

可叠加需求不会仅因能够独立加入而自动成为当前范围，也不因“可随时加入”而免除范围、隐私、安全、验证和维护评估。

## 功能要求

- 用户能够把 Avenor Launcher 作为 Android 主屏幕入口启动。
- Home 显示来自设备系统的时间和日期。
- Home 显示作者保存在本地的收藏应用，并允许启动所选收藏应用。
- 用户能够从 Home 访问 Drawer。
- 无论 Avenor Launcher 是否已设为默认主屏幕，Drawer 都采用单列表展示 Android 平台规则下应当对 Launcher 可见且可启动的全部应用入口，并允许用户启动所选入口。
- 当 Android 平台向 Launcher 暴露应用分身入口时，Drawer 将其作为独立的可启动入口展示，不得仅按包名去重。
- 用户能够在 Settings 中选择跟随系统、英文或简体中文。
- 用户能够从 Settings 打开 Android 系统的默认主屏幕应用设置。
- 首个里程碑不提供一键清除或恢复全部本地配置；用户通过具体设置项修改配置。
- Home、Drawer 和 Settings 的核心路径不得依赖网络、账号、云同步或自建服务器。
- 未来若增加天气等联网能力，其不可用、未授权或断网状态不得阻断核心路径。

## 非功能要求

- **本地优先：** 首个里程碑的产品状态和核心数据保存在设备本地。
- **离线可用：** 无网络时，Home、Drawer、应用启动和核心 Settings 仍可使用。
- **最少权限：** 每项权限必须对应当前核心能力，并记录用途、触发时机、拒绝行为和渠道政策影响。
- **可见性最小化：** V1 只需要发现和启动 Android 暴露给 Launcher 的应用入口，不把不受限制地读取全部已安装包数据纳入当前范围；具体 API、清单声明和权限由后续技术与隐私审查决定。
- **可靠性：** 首个里程碑必须支持作者在真实主力设备上持续日常使用；具体稳定性门槛待确认。
- **兼容性：** 支持 Android 16/API 36 至 Android 17/API 37 的普通手机竖屏环境，并至少在已记录的两台真实设备上验证。

## 验收标准

- Given Avenor Launcher 已在支持的 Android 设备上设为主屏幕应用，when 用户执行回到主屏幕的系统操作，then 系统显示 Avenor Launcher 的 Home。
- Given 用户进入 Home，when 系统完成基础内容加载，then Home 显示系统时间、日期、已保存的收藏应用和 Drawer 入口。
- Given 用户位于 Home，when 用户执行已定义的 Drawer 入口操作，then Drawer 以单列表显示 Android 暴露的可启动应用入口。
- Given Avenor Launcher 未设为默认主屏幕，when 用户直接启动 Avenor Launcher 并进入 Drawer，then Drawer 仍显示 Android 平台规则下应当可见且可启动的全部应用入口。
- Given Android 向 Launcher 暴露同一应用的分身入口，when Drawer 展示应用列表，then 每个分身入口均独立出现并可启动。
- Given Drawer 中存在可启动应用，when 用户选择其中一个应用，then 系统启动所选应用。
- Given 用户进入 Settings，when 用户选择跟随系统、英文或简体中文，then Launcher 使用对应语言规则显示界面。
- Given 用户进入 Settings，when 用户选择默认主屏幕应用设置入口，then 系统打开对应的 Android 设置页面。
- Given 设备无网络连接，when 用户访问 Home、Drawer、启动应用或使用核心 Settings，then 核心任务仍能完成。
- Given 某项非核心联网能力不可用或未获得授权，when 用户执行核心任务，then 该能力不会阻断 Home、Drawer、应用启动或核心 Settings。
- Given 首个里程碑提出系统权限，when 进行需求与渠道审查，then 每项权限均能追踪到必要的核心能力和拒绝后的行为。

## 成功判断与护栏

### 已确认方向

- 首个里程碑的核心成功含义是：Home、Drawer 和 Settings 已形成能够支持作者持续日常使用的最小工具闭环。
- 完成开发本身不能作为唯一成功证明，必须在作者的真实主力设备上观察使用结果。
- 成功判断以作者本人的日用体验为依据，不把未收集的外部用户意见当作验收证据。
- 核心路径不得发生由 Avenor Launcher 引起的崩溃或无响应。
- Drawer 不得遗漏、重复或错误展示 Android 平台规则下应当可见且可启动的应用。
- 用户选择应用后必须正确启动目标应用。
- 本地配置不得意外丢失或损坏。
- 权限被拒绝时，只能降级依赖该权限的能力，不得阻断其他核心任务。
- 设备离线时，Home、Drawer、应用启动和核心 Settings 必须保持可用。

性能、功耗、内存和启动响应的最低可接受水平将在质量基线中另行定义，不属于本产品基础基线的完成条件。

## 用户控制

首个里程碑允许用户维护 Home 的收藏应用，并通过具体设置项修改配置，但不提供一键清除、导出、云端删除或恢复全部配置。用户可以通过 Android 系统清除应用数据。收藏变化和语言选择必须由明确的用户操作触发，不根据行为自动调整。

## 本地数据边界

- 唯一的用户内容数据是 Home 收藏的可启动应用入口标识；标识必须足以区分平台暴露的应用分身，不得只按包名存储或去重。
- 语言选择和首个里程碑契约中的其他界面设置属于本地配置，不属于行为分析数据。
- 时间和日期直接来自设备系统，不作为历史数据保存。
- V1 不采集或保存通知、联系人、位置、剪贴板、文件、照片、稳定设备标识、应用使用历史或分析事件。
- V1 不建立账号、云同步、服务器或跨设备备份。

## 依赖与风险

- Android 默认主屏幕角色、应用枚举方式、应用分身可见性及相关清单声明/权限尚未完成技术与隐私核实。
- Settings 已确认包含语言选择和系统默认主屏幕设置入口；其具体界面与状态行为仍需在垂直切片中定义。
- 当前证据只代表作者本人，不能支持大众市场需求结论。
- “美观、舒适且极简”尚未转化为可观察标准，也不属于首个里程碑验收目标。
- 以学习 Agent 体系为项目动机可能诱发超出产品需要的流程或技术复杂度，应通过范围变更机制控制。

## 建议下一步

下一步将首个里程碑拆分为一个最小可观察垂直切片，并为 Home、Drawer、应用启动和 Settings 的具体交互补充用户旅程与验收边界。技术架构和权限方案应在该范围写入当前产品契约后另行评估。
